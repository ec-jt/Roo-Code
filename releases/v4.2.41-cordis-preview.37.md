# Roo Code 4.2.41 - Cordis preview 37

Extension version: **4.2.41**. Git tag: **v4.2.41-cordis-preview.37**. Experimental GitHub prerelease, not a stable or marketplace release.

## GitHub updater permissions and task handling

- Fix the Windows temporary-directory check. Unix permission bits reported by Node do not represent Windows ACLs and could incorrectly trigger "Temporary update directory is not private." Windows uses inherited permissions from its temporary location; keep the normal user temporary directory protected by its user ACLs. Custom shared temporary locations are not supported as a security boundary.
- Continue enforcing owner-only permissions on Linux/macOS, verify ownership, and reject non-directory or symbolic-link temporary paths. Clean up when permission setup or validation fails.
- Allow manual and opted-in automatic installation while a Roo task is loaded or running, including a task loaded during download. Task state no longer blocks installation.
- Keep reload separate and manual. Roo's reload button still requires closing the loaded task because reloading interrupts the extension host. The updater does not automatically stop tasks or reload.
- Preserve native installation consent, opt-in automatic updates, cancellation checks, checksum and manifest verification, download limits, and cleanup.

## Known unresolved findings

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- The separate bounded large/history command-output preview can still show the beginning instead of following the tail. Recent-output previews apply to normal command cards.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Pre-existing historical-action and older LiteLLM handler fixture failures, plus a Bedrock context-window expectation mismatch, remain outside this change. This is not a claim that the entire repository test suite passes. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. The Mac grey-panel incident remains unverified.

## Install and rollback

**If the old updater reports the temporary-directory error, install this release's VSIX manually once using Extensions: Install from VSIX.** The updater running in the old version cannot fix itself before installation. Verify the attached SHA-256 checksum. Versions through 4.2.40 also retain the loaded-task installation block; close the loaded task before using their in-app updater, or use manual VSIX installation.

After activating 4.2.41, updates can install while tasks are loaded. Finish or stop work and close the loaded task before using Roo's **Reload to activate** button. **Developer: Reload Window** bypasses Roo's guard and interrupts the extension host, so use it only when safe. Install separately on each extension host. End-to-end in-app Remote SSH installation remains unverified.

The previous published 4.2.40 prerelease remains available. Disable automatic GitHub updates before a deliberate rollback. Versions below 4.2.34 do not support the LM Studio token field. Versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
