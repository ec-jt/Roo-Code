# Roo Code 4.2.51 - Cordis preview 47

Extension version: **4.2.51**. Git tag: **v4.2.51-cordis-preview.47**. Experimental GitHub prerelease, not a stable or marketplace release.

## Browser controls

Direct CDP now supports explicit tab selection, bounded DOM snapshots and element references, click/fill/select, bounded console logs and network metadata, styles and performance metrics. Each rich model command requires native per-command approval, including status. Generic tool auto-approval does not approve these commands. The native Browser controls panel shows the actual extension host, transport, ownership and capabilities. Remote SSH browser operations run on the extension host, not automatically on the local desktop. Arbitrary model evaluation, response bodies and debugger commands remain unavailable. See [direct-CDP controls](../docs/browser-cdp-controls.md).

The optional Chrome companion uses an authenticated loopback bridge and explicit per-tab attachment. Its command surface is **read-only**: status, tabs, selection, snapshot, inspect and bounded wait. It cannot navigate, click, fill, change selections or bypass certificates. The separate companion source ZIP needs no build; extract it and follow the [manual Chrome installation and pairing instructions](../docs/browser-extension-bridge.md). Review its powerful debugger permission first. This release operation does not install the companion, attach to a personal browser, or create a tunnel.

The native-only isolated certificate session requires **two confirmations**. It launches a fresh Roo-owned local sandboxed process and profile with insecure certificates accepted for **all certificates in that session**, not a hostname pin. It refuses existing, remote and bridge configurations. Close resets the exception; normal TLS remains the default. A certificate exception does not authorize site mutations. Do not use this session for unrelated sites or personal browsing.

## Native PDF reading

PDF text extraction uses the existing JavaScript pdf-parse engine in a separate worker. Bounds are 20 MiB input, 100 pages, 100,000 text characters and a 15-second parsing deadline. Remote acquisition is credential-free HTTP(S), with a 30-second deadline, bounded redirects and normal TLS verification. Browser cookies and authorization headers are not replayed. No Python or pypdf installation is required. The separate macOS Python/LibreSSL warning is unchanged. OCR and password entry are not implemented. The parser worker is not an OS security sandbox. See [PDF reading](../docs/pdf-reading.md).

## Mode and model preservation

Changing modes in an open task preserves the selected model, profile and unsaved overrides regardless of the workspace profile lock. Selecting the current mode is a no-op. Children receive a separate copy of the parent's active configuration even in a different mode. Explicit profile selection still works. With no task open, modes can still load saved defaults when unlocked. Parent restoration and history reopening can still lose unsaved overrides because they retain their stored-profile behavior. This supersedes the previous release's statement that an unlocked mode change releases the inherited configuration guard. See [mode and model selection](../docs/mode-model-selection.md).

## Validation and limits

Reused focused implementation evidence: 121 PDF tests across four files; 118 final browser/service/native-handler/tool tests across five files, followed by a passing 13-test tool rerun after one additional tool test; seven panel tests; parser integration and companion protocol/worker tests; and 113 mode/delegation tests across six files. Backend and UI TypeScript checks passed in the implementation workspace. Counts overlap between runs and are not a combined unique-test total.

Release gates cover isolated formatting and lint, the release-local commit hook, packaging, isolated backend TypeScript integration checking, ZIP CRC and manifest identity, both worker bundles, feature markers and excluded-provider markers, source-to-commit hashes, asset SHA-256 and GitHub server digest/size, and installed-file byte identity. These are not a full test suite or live browser pass.

A disposable local Chromium launch was attempted during implementation but failed because Snap rejected the host cgroup. No sandbox bypass or alternative browser installation was attempted. **Live CDP, certificate sessions, Chrome companion attachment, macOS behavior and end-to-end user workflows remain unverified.** Installation does not imply activation.

## Storage and unresolved limits carried forward

The [4.2.50 release notes](v4.2.50-cordis-preview.46.md), [4.2.49 release notes](v4.2.49-cordis-preview.45.md) and [4.2.48 release notes](v4.2.48-cordis-preview.44.md) remain applicable except for the mode-change behavior explicitly superseded above. The chat header can still misrepresent a delegated task's effective model. Snapshot retention, historical UI issues and previously reported unrelated test failures are not fixed here.

**Versions 4.2.48 and earlier cannot replay new version-2 request snapshots.** Rolling back does not convert snapshots. Existing task storage is not inventoried, read, migrated, rewritten, pruned or deleted by this release operation. No storage reclamation is claimed. Preserve task storage before downgrading. Disable automatic updates before deliberate rollback.

**Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery. Avoid navigation while saving history edits. Keep managed environments and their auto-approval disabled pending the previously documented fixes.**

Unfinished provider-connection checks and unrelated local editor, UI, Tetris, archive and research changes are excluded. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual.

## Installation

Verify the attached VSIX against its SHA-256 file before installation, or use **Settings > About > GitHub release updates**. Install separately on each extension host. If an older updater reports a temporary-directory error, install the VSIX manually once.

This release operation installs only on the current **Linux code-server host**, without reloading the editor or activating the new extension. It does not install on a Mac. The previous 4.2.50 prerelease remains available. The companion ZIP is optional and requires separate manual Chrome installation; it is not part of VSIX installation.
