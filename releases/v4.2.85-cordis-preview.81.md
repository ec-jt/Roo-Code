# Roo Code 4.2.85 - Cordis preview 81

Extension version: **4.2.85**. Git tag: **v4.2.85-cordis-preview.81**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release has three changes: `task_state` and `memory` accept loose arguments, a new end-to-end test covers the Cordis dispatch retry, and the plan review has a text box.

## 1. `task_state` and `memory` accept loose arguments

Before this release, some models (for example DeepSeek `deepseek-flash`) sent `task_state` calls such as `{"action": "read", "operations": ""}` with no `expected_revision`. Every call failed schema validation, and three failures in a row stopped the task with `mistake_limit_reached`.

Now:

- **Normalization before validation.** For `task_state` and `memory` only, the parser treats a missing value, an empty string or a whitespace-only string as `null` for `expected_revision` (both tools) and `operations` (`task_state`). Other fields are still validated strictly.
- **Read without a revision works.** `{"action": "read", "operations": ""}` now reads the ledger.
- **A write without a revision is still refused, with guidance.** A `task_state` patch, or a `memory` update or delete, without `expected_revision` returns a tool error: call `read` first and pass the exact revision it returns. This error comes from the tool's normal error path. It is not a schema failure and does not add to the mistake count. No write happens without the revision check.
- **The tool definitions do not change.** The JSON schemas sent to the model still require every field, because Anthropic and OpenAI strict mode need that. Only the parsing is more tolerant.

## 2. End-to-end fault-injection test for the Cordis dispatch retry

4.2.84 added automatic retry for Cordis requests that fail before the first chunk. A new test now runs that path with as little stubbing as practical: a real Cordis `Task` with the real preview runtime, the real interactive task loop, a real `AnthropicHandler`, and a real SDK `APIError` (status 529, `overloaded_error`, `Overloaded`). Only the SDK transport (`messages.create`) is mocked. The test checks that the task retries automatically, that admission runs twice, that the turn completes, that the retry row shows `529` and `Overloaded`, and that no row contains the API key.

## 3. Text box in the plan review

The Cordis plan review (`plan_review`, from `exit_plan`) now has an optional text box ("Add instructions (optional)") above the **Approve plan** and **Keep planning** buttons. It appears for every plan review, including amendments.

- **Approve plan** sends the text with the approval. The model gets a status-only tool result (`{"status":"approved", ...}`) followed by a separate `<user_message>` block in the same user turn. The text is never inside the tool result.
- **Keep planning** sends the text as feedback, as before.
- Text in the main chat box during a plan review still works as before. If both boxes have text when you click a button, both are sent, review box first.
- New strings `chat:planReview.instructionsLabel` and `chat:planReview.instructionsPlaceholder` in all 18 locales.

## Changes

- `src/core/prompts/tools/native-tools/task_state.ts`, `memory.ts`: shared strict object schema; new parser schemas that let a missing write revision through to the tool; `normalize*Args()` helpers; revision guidance strings. The exported tool definitions are unchanged.
- `src/core/assistant-message/NativeToolCallParser.ts`: `task_state` and `memory` normalize, then validate with the parser schemas.
- `src/core/tools/TaskStateTool.ts`, `MemoryTool.ts`: normalize; return `REVISION_REQUIRED` guidance for a write without a revision; then validate with the strict schema.
- `src/core/tools/ExitPlanTool.ts`: approval with text returns status JSON and pushes the text with `pushUserFeedbackToUserContent()`.
- `webview-ui/src/components/chat/ChatView.tsx`: plan review text box (Tailwind classes) wired into the existing Approve and Keep planning handlers.
- `webview-ui/src/i18n/locales/*/chat.json`: two new keys.
- Tests: `NativeToolCallParser.loose-state-args.spec.ts` (new), `TaskStateTool.spec.ts` (new), `MemoryTool.spec.ts`, `exitPlanTool.spec.ts`, `task-model-dispatch.spec.ts`, `ChatView.spec.tsx`.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until you reload the window.

## Storage and rollback

This release adds no settings and changes no stored data. If you roll back, loose `task_state` and `memory` calls fail schema validation again, and the plan review loses its text box.
