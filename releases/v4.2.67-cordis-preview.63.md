# Roo Code 4.2.67 - Cordis preview 63

Extension version: **4.2.67**. Git tag: **v4.2.67-cordis-preview.63**. Experimental GitHub prerelease, not a stable or marketplace release.

## Cordis tasks use a fixed tool preset

Each task now has a profile, **modes** or **cordis**, decided once when the task is created:

- A resumed task keeps the profile it was created with.
- A subtask inherits its parent's profile.
- A new task gets **cordis** when the **Cordis runtime preview** experiment is on, and **modes** otherwise. Turning the experiment on or off affects only tasks created afterwards.

In a Cordis task, every mode gets all tool groups (read, edit, browser, command, MCP) without file restrictions, and `switch_mode` is never offered. For example, Architect can run commands and edit non-Markdown files in a Cordis task. The mode's role and instructions do not change. The preset applies both to the tool list sent to the model and to the checks made when a tool runs, including the browser tool and browser control access.

The mode of a Cordis task is fixed after its first request. The mode selector is disabled for that task, and a mode-switch request shows a notice: start a new task to use a different mode. Tasks with the **modes** profile behave as before.

## Storage

Task history gains an optional `profile` field. It is written only for Cordis tasks. Existing tasks have no field and load as **modes**. Nothing is migrated or rewritten. Older builds ignore the field, so a Cordis task opened in an older build behaves like a normal modes task.

## Validation and limits

Focused tests pass: a new Cordis profile spec (9 tests: profile precedence, the preset, and execution-time validation that blocks `switch_mode` and allows Architect commands and code edits only under Cordis), the sticky-mode spec including a new mode-lock test, mode-switch model preservation, delegation, tool filtering, tool validation, presenter, browser tool and task persistence specs. TypeScript checks for types, extension and webview pass. Release gates cover lint, packaging, VSIX ZIP integrity, manifest version, both worker bundles and asset digests.

Pre-existing failures, identical on 4.2.66 without this change: 4 presenter policy-boundary tests and 12 `ClineProvider.spec.ts` edit tests, plus the 25 tests in `src/core/task/__tests__` noted in earlier releases.

Cordis tasks were not exercised with a live model.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Builds before 4.2.62 show prune-only recovery rows as unknown messages. This release does not migrate or rewrite stored tasks, and no existing task data was read during the release operation.
