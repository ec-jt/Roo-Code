# Roo Code 4.2.61 - Cordis preview 57

Extension version: **4.2.61**. Git tag: **v4.2.61-cordis-preview.57**. Experimental GitHub prerelease, not a stable or marketplace release.

## Settings model picker no longer substitutes the provider default

The settings model picker reported the provider default model whenever model data was not ready. That covered router models that were still loading, a provider switch, and the first load of the view. The settings view writes the reported identifier back into the provider configuration, and saving settings rebuilds the running task's handler. A transient default could therefore replace the user's chosen model with whatever the default constant points at, including a newly added model.

The picker now reports the configured model for every provider while data loads. The provider default is used only when no model is configured.

- A configured model is always reported, including while router data is loading.
- A running task is no longer silently replaced by the default constant through a transient read.
- Providers that keep the model in their own field are read from that field: OpenRouter, Requesty, Unbound, LiteLLM, LM Studio and Ollama.
- Providers that keep the model in `apiModelId` are read from `apiModelId`, and `vscode-lm` is read from its model selector.

## Validation and limits

The new unit spec asserts that a configured OpenRouter model is reported while router data is loading. That spec passes, and webview-ui TypeScript checking passes. Both results were produced during the change work and were not re-run for this release.

Release gates cover isolated lint, packaging, VSIX ZIP CRC, manifest identity and version, both worker bundles, retained feature markers, absence of unfinished provider-connection markers, presence of the configured-model fallback in the built webview bundle, source-to-commit hashes, asset SHA-256, GitHub server digest and size, and installed-file byte identity. These gates are not a full test suite.

One test in `useSelectedModel.spec.ts` fails before and after this change: the bedrock 1M context case expects a 200000 context window and receives 1000000. It was confirmed to fail identically on the unmodified baseline, so it is pre-existing and unrelated. It is not fixed in this release.

A live settings interaction and a live running task were not exercised. Extension activation, live model stability, macOS install and end-to-end user workflows remain unverified.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads. An editor that still reports an older version after a successful install has not reloaded.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Rolling back does not convert snapshots. Preserve task storage before downgrading, and disable automatic updates before a deliberate rollback.

Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery. Avoid navigation while saving history edits.

This release does not migrate or rewrite stored tasks, and no existing task data was read during the release operation. Unfinished provider-connection checks and unrelated local editor, UI, Tetris, archive and research changes are excluded.

## Installation

Verify the attached VSIX against its SHA-256 file. Install separately on each extension host. This release operation installs only on the current Linux code-server host, without reloading the editor or activating the new extension. It does not install on a Mac. The companion ZIP is optional, unchanged since 4.2.51, and requires separate manual Chrome installation.
