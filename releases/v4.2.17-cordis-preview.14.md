# Roo Code 4.2.17 - Cordis preview 14

Extension version: **4.2.17**. Git tag: **v4.2.17-cordis-preview.14**. This is an experimental GitHub prerelease, not a stable or marketplace release. Version 4.2.16 was a local test build.

## Known safety and correctness issues

The source review identified four issues that are **not fixed in this release**:

- **Managed installs:** pip isolated mode still reads global configuration. An install target/prefix in that configuration can redirect writes outside the approved environment, and an empty environment may subsequently be reported ready. **Keep managed environments and their auto-approval disabled pending a fix.**
- **Command ownership:** VS Code shell events are currently associated by terminal rather than the exact shell execution. A manual command started in a Roo-owned terminal while Roo has a pending command can be attributed to Roo, enabling Stop command under the wrong label. **Do not mix manual work into Roo-owned terminals when testing stop controls.**
- **Manifest reads:** a named-pipe manifest can block preparation before approval and before the installation timeout. Use regular files only. Checkpoint compatibility inspection shares this reader.
- **musl Linux:** the future published interpreter path is supplied to pip before it exists, which can prevent recognition of compatible musllinux wheels.

These issues were identified by source review and isolated in-memory checks, not destructive integration tests. This package is for controlled testing; passing mocked tests does not resolve these findings.

## Compact Background activity

- Move Background activity to the bottom of Chat, alongside file changes above the prompt area.
- Collapse the whole section by default. The header shows active/total command counts and current task status, including approval needs.
- Expand for task controls and command details without a second Commands toggle. Expanded content has a bounded scroll area. Empty activity is hidden and collapsed timers do not run.
- The monitor remains available in History.

## Included since the previous public prerelease

- Single-task background mode keeps the loaded stack running while browsing the history list. Return/Cancel controls are instance-correlated; task opening and deletion are blocked while backgrounded. Required approvals remain pending and existing auto-approval policy is unchanged. No concurrent Roo task runner is introduced.
- Roo-launched terminal activity includes command, working directory, launching task, elapsed time, known exit status, and bounded non-consuming output tails. Recent activity summaries are included in subsequent model context. Stop requests are not proof of exit.
- Tracking is session-only, not a host process list. Detached descendants and managed installer subprocesses are not separately listed. An extension-host restart loses tracking and stops task execution.
- Experimental managed Python environments provide exact-wheel manifests, a separate default-off approval policy, external environment records, and advisory checkpoint mismatch checks. Linux only; no source builds, automatic resolution/reuse, system changes, or automatic activation. See the known issues above before use.
- New labels use English fallback. Cordis runtime preview remains off by default.

## Validation and limits

The compact layout passed 33 focused UI tests. Earlier focused checks covered task delegation/approval guards, terminal ownership within mocked lifecycle events, command controls, environment validation, and checkpoint compatibility. Backend/webview type checks and scoped lint passed during implementation. No live-editor visual smoke test or real managed package installation was performed.

## Install and rollback

Install **roo-cline-4.2.17.vsix**, verify the accompanying SHA-256 checksum, and run **Developer: Reload Window** when ready to interrupt the current extension session.

The previous public 4.2.15 prerelease remains available for rollback and does not contain the new managed-environment or background-activity features. Rollback does not uninstall experimental environments, stop detached processes, or undo completed actions.
