# Roo Code 4.2.68 - Cordis preview 64

Extension version: **4.2.68**. Git tag: **v4.2.68-cordis-preview.64**. Experimental GitHub prerelease, not a stable or marketplace release.

## Plan overlay for Cordis tasks

Cordis tasks (created while the **Cordis runtime preview** experiment is on) can now plan before they act:

- Type `/plan <request>` to start a new Cordis task in plan mode, or `/plan` in a running Cordis task to turn plan mode on. `/plan off` turns it off.
- While plan mode is on, a badge shows next to the mode selector. The model explores and designs, makes no edits except to plan or architecture documents, and submits the plan with the new `exit_plan` tool.
- The plan appears in chat for review. **Approve plan** turns plan mode off and the model continues with implementation. **Keep planning** sends your typed feedback back; plan mode stays on.
- Plan review is never auto-approved, including with all actions auto-approved.
- Plan mode is saved with the task and restored on resume.

In tasks with the **modes** profile, `/plan` shows a notice that the plan overlay is available in Cordis preview tasks, and `exit_plan` is not offered.

## Architecture drift in Cordis tasks

Cordis tasks keep their mode, so drift is handled in the task. When the project has `docs/architecture/` and the model finds drift, it stops the conflicting change, records a task-state blocker, and submits an amendment with `exit_plan`: the drift, the proposed record change, and the updated plan. After you approve, it writes the record changes, clears the blocker, and continues. This replaces the "ask to switch to Architect" rule for Cordis tasks only.

The Cordis prompt section depends only on the task's profile and plan state, so the prompt cache changes only when you toggle plan mode. Tasks with the **modes** profile get no new prompt text.

## Storage

Task history gains an optional `planOverlay` field, written only for Cordis tasks while plan mode is on. Nothing is migrated or rewritten. Older builds ignore the field.

## Limits

- Plan mode restricts edits through instructions only; the tool list does not change.
- A user-defined slash command named `plan` is shadowed when you press Enter on `/plan`; choosing it from the menu still works.
- The CLI has no handler for plan review and waits at that prompt.
- Plan mode was not exercised with a live model.

## Validation

Focused tests pass: Cordis profile, `exit_plan` tool, plan-review auto-approval (never approved), task metadata, the Cordis prompt section and system-prompt snapshots (unchanged for modes tasks), task model dispatch (overlay from task options and on resume), the webview message handler (`/plan` paths), the `/plan` parser and chat view interception. TypeScript checks for types, extension and webview pass. Release gates cover lint, packaging, VSIX ZIP integrity, manifest version, both worker bundles and asset digests.

Pre-existing failures, identical on 4.2.67: the Markdownify all-actions approval test, one edit-confirmation test in the webview message handler spec, one queued-message test in the chat view spec, 4 presenter policy-boundary tests, 12 `ClineProvider.spec.ts` edit tests and 25 tests in `src/core/task/__tests__`.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Builds before 4.2.62 show prune-only recovery rows as unknown messages. Builds before 4.2.68 show a plan review as an unknown message. This release does not migrate or rewrite stored tasks, and no existing task data was read during the release operation.
