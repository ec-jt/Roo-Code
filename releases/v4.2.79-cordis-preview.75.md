# Roo Code 4.2.79 - Cordis preview 75

Extension version: **4.2.79**. Git tag: **v4.2.79-cordis-preview.75**. Experimental GitHub prerelease, not a stable or marketplace release.

## Per-profile context window override

Every API profile now has an optional **Context window override (tokens)** setting. It is for testing overflow recovery on a large-context model. For example, an opus profile with a 1M-token window and an override of 64,000 makes Roo treat the model as a 64,000-token model.

- The setting is optional. Empty means no override, and behavior is unchanged.
- The override only lowers the window. The effective window is `min(override, real window)`. A larger value is ignored.
- The provider request does not change. The model ID, `max_tokens`, the thinking budget, temperature and beta headers are computed from the real model info, as before.
- The setting works for every provider. Bedrock `awsModelContextWindow` still works as before. The new override applies after it, so the smaller value wins.

With an override, Roo uses the overridden window for:

- overflow recovery in `manageContext`: the prune and image-offload budget, summarizing, and the truncation fallback;
- proactive overflow detection before a request is sent (new, see below);
- the context bar and token tooltip in the chat header;
- the conservative context checks for fresh context, saved-prefix profile switches and prepared requests (`assertContextFits`);
- condense failure diagnostics ("Advertised context window").

### Proactive overflow detection

Roo already ran recovery only after the provider rejected a request. A model with a 1M window does not reject a 64k-sized request, so the override needs its own trigger.

Before a request is sent, when the profile has an override, Roo compares the last known context size plus the output reserve with the overridden window. If the sum is larger, Roo runs the same recovery as for a provider rejection, once, and then sends the request. The rules are the same as for a rejection:

- only when **Compact on context overflow** is on;
- only once per request (the provider-rejection path does not run a second recovery);
- never for prepared model-operation requests;
- **Cancel** stops the compaction.

Without an override, this check does not run.

### Output reserve rule

When the override lowers the window, `info.maxTokens` is capped to `ceil(0.2 * overridden window)`. Every output reserve that Roo derives from model info then leaves at least 80% of the window for input. For a 64,000 window the reserve is at most 12,800 tokens, so at least 51,200 tokens are left for input. Opus would otherwise reserve 128,000 tokens, which is larger than the whole overridden window.

The cap changes only what Roo reserves in its own budget. It does not change the `max_tokens` value that is sent to the provider.

## Where to find it

Settings, Providers, select a profile, open **Advanced settings**. The field is below **Error & Repetition Limit**. Save the profile. Clear the field to remove the override.

## Changes

- `packages/types/src/provider-settings.ts`: `modelContextWindowOverride: z.number().int().positive().optional()` in the base provider settings schema, so every profile has it.
- `src/shared/api.ts`: new `applyContextWindowOverride(info, settings)` and `CONTEXT_WINDOW_OVERRIDE_OUTPUT_FRACTION` (0.2). It returns a new object and never changes static model tables.
- `src/api/index.ts`: `buildApiHandler()` wraps the handler with the new `withContextWindowOverride()`. This is the single choke point. It patches the `getModel()` method on the handler instance, so the class is unchanged (`instanceof` checks and the mediated Anthropic path still work). The provider's own `getModel()` runs first, so request parameters are computed from the real model info.
- `src/core/task/Task.ts`: proactive overflow check in `attemptApiRequestPinned()`. It runs only with an override.
- `webview-ui/src/components/settings/ContextWindowOverrideControl.tsx`: new field (Tailwind classes). Empty or invalid input means no override.
- `webview-ui/src/components/settings/ApiOptions.tsx`: renders the field once, in the shared Advanced settings section, for every provider.
- `webview-ui/src/components/chat/TaskHeader.tsx`: applies the same helper to the selected model, so the context bar uses the overridden window and the capped reserve.
- `webview-ui/src/i18n/locales/*/settings.json` (18 locales): new keys `providers.contextWindowOverride.label`, `.description`, `.placeholder`.
- Tests: new `src/api/__tests__/context-window-override.spec.ts` and `webview-ui/src/components/settings/__tests__/ContextWindowOverrideControl.spec.tsx`. New cases in `task-model-dispatch.spec.ts`, `TaskHeader.spec.tsx` and `ApiOptions.spec.tsx`.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback

The new key `modelContextWindowOverride` is stored only in profiles where the user sets it. It is optional. Older builds ignore the key and use the model's real window. No stored tasks change. Rolling back removes the field and the proactive check. A profile that still has the key works as before in the older build.
