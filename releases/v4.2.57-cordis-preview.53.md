# Roo Code 4.2.57 - Cordis preview 53

Extension version: **4.2.57**. Git tag: **v4.2.57-cordis-preview.53**. Experimental GitHub prerelease, not a stable or marketplace release.

## Subtask navigation uses durable child IDs

Subtask links now bind to a durable per-message child ID. Each `new_task` message and each `subtask_result` message stores the child task ID directly, so a link no longer depends on the position of an entry in the `childIds` array.

- The `new_task` card of a parent message points to the child that the delegation actually created.
- A `subtask_result` row carries its own child ID and opens the correct child task.
- Index-based lookup from the `childIds` array is no longer authoritative for the UI. The 4.2.55 `newTaskChildLinks` map remains as a secondary record and is harmless.

## Legacy history recovery

Saved history written before this release has no child IDs on messages. When such a task is loaded, the extension recovers links from the saved conversation itself:

- A link is restored only when the saved history makes the child unambiguous.
- Ambiguous legacy prompts stay unlinked. The UI does not guess.
- Durable IDs always win over recovered links.

## Plain history messages

History messages that are not part of a live task now show a **Go to subtask** button when a child ID is known. This makes stored delegations reachable from chat history.

## Features retained from 4.2.51 to 4.2.56

Browser controls with auto-approval for every rich command, native PDF reading, mode/model preservation, the DeepSeek strict tool-schema fix, the single read-only browser approval, subtask links from an explicit `new_task`-to-child map, and the clear failure for closed or detached browser pages are unchanged. See the [4.2.56 release notes](v4.2.56-cordis-preview.52.md), [4.2.55 release notes](v4.2.55-cordis-preview.51.md), [4.2.54 release notes](v4.2.54-cordis-preview.50.md), [4.2.53 release notes](v4.2.53-cordis-preview.49.md), [4.2.52 release notes](v4.2.52-cordis-preview.48.md) and [4.2.51 release notes](v4.2.51-cordis-preview.47.md).

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads. An editor that still reports an older version after a successful install has not reloaded.

## Validation and limits

Focused implementation evidence, produced before packaging in an isolated worktree: 47 backend tests pass for provider delegation, subtask link recovery and history resume delegation; 21 WebView tests pass for subtask link rendering and chat window behavior; backend and WebView TypeScript checks pass. Release gates cover isolated lint, packaging, isolated backend TypeScript checking, ZIP CRC and manifest identity, both worker bundles, feature markers, absence of unfinished provider-connection markers, presence of `subtaskId` and `recoverSubtaskLinks` in the built bundle, source-to-commit hashes, asset SHA-256, GitHub server digest and size, and installed-file byte identity. These gates are not a full test suite.

Extension activation, live browser behavior, macOS behavior and end-to-end user workflows remain unverified.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Rolling back does not convert snapshots. Preserve task storage before downgrading, and disable automatic updates before a deliberate rollback.

Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery. Avoid navigation while saving history edits.

Legacy link recovery reads saved history only. It does not rewrite, migrate or delete stored tasks. Unfinished provider-connection checks and unrelated local editor, UI, Tetris, archive and research changes are excluded.

## Installation

Verify the attached VSIX against its SHA-256 file. Install separately on each extension host. This release operation installs only on the current Linux code-server host, without reloading the editor or activating the new extension. It does not install on a Mac. The companion ZIP is optional, unchanged from 4.2.51 to 4.2.56, and requires separate manual Chrome installation.
