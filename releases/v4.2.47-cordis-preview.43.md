# Roo Code 4.2.47 - Cordis preview 43

Extension version: **4.2.47**. Git tag: **v4.2.47-cordis-preview.43**. Experimental GitHub prerelease, not a stable or marketplace release.

## Reasoning streams from compatible providers

LiteLLM and OpenAI-compatible streaming now forward plain-text reasoning from either supported reasoning field. This covers both the normal OpenAI-compatible path and its o3 streaming path. When both fields contain nonempty strings, the established field takes precedence. Aliases are not duplicated, and structured or non-string values are not coerced into displayed text.

Reasoning is emitted before content or tool calls from the same chunk. Tool-call arguments and usage accounting remain unchanged. LiteLLM also tolerates usage-only chunks without choices. Non-streaming completions are unchanged.

Reasoning-only output is still not a final answer. This fix does not establish the cause of the reported empty response. No live provider, tunnel, API-key, server, or private-infrastructure checks were performed.

## Validation and limits

The focused compatible-provider reasoning suite passed all 19 tests on the unchanged source. Release gates include isolated lint, backend TypeScript checking, packaging, archive integrity, source-to-commit identity, checksums, uploaded-asset verification, and installed-file verification. These are scoped checks, not a full-suite or live-provider pass.

Correction to earlier release wording: task-state acceptance checks are **user-attested only**. No executable acceptance test runner was implemented. The earlier claim that such a runner is off by default was misleading; this release does not add one.

The Windows file-sync change from an earlier release is present, but the notification after dispatch is already closed remains unverified and may never appear. No Windows host was used. The Mac grey-panel incident remains unverified. Directory-listing runtime behavior on Windows, macOS, Electron, and remote filesystems remains untested.

## Known unresolved findings carried forward

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- The separate bounded large/history command-output preview can still show the beginning instead of following the tail.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Previously reported historical-action and LiteLLM fixture failures and a Bedrock context-window expectation mismatch remain outside this change. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. Unfinished provider-connection checks and unrelated local UI changes are not included in this release.

## Install and rollback

Install the attached VSIX and verify its SHA-256 checksum, or use **Settings > About > GitHub release updates**. If an older updater reports a temporary-directory error, install the VSIX manually once. Install separately on each extension host. This release operation targets the current Linux code-server host, not a Mac. It does not reload or activate the installed extension. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.46 prerelease remains available. Disable automatic updates before deliberate rollback. Older versions do not provide the task-state workflow; preserve task storage before downgrading. Versions below 4.2.34 do not support the LM Studio token field; versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
