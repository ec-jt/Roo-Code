# Roo Code 4.2.53 - Cordis preview 49

Extension version: **4.2.53**. Git tag: **v4.2.53-cordis-preview.49**. Experimental GitHub prerelease, not a stable or marketplace release.

## DeepSeek strict browser schema fix

DeepSeek rejected `browser_action` control commands with: `At schema path /properties/command/anyOf/3/properties/url, format "uri" is not supported for strict schemas`.

The native `navigate` URL field no longer declares `format: "uri"`. The explicit `^https?://` pattern, `maxLength` and the runtime `validateWebUrl` check remain authoritative. A new test asserts that the schema uses only strict-schema-safe keywords.

## One read-only browser approval per task and session

Read-only browser commands (`status`, `tabs`, `snapshot`, `console`, `network`, `inspect`, `styles`, `performance`) now require one native approval per task and browser session. Later read-only commands in the same task and session run without another modal. A new browser session or a new task requires fresh approval. Mutating commands (`navigate`, `click_ref`, `fill_ref`, `select_ref`) and `select_tab` still require explicit approval for each call.

No capability change. Approvals are held in memory only, not persisted. Host fence authorization, capability checks, session checks and transcript persistence still run for every command. Tool prompt text and browser control documentation are updated to match.

## Features retained from 4.2.51 and 4.2.52

Browser controls, native PDF reading, mode/model preservation and the Codex strict tool-schema fix are unchanged. See the [4.2.52 release notes](v4.2.52-cordis-preview.48.md) and [4.2.51 release notes](v4.2.51-cordis-preview.47.md).

## Validation and limits

Focused implementation evidence: 66 tests pass across the browser control tool, browser schema, and Codex schema and provider specs; the backend TypeScript check passes in the implementation workspace. Release gates cover isolated lint, packaging, isolated backend TypeScript checking, ZIP CRC and manifest identity, both worker bundles, feature markers, excluded-provider markers, source-to-commit hashes, absence of `format: "uri"` in the built bundle, asset SHA-256, GitHub server digest and size, and installed-file byte identity. These gates are not a full test suite, and installation does not imply activation.

Live CDP, certificate sessions, Chrome companion attachment, macOS behavior and end-to-end user workflows remain unverified.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Rolling back does not convert snapshots. This release does not inventory, read, migrate, rewrite, prune or delete existing task storage. Preserve task storage before downgrading, and disable automatic updates before a deliberate rollback.

Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery. Avoid navigation while saving history edits.

Unfinished provider-connection checks and unrelated local editor, UI, Tetris, archive and research changes are excluded.

## Installation

Verify the attached VSIX against its SHA-256 file. Install separately on each extension host. This release operation installs only on the current Linux code-server host, without reloading the editor or activating the new extension. It does not install on a Mac. The companion ZIP is optional, unchanged from 4.2.52, and requires separate manual Chrome installation.
