# Roo Code 4.2.87 - Cordis preview 83

Extension version: **4.2.87**. Git tag: **v4.2.87-cordis-preview.83**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release fixes two defects found in the 4.2.86 live checks: the model could not patch task state, and the chat window dropped the prune and offload data from context rows.

## 1. `task_state` patch accepts common operation shapes and returns specific errors

In 4.2.86, DeepSeek (`deepseek-flash`) sent six `task_state` patches. All six failed with the generic parser error "Invalid tool call for 'task_state': Arguments do not match the tool schema". Each failure counted toward the mistake limit, and the model never learned what was wrong.

**Cause.** The parser schema parsed and validated the operations JSON. Any operation that did not match the exact shape became a generic schema failure, before the tool could return `REVISION_REQUIRED` or any useful guidance. The model sent two shapes that differ from the canonical one:

- **A:** `{"op":"upsert","collection":"evidenceRefs","record":{"id":"...","text":"...","source":"..."}}` (`record` instead of `value`)
- **B:** `{"op":"upsert","collection":"evidenceRefs","id":"...","text":"...","source":"..."}` (record fields at the top level)

None of these patches had `expected_revision`.

**Fix.**

- **Parser.** The parser checks only the top-level shape: `action`, `expected_revision` and `operations` as a string or `null`. It no longer validates the operations content.
- **Normalization.** Before strict validation, each `upsert` operation is normalized:
    - `record` is renamed to `value` when `value` is absent.
    - When neither `value` nor `record` is present, the record fields `id`, `text`, `status`, `evidenceIds` and `source` move into `value`.
    - Unknown keys stay where they are, so strict validation still rejects them. No data is added.
- **Revision first.** A patch without `expected_revision` returns `REVISION_REQUIRED` before the operations are checked. It does not count as a mistake and writes nothing.
- **Specific error.** If the operations are still invalid, the tool returns `INVALID_OPERATIONS` with the index of the first invalid operation, the failing field (for example `operations[1] is invalid at collection` or `operations[0] is invalid at value.status`), one complete valid example, and the list of operation forms. Nothing is written. This error counts once toward the mistake limit, like other tool argument errors.
- **Tool description.** It now says "Patch requires expected_revision from the last read." and shows one exact patch call. The strict JSON schema of the tool is unchanged.
- **Unchanged.** Every write still requires the exact revision from the last read, approval and the existing authorization checks.

`memory` does not take patch operations. Its arguments are flat fields, so it is unchanged.

## 2. Chat window keeps prune and offload data

In 4.2.86, the chat window serializer copied only some context fields to the webview:

- `contextPrune` was not copied, so `context_pruned` rows reached the webview without data and rendered nothing.
- `contextCondense` was rebuilt without `prunedCount` and `offloadedCount`.

Now `contextPrune` is copied under the normal size limit, and the rebuilt `contextCondense` keeps `prunedCount` and `offloadedCount`, also when the summary is truncated. `contextTruncation` was already copied whole and keeps its counts.

## Changes

- `src/core/prompts/tools/native-tools/task_state.ts`:
    - the parser and executor schemas check only the top-level shape
    - new `normalizeTaskStatePatchOperations` and `parseTaskStatePatchOperations`
    - new `TASK_STATE_PATCH_EXAMPLE`; the tool description has a patch example
- `src/core/tools/TaskStateTool.ts`: `INVALID_OPERATIONS` error, checked after `REVISION_REQUIRED` and before any transaction, approval or write; counted once as a mistake.
- `src/core/webview/history/ChatWindow.ts`: copies `contextPrune`; keeps `prunedCount` and `offloadedCount` in `contextCondense`.
- Tests:
    - `NativeToolCallParser.loose-state-args.spec.ts`: live shapes A and B pass the parser.
    - `TaskStateTool.spec.ts`: live shapes A and B write the canonical operation; shape A without a revision returns `REVISION_REQUIRED`; an unknown collection returns the specific error; the canonical shape still works.
    - `chatPreview.spec.ts`: `context_pruned` keeps `contextPrune`; condense rows keep the counts with a short and a truncated summary.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until you reload the window.

## Storage and rollback

This release adds no settings and no stored fields.

If you roll back to 4.2.86:

- Patches with `record` or flat record fields fail with the generic schema error again.
- `context_pruned` rows render nothing, and condense rows lose the counts in the chat window.
