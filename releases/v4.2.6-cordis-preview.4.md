# Cordis runtime preview 4

Extension version: **4.2.6**. Git tag: **v4.2.6-cordis-preview.4**. This is a GitHub prerelease, not a stable or marketplace release.

## Optional nested-subtask auto-approval

The new **Nested subtasks** toggle appears in **Settings > Auto-approve** and the chat auto-approval menu. It is off by default and is not enabled implicitly by **All actions**.

To auto-approve a child creating another subtask, enable all of:

1. Master auto-approval.
2. **Subtasks** or **All actions**.
3. **Nested subtasks**.

Each deeper request still needs a justification. It cannot gain wider mode or file permissions, bypass mandatory model-operation approval, or proceed with stale ancestry or task identity. Approval settings are rechecked before delegation, so revoking permission cancels a pending authorization. Without the opt-in, deeper delegation retains explicit per-action human confirmation.

Nested tasks can add API cost at each level. This setting is not a financial budget cap or a promise that the model will delegate only rarely. The guidance still favors direct execution for small work.

## Productive subtasks

Delegation guidance now explicitly supports implementation, bug fixing, and testing in modes that permit those actions. Children are not inherently read-only. Briefs should specify clear file ownership and expected results to avoid conflicting changes. Review-only instructions and mode restrictions remain binding.

## Validation and limits

Focused checks cover nested-approval prerequisites, settings persistence, opt-in revocation, mandatory approval fences, stale ancestry, guidance, and UI toggles. Backend and UI TypeScript checks passed during implementation. Shared schema tests cover the new setting.

The new UI wording uses English fallback. Translation validation reports these new untranslated strings alongside existing gaps. The previous release's known provider-suite baseline failures remain outside this change. No live provider or cross-platform extension-host validation was performed.

The **Cordis runtime preview** setting remains off by default. Nested-subtask approval does not require enabling it. Existing checkpoint protections, timeout behavior, and preview recovery fixes remain in place. Graph execution and strict financial budget enforcement remain unavailable.

## Install and rollback

Install **roo-cline-4.2.6.vsix**, then run **Developer: Reload Window**. Verify the artifact using the accompanying SHA-256 file. The extension ID is unchanged. No approval setting is automatically enabled by installation.

The previous 4.2.5 prerelease remains available for rollback. It always requires explicit confirmation for deeper delegation and ignores this new opt-in. Rollback cannot undo completed task actions.
