# Roo Code 4.2.99 - Cordis preview 95

Extension version: **4.2.99**. Git tag: **v4.2.99-cordis-preview.95**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release adds a third task profile, `hybrid`, as decided in ADR-2026-11-22-hybrid-task-profile. Hybrid keeps modes and adds plan review. The default profile is unchanged (`cordis`) until the long-task evaluation (L1) decides it.

## New: the hybrid task profile

| Feature                                    | modes           | cordis          | hybrid               |
| ------------------------------------------ | --------------- | --------------- | -------------------- |
| Mode roles and per-mode tool limits        | yes             | no (all groups) | yes                  |
| `switch_mode`                              | yes             | no              | yes                  |
| `/plan`, `exit_plan`, plan review          | no              | yes             | yes                  |
| Switch to the target mode on plan approval | no              | not needed      | yes (default `code`) |
| Drift as a plan amendment                  | no              | yes             | yes                  |
| `cordisTextOnlyTurnPolicy`                 | normal reminder | yes             | yes                  |
| Dispatch runtime                           | no              | Anthropic       | Anthropic            |

In a hybrid task:

- Every mode keeps its tool groups and file restrictions. `switch_mode` stays available. `exit_plan` is available in every mode, because it is an always-available tool and the hybrid profile does not disable it.
- The system prompt gets a `HYBRID TASK` section. It tells the model to finish planning in Architect (or any planning mode) by calling `exit_plan`, not with a text plan and a follow-up question. It also contains the drift rule: stop, record a `task_state` blocker, call `exit_plan` with an amendment, and continue after approval. It does not say that the mode is fixed.
- `/plan` turns on the plan overlay, as in Cordis tasks. The overlay text is the same.
- When the user approves a plan, the task switches once to the target mode before it continues. The target is `code`, or the mode named in the new optional `exit_plan` parameter `mode`. An unknown mode falls back to `code`. If the task is already in the target mode, nothing switches. The switch uses the existing in-task path (`ClineProvider.handleModeSwitch`), so the model and provider profile stay the same (Q-USE-1). The chat shows the switch with the same row as `switch_mode` ("Roo switched to code mode because: plan approved").
- "Keep planning" never switches the mode.

Cordis and modes tasks behave as before. In a Cordis task, plan approval does not switch the mode.

## New: task profile setting

Settings > Experimental now has a **Task profile for new tasks** select with three options: Modes, Cordis, Hybrid. It replaces the Cordis runtime preview on/off toggle.

- Selecting an option writes the new global setting `taskProfile`.
- When `taskProfile` is not set, the stored `experiments.cordisRuntimePreview` decides as before: `false` means modes, `true` or absent means cordis. The old key is read but never rewritten (C-5).
- A new task takes its profile from the stored value first, then from the parent task, then from the setting. An unknown stored value gives `modes`.
- New strings `settings:experimental.taskProfile.*` are in all 18 webview locales (C-7).

## Changed: dispatch runtime selection

`selectPreviewRuntime(provider, profile, currentSetting)` now takes the task profile instead of the experiments object. It returns the preview runtime for `cordis` and `hybrid` tasks on Anthropic only (R-5).

The kill switch is kept. When the effective profile setting is `modes`, no task gets the runtime when it is created or resumed. If the setting changes to `modes` while a task runs, active preview requests are cancelled as before. A write to `taskProfile` now fires the same settings notification as a write to `experiments`.

A resumed child task now gets the runtime from its own stored profile, not from the current flag. A Cordis child resumed with the flag on keeps the runtime. A modes child does not get it.

## Storage and rollback

New data: the global setting `taskProfile`, and `profile: "hybrid"` with `planOverlay` in the task's history item. `cordisRuntimePreview` is never rewritten (C-5).

A task stored with `hybrid` and opened in 4.2.98 runs as a modes task. 4.2.98 reads the history item without schema validation and passes the stored value through unchanged. Every 4.2.98 check compares the profile to `"cordis"`, so a hybrid task gets the mode tool limits and `switch_mode`, `exit_plan` is disabled, the prompt has no Cordis or hybrid section, `/plan` is refused, and the mode is not locked. In 4.2.98 the dispatch runtime still follows the `cordisRuntimePreview` flag, so an Anthropic task gets it when that flag is on or absent. 4.2.98 does not write a profile for a non-Cordis task, and the history store merges items, so the stored `hybrid` value stays on disk and returns when the task is opened again in 4.2.99. 4.2.98 ignores the `taskProfile` setting, because the key is not in its settings list.
