# Roo Code 4.2.64 - Cordis preview 60

Extension version: **4.2.64**. Git tag: **v4.2.64-cordis-preview.60**. Experimental GitHub prerelease, not a stable or marketplace release.

## Architecture context (off by default)

New setting: **Settings > Context management > Architecture context** (`architectureContextMode`). When a workspace has `docs/architecture/arc42.md`, Roo can add a block with the project's architecture records to the task context.

| Mode          | Contents                                                                             | When the block is re-sent                     |
| ------------- | ------------------------------------------------------------------------------------ | --------------------------------------------- |
| Off (default) | Nothing                                                                              | Never                                         |
| Index         | One line per record: ID, status, title, file, Paths                                  | Only when `docs/architecture/` changes        |
| Constraints   | Index plus full constraints and accepted quality goals                               | Only when `docs/architecture/` changes        |
| Full          | Constraints plus accepted decisions and risks whose `Paths` match files Roo has read | Also when newly read files match more records |

Rejected and superseded records are never included. Proposed records that are not yet confirmed are labelled as such. The block is limited to 8 KiB; when larger, the lowest-priority records are omitted and the block says how many. The block states that it is lower-trust repository data, not instructions.

### Prompt caching

The block is added only to the newest user message, and only when its content digest differs from the last block in the conversation. Earlier messages and the system prompt are never changed, so the cached prompt prefix stays valid. In Index and Constraints modes, the content depends only on the files in `docs/architecture/`, so a task normally receives the block once. Full mode adds a new copy each time a newly read file matches another record; each copy is billed as new input, though it does not invalidate earlier cache.

For this repository the block is about 4.3 KB (Index) and 5.1 KB (Constraints).

The block is also passed to manual compaction and overflow-recovery summaries, so cited IDs survive compaction. It is not added in untrusted workspaces. If the records cannot be read, Roo posts one notice per task and continues without the block.

## Validation and limits

Focused tests pass: the new architecture context spec (glob matching, all four modes, exclusion of rejected and superseded records, stable output in Index and Constraints, budget omission, tag escaping, append-only-on-change, trust gate, read-failure notice), condense, context-management and task dispatch specs, the modes spec, and the context-management settings spec including the new select. TypeScript checks for types, extension and webview pass. Release gates cover lint, packaging, VSIX ZIP integrity, manifest version, both worker bundles and asset digests. They are not a full test suite.

A live task with a real model was not exercised, so the effect on answers and actual cache hit rates are unverified.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Builds before 4.2.62 show prune-only recovery rows as unknown messages. This release does not migrate or rewrite stored tasks, and no existing task data was read during the release operation.

## Installation

Verify the attached VSIX against its SHA-256 file. Install separately on each extension host. The companion ZIP is optional, unchanged since 4.2.51, and requires separate manual Chrome installation.
