# Roo Code 4.2.62 - Cordis preview 58

Extension version: **4.2.62**. Git tag: **v4.2.62-cordis-preview.58**. Experimental GitHub prerelease, not a stable or marketplace release.

## Overflow recovery prunes large old tool results first

When the provider rejects a request for exceeding its context limit, Roo now shortens large older tool results before it summarizes history.

- A tool result before the latest input that is longer than 8192 characters keeps its first 4096 and last 1024 characters. A marker replaces the middle.
- The full original text is saved in the task folder as `command-output/tool-<n>.txt`. The marker names the artifact. `read_command_output` accepts `tool-<n>.txt` in addition to `cmd-<n>.txt`.
- Roo then estimates the size of the pruned request with the provider's token counter. If it fits within the context window minus the requested output, with a 10% margin, Roo retries without a summary. Otherwise Roo summarizes the pruned history as before.
- If saving an artifact fails, that tool result stays unchanged. If the estimate fails, Roo falls through to the summary.
- The latest input and its tool exchange are never pruned. Pruning is idempotent. Image blocks in tool results are kept.
- A prune-only recovery shows a new **Tool Results Pruned** chat row with the token change and the number of results shortened. It has the **Recover in new branch** action, backed by the same exact pre-event snapshot as compaction and truncation.

Compaction stays overflow-only. Nothing is pruned or summarized before the provider rejects a request. Recovery still runs at most once and retries at most once.

New setting: **Settings > Context management > Prune large tool results first** (`pruneToolResultsOnOverflow`). It is enabled by default and applies only when **Compact on context overflow** is enabled.

## Validation and limits

Focused tests pass: the new pruner spec, the context-management spec with prune-only, prune-then-summarize, estimate-failure and disabled cases, the `read_command_output` artifact id spec, a task-level spec for prune-only acceptance and snapshot identity, the context-management settings spec, and the architecture check spec. TypeScript checking of types, extension and webview passes. These results were produced during the change work. Release gates cover lint, packaging, VSIX ZIP integrity, manifest version, both worker bundles and asset digests. They are not a full test suite.

Known limits:

- Architect and Ask modes do not have `read_command_output`, so they cannot read a pruned artifact back.
- Pruning breaks prompt-cache reuse from the first changed message. This happens only during overflow recovery, where a summary would do the same.
- Character budgets approximate tokens. The provider's token estimate decides whether the summary is skipped.
- Command-output artifacts are not copied into a recovery branch.

A live overflow in a running task was not exercised. Extension activation, macOS install and end-to-end user workflows remain unverified.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Rolling back does not convert snapshots. Preserve task storage before downgrading. Older builds show prune-only recovery rows as unknown messages.

This release does not migrate or rewrite stored tasks, and no existing task data was read during the release operation.

## Installation

Verify the attached VSIX against its SHA-256 file. Install separately on each extension host. The companion ZIP is optional and requires separate manual Chrome installation.
