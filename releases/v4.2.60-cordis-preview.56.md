# Roo Code 4.2.60 - Cordis preview 56

Extension version: **4.2.60**. Git tag: **v4.2.60-cordis-preview.56**. Experimental GitHub prerelease, not a stable or marketplace release.

## Task state survives compaction and delegation

A task with an enabled task-state ledger now supplies that ledger to compaction. The summarization request carries the stored state together with an explicit statement that it is data, not instructions or permission, and that the summary must preserve its objective, completed work, failed approaches and blockers.

A subtask created by delegation now receives the parent task's stored state in its initial message. The section states that it is the parent task's state, that it is data and not instructions or permission, that work already marked implemented or verified must not be repeated, and that failed approaches must not be retried unless the evidence changed.

- Recall is read only. These paths do not write, migrate or rewrite the ledger.
- A task without an enabled ledger sends exactly the previous request. The summarization request is byte-identical, and the child receives the plain delegation message.
- A failed ledger read is logged and treated as absent, so compaction and delegation are not blocked.

## Validation and limits

Two new unit specs cover the summarization request with and without the ledger. The 63 focused tests across `__tests__/provider-delegation.spec.ts`, `core/task/__tests__/subtask-return.spec.ts` and `core/condense/__tests__/condense.spec.ts` pass on this source commit, and backend TypeScript checking passes. Those results were produced during the change work and were not re-run for this release.

Release gates cover packaging, VSIX ZIP CRC, manifest identity and version, both worker bundles, retained feature markers, absence of unfinished provider-connection markers, presence of the ledger-preservation and do-not-repeat wording in the built bundle, source-to-commit hashes, asset SHA-256, GitHub server digest and size, and installed-file byte identity. These gates are not a full test suite.

A live compaction and a live delegated subtask with an enabled ledger were not exercised here. Extension activation, live browser behavior, macOS install and end-to-end user workflows remain unverified.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads. An editor that still reports an older version after a successful install has not reloaded.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Rolling back does not convert snapshots. Preserve task storage before downgrading, and disable automatic updates before a deliberate rollback.

Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery. Avoid navigation while saving history edits.

This change adds read-only recall. Existing stored tasks are not migrated or rewritten by the release, and no task data was read during the release operation. Unfinished provider-connection checks and unrelated local editor, UI, Tetris, archive and research changes are excluded.

## Installation

Verify the attached VSIX against its SHA-256 file. Install separately on each extension host. This release operation installs only on the current Linux code-server host, without reloading the editor or activating the new extension. It does not install on a Mac. The companion ZIP is optional, unchanged since 4.2.51, and requires separate manual Chrome installation.
