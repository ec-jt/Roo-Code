# Roo Code 4.2.46 - Cordis preview 42

Extension version: **4.2.46**. Git tag: **v4.2.46-cordis-preview.42**. Experimental GitHub prerelease, not a stable or marketplace release.

## Memory reports unavailable projects without switching

Memory now rejects an empty, relative, missing, unreadable, or non-directory project path with a clear unavailable-project error instead of a raw filesystem error. The message explains that the selected folder is unavailable on the current extension host and may belong to another machine or an earlier task path.

A failed project-resolution promise is evicted from both the webview memory controller and the task-memory cache. A later request retries resolution for the same task and workspace. Memory does not create a replacement folder, select a different project, or fall back to a Linux home path.

The reported macOS error that named a Linux home path is consistent with a different remote or container extension host, or with an old task path. The exact cause was not confirmed.

## Bounded directory listing replaces the previous scanner

- The filesystem directory-listing action and the legacy list-files tool now share one bounded breadth-first scanner. The previous ripgrep `--follow` multi-stage scan is removed.
- Filesystem calls run in a child Node process started from `process.execPath` with `ELECTRON_RUN_AS_NODE=1`. The worker source is inline and uses only Node built-ins. No new dependency, executable, or packaged worker asset is required.
- Shallow listing reads direct directory entries only. It does not open file contents, read Git ignore files, or follow discovered symbolic links.
- Recursive listing does not follow discovered symbolic links. Canonical paths under `/proc`, `/sys`, or `/dev` are reduced to shallow listing with an explicit reason. Other mounts remain subject to work and time budgets.
- One 10-second deadline covers the whole scan. Limits are 100,000 inspected entries, depth 32, and 50,000 results; interactive tools request 200 results. Directories are read in batches of 32.
- At most four listing workers may remain live. Completion sends termination and escalates to forced termination after 250 milliseconds. A child blocked in an uninterruptible kernel call retains its slot until it exits.
- Both tools request approval before scanning and pass the run cancellation signal through `runReadOnlyTool`. Late results are discarded after cancellation, abandonment, or dispatch closure.
- Cached Roo ignore decisions and protected-path annotations format results without new synchronous path resolution. Recursive scans read regular `.gitignore` files only, limited to 64 KiB per file and 1 MiB in aggregate. Shallow scans intentionally do not apply disk-based Git ignore rules. Global Git and ripgrep ignore configuration is not loaded.

The exact user-reported hang was not reproduced. Windows, macOS, Electron, and remote-filesystem runtime behavior remain untested. Linux fixture tests cover the worker protocol, cancellation, worker limits, ignore policy, and result formatting. See [Bounded directory listing](../docs/directory-listing.md) for behavior and limits.

## Validation and limits

Reused focused results: 40 memory tests across three files passed, and 69 listing tests across seven files passed. A final backend TypeScript check over the whole current state passed. User-focused tests were not rerun because no source behavior changed afterward. Release lint, isolated packaging, archive integrity, source-to-commit identity, checksums, installed-version checks, and uploaded-asset verification are required before publication. These are scoped results, not a full-suite or live-host pass. The directory-listing documentation no longer calls the change source-only; it now states that packaging includes the inline scanner and that platform runtime verification is still required.

The prior release's user-attested checks remain user-attested. Roo's shell-command test runner remains off by default. The Windows file-sync change from an earlier release is present, but the notification after the dispatch is already closed remains unverified and may never appear. No Windows host was used. The Mac grey-panel incident remains unverified.

## Known unresolved findings carried forward

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- The separate bounded large/history command-output preview can still show the beginning instead of following the tail.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Previously reported historical-action and LiteLLM fixture failures and a Bedrock context-window expectation mismatch remain outside this change. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual.

## Install and rollback

Install the attached VSIX and verify its SHA-256 checksum, or use **Settings > About > GitHub release updates**. If an older updater reports a temporary-directory error, install the VSIX manually once. Install separately on each extension host. Finish or stop work before reloading; this release operation does not reload or activate the installed extension. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.45 prerelease remains available. Disable automatic updates before deliberate rollback. Older versions do not provide the task-state workflow; preserve task storage before downgrading. Versions below 4.2.34 do not support the LM Studio token field; versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
