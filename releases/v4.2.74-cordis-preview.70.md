# Roo Code 4.2.74 - Cordis preview 70

Extension version: **4.2.74**. Git tag: **v4.2.74-cordis-preview.70**. Experimental GitHub prerelease, not a stable or marketplace release.

## Computer use: fewer, smaller screenshots

- **Old screenshots leave the conversation.** Only the 3 most recent desktop screenshots stay in the model history. Older ones are replaced by a short note that tells the model to take a new screenshot. Before this, a 20-step desktop task carried 20 full screenshots. Images the user pasted and screenshots from other tools are never removed.
- **Faster JPEG screenshots on macOS.** Screenshots now use the system capture tool and are sent as JPEG at quality 70. Measured live: about 0.3-0.5 s and 140 KB for a 1232x800 image, against about 0.4 s and 300-400 KB as PNG before. If the system capture fails, Roo falls back to the built-in capture and PNG.

## Computer use: safer typing

Text longer than 40 characters is pasted from the clipboard instead of typed key by key. The user's clipboard is read first and restored right after. Measured live: an 89-character sentence with deliberate typos ("teh recieve adress") was entered unchanged in 1 s, and the clipboard was restored. Typing key by key would take several seconds, and macOS autocorrect could change words. Short text is still typed normally. If the clipboard cannot be written, Roo types the text instead.

## Computer use: click elements by name (macOS fallback)

Two new actions use the Accessibility tree instead of pixel coordinates:

- `list_elements`: lists the buttons, text fields, menus and other controls of a window, with their names and positions in screenshot pixels.
- `click_element`: presses an element by name (exact match first, then partial match). The pointer does not move, and the user does not have to stop working.

The model is told to use these when a click by coordinate misses. Apps without Accessibility names (some games and custom-drawn apps) cannot be used this way.

Measured live on TextEdit: `list_elements` found the text area, the window buttons and the document menu in 1.5 s. `click_element` "document actions" opened the menu in 2.4 s. The time depends on how many elements the window has; the search stops after 150 elements or 5 s.

## Validation

- Focused tests pass: desktop services, the tool, the parser, the screenshot history helper, and tool-result ordering (165 tests). New tests cover the fast capture and its fallback, paste with clipboard restore and its fallback, `list_elements` coordinate mapping, `click_element` while the user is busy, and the choice of screenshots to compact. The extension TypeScript check passes. Translations are complete in 17 locales.
- The live checks above ran against the real native module on macOS, outside the editor.

Not yet verified: screenshot compaction in a long live task, Windows and Linux.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback warnings carried forward

Builds before 4.2.74 show the new element actions with their raw action name. The warnings from 4.2.73 still apply. This release does not migrate stored tasks. Compaction changes only screenshots in the in-memory and saved model history of tasks that use computer use after the update.
