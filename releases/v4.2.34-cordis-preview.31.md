# Roo Code 4.2.34 - Cordis preview 31

Extension version: **4.2.34**. Git tag: **v4.2.34-cordis-preview.31**. Experimental GitHub prerelease, not a stable or marketplace release.

## LM Studio optional authentication and discovery

- Add an optional API token to the dedicated LM Studio provider. Store it as a provider secret. Send Bearer authentication when configured; omit authorization when blank. Do not retry rejected credentials without authentication.
- Normalize server-root URLs, accepting a trailing version-one path without duplicating it. Reject URL credentials, queries, and fragments.
- Prefer LM Studio's native REST catalog for downloaded chat models and loaded instances. Preserve loaded inference identifiers and runtime context lengths. Exclude embedding models when type metadata is available.
- Fall back to the OpenAI-compatible model list on older servers. Enrich through the legacy SDK only without a configured token, because the bundled SDK does not support API-token authentication.
- Separate in-memory metadata by server and credential identity instead of using the provider-wide disk catalog. Refresh metadata without explicitly loading or replacing server models.
- Refresh the settings picker using its current draft URL and token. Ignore stale replies, provide a Refresh models button, and show empty lists, authentication failures, and timeouts.
- Preserve inference HTTP status in sanitized errors rather than replacing every failure with generic context-length advice. Do not log server response bodies or request credentials.

Load the selected model in LM Studio or enable the server's own just-in-time loading. Discovery alone does not load models. The complete list is the chat catalog exposed by that endpoint and token, not every model on every machine. Older authenticated REST-only endpoints without type/runtime metadata may expose a limited list and cannot reliably classify embeddings.

## OpenAI Compatible remains available

LM Studio's OpenAI-compatible endpoint passed small live streaming-chat and native-tool-call probes. No tools executed and no workspace or conversation data was sent. Native REST and unauthenticated SDK discovery also succeeded. The observed server had one chat model, one embedding model, and a loaded context size of 126,720 tokens.

The generic OpenAI Compatible UI still requires a non-empty API-key field. For a server without authentication, a dummy value works but provides no protection. Use a real server token when required. Remote unauthenticated HTTP is unsuitable for sensitive prompts; use a private network, secure tunnel, or authenticated HTTPS.

## Validation and limits

71 distinct focused tests passed across discovery, optional-auth SDK headers, inference, tools, timeouts, correlated webview replies, and settings UI. Extension and webview type checks passed. Release lint, packaging, archive integrity, and checksum checks are required by the release procedure.

Authenticated behavior was tested with mocked transports, not a live authenticated server. Full Roo task behavior, all model architectures, and speculative decoding were not live-validated. Legacy SDK waits are bounded, but its transport has no cancellation/dispose API and can outlive the caller timeout.

Claude and DeepSeek thinking-model switching through LiteLLM remains incomplete and unverified. Direct-provider switching improvements from 4.2.33 remain included. Pinned replay and the experimental Anthropic-only mediated runtime retain their restrictions.

## Known unresolved findings

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- Long command-output previews can freeze on the beginning instead of following the tail.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

The pre-existing historical-action guard fixture failure remains outside this change. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. The Mac grey-panel incident remains unverified.

## Install and rollback

From 4.2.30 or later, use **Settings > About > GitHub release updates** after closing the loaded task. Alternatively install the attached VSIX and verify its SHA-256 checksum. Run **Developer: Reload Window** when ready to activate it. Install separately on each extension host. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.33 prerelease remains available. Disable automatic GitHub updates before a deliberate rollback. Earlier releases do not support the new LM Studio token field. Versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
