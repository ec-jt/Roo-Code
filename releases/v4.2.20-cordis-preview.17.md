# Roo Code 4.2.20 - Cordis preview 17

Extension version: **4.2.20**. Git tag: **v4.2.20-cordis-preview.17**. Experimental GitHub prerelease, not a stable or marketplace release.

## Large-history chat and persistence

- Load the original task row and up to 100 recent rows instead of the full conversation into the webview. Older, Newer, and Return to latest replace the current page rather than accumulating old pages.
- Limit normal chat projections to 1 MiB, with bounded previews for large bodies, images, and metadata. Unanswered approvals remain intact, even if they exceed this budget. Large stored messages and file diffs can be inspected in a read-only native editor, up to 8 MiB per request.
- Calculate full-history token, cache, cost, context, and file-change summaries in the backend. Incrementally update affected contributions instead of rescanning the entire conversation on each streamed update.
- Keep historical pages read-only with both UI and backend guards. Preserve draft input and deliver current todos independently of the displayed page.
- Add sampled receive/render acknowledgement diagnostics in the Roo output channel. Reports contain timing and size metadata, not conversation bodies, file paths, or task identifiers.
- Serialize atomic API/UI history writes per task directory. Coalesce superseded pending snapshots without crossing exact durability barriers. Drain writes at checkpoint and closure boundaries; block delegation and replacement if required persistence fails.

Full authoritative history is retained. No conversation data is migrated or deleted. See [large-history documentation](../docs/large-history.md) for limits and diagnostic interpretation.

## Validation and limits

Focused history, UI, persistence, delegation, checkpoint, and transport checks passed, including synthetic 20, 50, and 100 MiB histories. Backend and webview type checks passed. The affected Mac grey-panel incident has not been reproduced, and no interactive Mac memory-pressure or native-editor smoke test was performed.

This reduces renderer history work; it does not eliminate full backend history, whole-history JSON snapshot copies, or disk bandwidth costs. The chat budget does not cap all other extension-state fields. The save queue is process-local, not a cross-process transaction across history, metadata, and checkpoints. Stable and nightly have separate default storage; matching custom paths can still cause overlap.

## Known unresolved preview findings

The four preview 14 review findings remain unresolved:

- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Project memory remains opt-in. Cordis runtime preview remains off by default. Existing approval and storage settings are unchanged. New history controls currently use English labels.

## Install and rollback

Install **roo-cline-4.2.20.vsix**, verify its SHA-256 checksum, then run **Developer: Reload Window** when ready to interrupt the extension session. Install separately on each extension host, including a separate Mac installation.

The previous 4.2.19 prerelease remains available for rollback. Rollback does not erase task history or external memories, stop detached processes, or undo completed actions.
