# Roo Code 4.2.92 - Cordis preview 88

Extension version: **4.2.92**. Git tag: **v4.2.92-cordis-preview.88**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release fixes two small observations from the 4.2.91 live check (O2 and O3), and one from the 4.2.90 live check (O1). Context recovery itself does not change.

## O2: request rows after recovery record the provider start time

In the 4.2.91 live check, requests that ran context recovery before they were sent had no `providerStartedAt` in the timing of their request row. The debug log showed that the requests were sent. So a missing provider start time no longer meant "not sent".

**Cause.** The request loop passes a callback that records the provider start time on the request row. Every retry inside the request (after pre-send recovery, after a provider context rejection, and after an ordinary first-chunk retry) called the request again without that callback. The row then kept no start time, or the start time of the rejected attempt.

**Fix.** Each retry now passes the same callback. The request row records the provider start time of the request that is actually sent. Retries still reuse the same request row, as before. No new rows are created.

## O3: a visible row for a provider context rejection

In the 4.2.91 live check, the provider rejected a request with 400 "prompt is too long". The user saw only "Tool Results Pruned" and then the answer. Nothing showed the rejection or the automatic retry.

**Fix.** When the provider rejects a request because the context is too large, and automatic recovery will run, the chat now shows one warning row before the recovery row:

> **Context too large**
> The provider rejected the request because the context is too large. Recovering and retrying once.

The row is information only. The task continues. It is shown only after a real provider rejection. It is not shown when the check before sending (profiles with a context window override) starts recovery, because no request reached the provider. The text is translated into all supported languages.

## O1 (from 4.2.90): recovery errors are shown once

When automatic recovery failed (for example, a second rejection after the single retry), the error text was shown twice: on the request row ("API Request Failed") and in a separate error row. The request row is still marked as failed, but the text now appears only in the error row.

## Correction to the 4.2.90 release notes

The 4.2.90 release notes now start with a correction: the 4.2.90 commit message says "for all models", but only profiles with a context window override changed. Models without an override still recover only after a provider rejection (C-6). Git history was not changed.

- Tests: `src/core/task/__tests__/task-model-dispatch.spec.ts` (4 new tests) and `webview-ui/src/components/chat/__tests__/ChatRow.context-limit-rejected.spec.tsx` (new).

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until you reload the window.

## Storage and rollback

This release adds no settings. It adds one chat row type (`context_limit_rejected`), which is saved in the task's chat messages. 4.2.91 does not know this row type. Rollback with saved rows of this type was not tested.
