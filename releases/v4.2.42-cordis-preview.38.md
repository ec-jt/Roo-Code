# Roo Code 4.2.42 - Cordis preview 38

Extension version: **4.2.42**. Git tag: **v4.2.42-cordis-preview.38**. Experimental GitHub prerelease, not a stable or marketplace release.

## Windows request snapshot failure

- Fix the Windows `EPERM` failure when syncing a newly written model-operation record. The sync helper opened the file read-only, but Windows implements `fsync` with `FlushFileBuffers`, which requires write access. Regular files now open read-write for the sync. Directories still open read-only, because `"r+"` cannot open a directory and directory sync only runs on POSIX.
- Apply the same fix to the second sync helper used for model-operation receipts.
- Show a visible chat error when the request snapshot cannot be saved. Previously the task closed dispatch and stayed on "Preparing" with no explanation. The message states that no provider request was sent and includes the sanitized storage error.

This addresses the reported symptom: an empty `model-operation/` directory, `ui_messages.json` stopping at `api_req_started`, and no provider connection. The user confirmed a manual two-character patch to the installed bundle made the write, sync, and link sequence complete.

## Validation and limits

102 focused model-operation storage tests passed, covering request snapshots, branch provenance, replay, command artifacts, concurrent publication, and directory sync failure reporting. The extension TypeScript check passed. Release lint, packaging, archive integrity, checksum, installed-version checks, and uploaded asset verification are required before publication.

Windows behavior is verified by reasoning and POSIX tests only. No Windows host was used for this build. The directory-versus-file distinction was added after the first attempt failed the storage tests with `EISDIR` on directory sync.

The 4.2.41 updater fixes remain included: portable temporary-directory permissions and installation while a task is loaded. The 4.2.40 LiteLLM discovery and empty-selection fixes remain included. Earlier terminal-output, ripgrep, Settings/MCP, LM Studio, diagnostic-export, and new-task model-selection fixes remain included.

## Known unresolved findings

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- The separate bounded large/history command-output preview can still show the beginning instead of following the tail. Recent-output previews apply to normal command cards.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Pre-existing historical-action and older LiteLLM handler fixture failures, plus a Bedrock context-window expectation mismatch, remain outside this change. This is not a claim that the entire repository test suite passes. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. The Mac grey-panel incident remains unverified.

## Install and rollback

Install the attached VSIX and verify its SHA-256 checksum, or use **Settings > About > GitHub release updates** from 4.2.30 or later. Run **Developer: Reload Window** when ready to activate it. Install separately on each extension host. End-to-end in-app Remote SSH installation remains unverified.

If you patched an installed `extension.js` by hand for this defect, that patch is replaced by this release. The previous published 4.2.41 prerelease remains available. Disable automatic GitHub updates before a deliberate rollback. Versions below 4.2.34 do not support the LM Studio token field. Versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
