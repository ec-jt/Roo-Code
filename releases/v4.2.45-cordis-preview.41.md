# Roo Code 4.2.45 - Cordis preview 41

Extension version: **4.2.45**. Git tag: **v4.2.45-cordis-preview.41**. Experimental GitHub prerelease, not a stable or marketplace release.

## Opt-in task state for long-running work

- Add a task-local ledger with immutable revisions, history anchors, and compare-and-swap protection against stale writes. Work-item claims remain distinct from runtime observations and user-attested acceptance checks.
- Add a native Task state panel for initialization, reviewed corrections, policy configuration, disabling recall and continuation, Markdown export, and an explicit same-workspace fork into a task without a ledger.
- Expose model read and patch requests through the existing approval controls. Model requests cannot grant continuation permission or bypass tool permissions.
- Recall bounded, lower-trust task state in provider context after opt-in. Do not inject it into live prepared replay. Stored references and observations are not automatically revalidated against current files.
- Keep stable todo IDs when reconciling work items. A claimed status of verified is not independent evidence of acceptance.

## Explicit reviewed fresh context

After reviewing and saving state against current history, the user can approve a fresh-context checkpoint without an LLM summary or automatic dispatch. Original messages remain stored; the newest interaction is retained in provider context. The checkpoint validates retained context, model budget, current revision, and history coverage. Active work, stale state, unresolved tool pairs, prepared replay, and unsupported split-result batches are refused.

If saving fails, restore the live history and close dispatch because the on-disk outcome may be uncertain. Keep the pre-change recovery snapshot for inspection. This is a reviewed reduction of provider context, not a guarantee that all prior knowledge remains available. It does not change the existing overflow-only automatic recovery policy or guarantee a fix for provider compaction failures.

## Bounded continuation, disabled by default

The user must review a policy with acceptance-check descriptions, then explicitly arm the next ordinary turn through native confirmation. Arming alone does not dispatch work. Existing mode restrictions and approvals still apply. Step, elapsed-time, token, and no-progress limits are checked at dispatch, tool, and completion boundaries; they do not interrupt an operation already in flight.

Acceptance checks are **user-attested descriptions only**. Recording a result does not run shell commands, tests, or an automatic verification procedure. Saving policy resets counters and attestations. Stopping continuation revokes permission without interrupting an in-flight request or tool.

See [Task state and reviewed continuation](../docs/task-state.md) for workflow and recovery instructions. Recall is capped at 24,000 characters, and storage at 200 revisions and 4 MiB. No automatic growth pruning is implemented. Recalled data is sent to the configured provider; do not store secrets.

## Validation and limits

Reused focused results: 61 backend tests across task-state runtime, store, task-state context, and completion; a subsequent final checkpoint suite passed 14 tests, including four new regressions; backend TypeScript checking passed. The UI hook and panel suites passed 16 tests, and UI TypeScript checking passed. These are scoped results, not a full-suite pass.

Two additional runs had unrelated failures that are not included as passing coverage: the model-operation suite passed 56 tests and failed one suspended-stream preview expectation; the ChatView window suite passed 13 tests and failed one user-edit operation-ID expectation in the presence of unrelated editor changes. The release excludes those unrelated editor and provider-connection changes. Release lint, isolated packaging, archive integrity, source-to-commit identity, checksums, installed-version checks, and uploaded-asset verification are required before publication.

No live extension-host/browser workflow, process crash, power loss, or live provider request validates this feature. Stale transaction locks may require manual recovery. Installation does not reload the window or prove activation. The standalone browser development fallback does not send or log task-state payloads.

Previous Windows file-sync, updater, LiteLLM discovery, terminal-output, ripgrep, Settings/MCP, LM Studio, diagnostic-export, new-task selection, and overflow-recovery changes remain included. The Windows file-sync change is present, but the earlier snapshot-error notification is not a verified fix: dispatch may already be closed when the notification is attempted, so it may never become visible. No Windows host was used. Authenticated LM Studio retains its live-test limitations. Claude and DeepSeek thinking-model switching through LiteLLM remains incomplete and unverified.

## Known unresolved findings carried forward

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- The separate bounded large/history command-output preview can still show the beginning instead of following the tail.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Previously reported historical-action and LiteLLM fixture failures and a Bedrock context-window expectation mismatch remain outside this change. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. The Mac grey-panel incident remains unverified.

## Install and rollback

Install the attached VSIX and verify its SHA-256 checksum, or use **Settings > About > GitHub release updates**. If an older updater reports a temporary-directory error, install the VSIX manually once. Install separately on each extension host. Finish or stop work before reloading; this release operation does not reload or activate the installed extension. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.44 prerelease remains available. Disable automatic updates before deliberate rollback. Older versions do not provide the new task-state workflow; preserve task storage before downgrading. Versions below 4.2.34 do not support the LM Studio token field; versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
