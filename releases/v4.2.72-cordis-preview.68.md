# Roo Code 4.2.72 - Cordis preview 68

Extension version: **4.2.72**. Git tag: **v4.2.72-cordis-preview.68**. Experimental GitHub prerelease, not a stable or marketplace release.

## Fix: 400 "tool_use ids were found without tool_result blocks immediately after"

Anthropic rejected the request when the model called several image-returning tools in one turn. For example, three `read_file` calls on PNG files produced this user message:

`tool_result, image, tool_result, image, tool_result, image, text`

Anthropic requires all `tool_result` blocks to come first. The first image ends the tool-result section, so the second and third results were reported as missing, and the task could not continue.

Roo now moves every `tool_result` block to the front of a user message before the request is sent, and keeps the order of the other blocks. Messages that are already in a valid order are sent unchanged, so prompt caching is not affected. The fix runs on each request, so tasks that already contain the bad order work again after the update. Stored task history is not rewritten.

## Computer use fixes (found in the first live macOS test)

- **Key combinations with Cmd failed.** libnut rejects the modifier name `command` with "Invalid key flag specified". Roo now sends `meta`, the name libnut uses for the Command key on macOS and the Windows key on Windows.
- **Clicks could land at the old cursor position.** On macOS the first mouse move in a process can take about 35 ms to apply, and libnut clicks wherever the cursor is. Roo now waits up to 150 ms after each move until the cursor reports the target position.

Confirmed live on macOS with the real native module: screenshot (3024x1964 capture reduced to 1232x800, about 370 ms), window list, focus window, click on a Retina display at the mapped point, and scroll.

## Validation

Focused tests pass: the new tool-result ordering spec (interleaved results and images, already-valid order unchanged, text before a result), the existing tool-result ID validation spec, and all desktop service specs including the new `meta` mapping and cursor-wait tests (129 tests). The extension TypeScript check passes.

Not yet verified live: typing and key combinations after the `meta` fix, scroll direction on screen, approvals, allowlist, stop key and status indicator inside the editor.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback warnings carried forward

The warnings from 4.2.71 still apply. This release does not migrate or rewrite stored tasks.
