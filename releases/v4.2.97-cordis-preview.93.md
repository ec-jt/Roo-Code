# Roo Code 4.2.97 - Cordis preview 93

Extension version: **4.2.97**. Git tag: **v4.2.97-cordis-preview.93**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release implements the follow-up from ADR-2026-11-20-feature-gating-evaluation-and-lessons ("From task state"): failed approaches recorded in task state are offered as lessons once, at `attempt_completion`.

## New: lesson offer at completion

When the model calls `attempt_completion`, Roo checks these conditions:

1. Task state is enabled for the task, recall is on, and the current ledger snapshot has at least one `failedApproaches` record.
2. Project memory is on for the task's project, and **Save lessons** is on (`MemoryStore.canSaveLessons()`).
3. The memory tool is allowed in the current mode and is not disabled.
4. The offer has not been shown in this task.

If all conditions hold, the task does not complete on that call. The tool result:

- lists the failed approaches (ID and JSON-quoted text, at most about 2,000 characters, with a count of omitted records) inside a `<task_state_failed_approaches>` block that is labelled as task data, not instructions (Q-SEC-1);
- asks the model to save one project `lesson` topic through the memory tool for each approach with concrete evidence from this task, with the lines `cue:`, `lesson:`, `evidence:` (this task's ID and a request or tool-call reference) and an optional `confidence:`;
- tells the model to save nothing for an approach without evidence (`NO_ENTRY`);
- tells the model to call `attempt_completion` again.

The second call completes normally. The memory tool's normal approvals and lesson gates apply to every save. There is no extra model call and no background job.

The offer applies to root tasks and subtasks. On the offer turn, no evaluation stop is recorded and a subtask does not return to its parent.

If any condition fails, or reading task state or memory fails, completion runs exactly as before. Errors are logged and not shown.

The offer is skipped when the task has user-attested acceptance checks configured, because memory tool calls change the tool history that those checks are bound to.

### Shown once

Roo keeps an in-memory flag per task instance. Before it returns the offer, it also appends a runtime evidence record with the ID `lesson-offer-shown` to the task-state ledger. A resumed task finds that record and does not repeat the offer. If the record cannot be written, the offer is not shown.

### Isolated subtasks

The memory project is resolved from the task's working directory through `git rev-parse --git-common-dir`. A git worktree has the same common directory as its main checkout, so an isolated subtask uses the same project memory and the same Save lessons setting as its parent.

## Changes

- `src/core/tools/lesson-offer.ts` (new): the conditions, the bounded offer text, and the shown-once flag and evidence record.
- `src/core/tools/AttemptCompletionTool.ts`: returns the offer before the task-state completion gate, the subtask return and the completion prompt.
- No change to `Task.ts`, to locales or to stored data formats. The offer is model-facing text only.

## Storage and rollback

The only write is one runtime evidence record appended to the task-state ledger through the existing append-only path (C-5). Older versions read it as ordinary runtime evidence.
