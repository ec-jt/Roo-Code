# Roo Code 4.2.9 - Cordis preview 7

Extension version: **4.2.9**. Git tag: **v4.2.9-cordis-preview.7**. This is a GitHub prerelease, not a stable or marketplace release.

## Implementation first

The system and delegation prompts favor direct implementation once enough information is available to act safely. Multiple or nested subtasks should be used only for a concrete independent deliverable or specific blocker, not merely because a task is large. Existing nested-delegation justification, approval, and permission checks remain unchanged.

Validation should address a specific risk or an explicit user/project requirement. Prefer the smallest relevant check, reuse valid results from the current code state, and avoid routine full test/lint/type/build cycles after every edit. Stop when the requested deliverable and necessary validation are complete. This does not waive mandatory checks or permit unsupported success claims.

## Better child-to-parent context

Child completion guidance requests a self-contained handoff:

- Outcome, changes, essential findings, evidence, and important decisions.
- **Parent must check:** key files, symbols or line ranges, and existing artifacts, with what to read, why it matters, and what to verify.
- Validation commands, working directories, results, failures, and unverified areas.
- Remaining work, risks, blockers, and completed work that later subtasks should not repeat without a reason.

The parent receives the complete child result with a reminder to inspect critical references when permitted, retain useful findings, and carry them into future briefs. References supplement essential conclusions rather than replacing them. The mechanism does not automatically read files, copy the child's full transcript, or widen permissions. Legacy history retry deduplication remains supported.

## Validation and limits

Handoff and delegation validation passed 159 tests across nine suites during implementation. The final focused prompt run passed 40 tests across four suites, including explicit checks that the implementation-first text reaches the system and delegation prompts. These runs overlap and are not additive. Prompt snapshots reflect the new wording. Model compliance is not schema-enforced and is not guaranteed to eliminate all redundant work.

No new provider behavior or browser launch policy is introduced. The host-specific non-root code-server and AppArmor repair is not part of this portable extension package. Cordis runtime preview remains off by default.

## Install and rollback

Install **roo-cline-4.2.9.vsix**, verify its accompanying SHA-256 checksum, and run **Developer: Reload Window**. Start a new task to ensure the new system and tool instructions are used. The extension ID is unchanged.

The previous 4.2.8 prerelease remains available for rollback. Rollback does not undo completed task actions or host configuration changes.
