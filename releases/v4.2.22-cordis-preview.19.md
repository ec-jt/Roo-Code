# Roo Code 4.2.22 - Cordis preview 19

Extension version: **4.2.22**. Git tag: **v4.2.22-cordis-preview.19**. Experimental GitHub prerelease, not a stable or marketplace release.

## Edit assistant responses without running

- Add Edit assistant response and Save without running to completed assistant text responses on the latest chat page.
- Update assistant text in both UI and model history while preserving later messages, tool calls/results, reasoning, timestamps, and usage records.
- Do not send a user message, resume the task, rewind files, or rerun tools when saving.
- Reject stale task instances and changed source text. Keep drafts open on rejected saves and report missing acknowledgements without automatic retries.
- Invalidate reusable provider response context from the edited turn onward, so the next request uses the edited local history.
- Use exact persistence barriers, rollback attempts, and an interruption marker to prevent dispatch through uncertain history after a failed save.

This is **conversation-history editing**, not assistant-prefill continuation. Later responses are preserved, not regenerated, and can contradict the edit. Normal provider formatting and context limits still apply.

## Availability and recovery

Editing requires a stopped or settled foreground task. Stop active work and reopen without resuming when instructed. Only completed assistant text with an exact, unambiguous model-history match is supported. Condensed/truncated turns, synthetic text, multi-text responses, reasoning, tool-generated completion messages, and prepared replay tasks are excluded. Historical pages remain read-only. New editor labels use English.

API and UI files are not one filesystem transaction. If an interrupted edit leaves the pending-edit marker, reopening remains blocked until a consistent history pair is restored. **Do not remove the marker merely to bypass the error.** Back up important conversations before editing. See [assistant editing and recovery documentation](../docs/assistant-response-editing.md).

## Validation and limits

Focused backend mapping, persistence, acknowledgement, historical-guard, and UI tests passed. Backend and webview type checks passed. Tests cover stale/busy rejection, unchanged later history, no automatic execution, rollback failure, draft retention, and provider-context invalidation. No live-provider request, real-filesystem crash-injection, or interactive Mac test was performed.

The large-history and process-local queue limits from preview 17 remain. The earlier Mac grey-panel incident is still unverified.

## Known unresolved preview findings

- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Project memory remains opt-in. Cordis runtime preview remains off by default. Existing approval and storage settings are unchanged.

## Install and rollback

Install **roo-cline-4.2.22.vsix**, verify its SHA-256 checksum, then run **Developer: Reload Window** when ready to interrupt the extension session. Install separately on each extension host, including a separate Mac installation.

The previous 4.2.21 prerelease remains available for rollback. **Resolve any interrupted assistant edit before downgrading**, because earlier versions do not recognize the pending-edit marker. Rollback does not undo history edits, erase external memories, stop detached processes, or undo completed actions.
