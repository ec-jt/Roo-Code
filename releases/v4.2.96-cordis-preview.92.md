# Roo Code 4.2.96 - Cordis preview 92

Extension version: **4.2.96**. Git tag: **v4.2.96-cordis-preview.92**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release implements ADR-2026-11-20-isolated-subtask-workspace: a subtask can share its parent's workspace (the default, unchanged) or run in an isolated git worktree. The choice exists only in a development extension host.

## New: shared or isolated subtask workspace (development builds only)

`new_task` has an optional `workspace` parameter with two values:

| Value              | Behaviour                                                                                                             |
| ------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `shared` (default) | The child works in the parent's folder, on the same files and checkpoints. This is the behaviour of earlier versions. |
| `isolated`         | The child works in a new git worktree created from the parent's `HEAD`, on the branch `roo/subtask/<childTaskId>`.    |

The tool description tells the model when to choose each value (the ADR's Decision table). A missing or `null` value means `shared`.

### Isolated flow

1. Roo checks that the parent's folder is inside a git repository that has a `HEAD` commit. If it is not, `new_task` returns an error with the reason before the approval and creates no child. It never falls back to `shared`.
2. After approval, Roo creates the worktree next to the repository root, at `<repoParent>/<repoName>-subtask-<shortId>`, with the existing worktree service (`git worktree add -b roo/subtask/<childTaskId> <path> <HEAD>`). A creation failure stops the delegation with the reason, before the parent is closed, and creates no child.
3. The child's working directory is the worktree (the same subfolder when the parent works below the repository root). File tools, commands and checkpoints use this folder.
4. The `new_task` result tells the parent that its uncommitted changes, installed dependencies and build output are not in the worktree.
5. When the child completes, the result the parent receives ends with `Isolated workspace: branch roo/subtask/<id> at <path>`, the committed changes (`git diff --stat <base>...HEAD`) and the uncommitted changes (`git status --short`) of the worktree.
6. Roo never merges the branch and never deletes the worktree. The result text says so. Remove the worktree from the Worktrees view when it is no longer needed.

The `new_task` approval row shows a line when the subtask is isolated.

### Resume

The child's history item stores four optional fields: `workspaceMode`, `worktreePath`, `worktreeBranch` and `worktreeBaseCommit`. A resumed isolated child reopens in its worktree. If the worktree folder no longer exists, Roo shows an error and does not open the task, so it can never run in the parent's workspace by mistake.

### Production

Outside `vscode.ExtensionMode.Development` the `new_task` schema has no `workspace` parameter, a `workspace` value sent anyway is ignored, and every subtask is shared. A test checks that the parameter is absent from the production schema.

## Checkpoints

Checkpoints are stored per task (`tasks/<taskId>/checkpoints`), and the shadow repository's work tree is the task's working directory. An isolated child therefore has its own shadow repository whose work tree is the worktree. The workspace hash used by `ShadowCheckpointService.hashWorkspaceDir` also differs for the worktree path. A test checks both.

## Changes

- `src/core/tools/subtask-workspace.ts` (new): the development-mode gate, the schema extension, the git check, worktree creation through `worktreeService` from `@roo-code/core`, the delegation and return texts, and the history-item helpers.
- `src/core/tools/NewTaskTool.ts`: reads `workspace`, checks git before approval, adds `workspace` to the approval payload, and passes it to delegation.
- `src/core/webview/ClineProvider.ts`: creates the worktree for an isolated delegation before closing the parent; creates the child with its pre-allocated ID and the worktree as cwd; refuses to reopen an isolated task whose worktree is missing.
- `src/core/task/Task.ts`: an optional `subtaskWorkspace` option; an isolated child uses its worktree as cwd instead of the parent's; the history fields are added when the task saves.
- `src/core/tools/AttemptCompletionTool.ts`: appends the isolated summary on the subtask return path.
- `src/core/task/build-tools.ts`: adds the parameter to the `new_task` schema only in development mode.
- `src/core/assistant-message/NativeToolCallParser.ts`, `src/shared/tools.ts`, `src/core/task/delegation-policy.ts`: carry the `workspace` argument.
- `packages/types`: optional history-item fields and the `workspace` field of the `newTask` approval payload.
- `webview-ui/src/components/chat/ChatRow.tsx`: the isolated line in the `new_task` row.
- Locales: `common:errors.isolated_worktree_missing` (extension) and `chat:subtasks.isolatedWorkspace` (webview) in all 18 languages.
- `src/utils/pathUtils.ts` and the file tools: `isPathOutsideWorkspace` accepts extra roots, and the file tools pass the isolated child's worktree root (`getTaskWorkspaceRoots`), so reads, writes and edits in the worktree are no longer flagged "outside workspace". Shared tasks are unchanged.

## Storage and rollback

The four history-item fields are optional and additive (C-5). Existing tasks are not read in bulk or changed. Older versions ignore the fields: after a rollback, an isolated child reopens in the folder stored in its `workspace` field (the worktree path) if it still exists. Worktrees and `roo/subtask/*` branches stay until the user removes them.
