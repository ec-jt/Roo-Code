# Roo Code 4.2.26 - Cordis preview 23

Extension version: **4.2.26**. Git tag: **v4.2.26-cordis-preview.23**. Experimental GitHub prerelease, not a stable or marketplace release.

## Context recovery branches

- Add **Recover in new branch** to compaction and truncation events, including historical-page previews.
- Choose a saved provider/model profile and either compact the restored context or keep it uncompressed.
- Save a standalone **[Context recovery]** task in History without automatically continuing. Leave the original parent, completed child, delegation metadata, and files unchanged.
- Preserve the exact pre-event history, including completed child results present at that boundary. Later parent messages remain in the original task. Earlier compactions remain part of the selected event's input.
- Save exact recovery snapshots before publishing new context replacements. Refuse older events that have no snapshot rather than guess their boundaries.
- Require stopped or settled source execution and complete tool-call/result pairs. Disable source checkpoint reuse and provider response chaining in the branch. Retain a durable preparation marker so an interrupted branch cannot resume as if preparation succeeded.

See [context recovery](../docs/context-recovery.md). **This feature cannot retroactively recover old compaction events without exact snapshots, including events created by 4.2.14.** Snapshot storage adds disk usage. Command-output artifacts are not copied. This is not a filesystem rollback. Review the current workspace before resuming the branch.

## Codex tool-result protection

Filter outgoing Codex function-call outputs that have no matching function call in the same request. This prevents the corresponding provider rejection but does not recover missing calls or establish the cause of a historical error. Recovery branches use stricter validation and refuse incomplete exchanges.

## Validation and limits

235 distinct focused tests passed across Codex request formatting, recovery snapshots, task persistence/reload, overflow dispatch, and UI behavior. Backend and webview type checks passed. No live-provider requests, interactive VS Code recovery flow, Mac validation, or real-filesystem crash-injection test was performed.

The selected profile is saved with the branch and used for optional compaction, which can incur model charges. An ordinary compaction error leaves the restored branch uncompressed with the error visible. A failed durable preparation blocks branch resumption. Restoring large uncompressed context can overflow again after explicit resume.

## Known unresolved lifecycle findings

- **Closing a task blocked by an interrupted assistant-edit marker can overwrite its UI history with an empty snapshot.** Preserve the task directory before attempting recovery.
- **Closing or switching during an assistant edit can leave the task stuck even after a safe rollback.** Avoid task navigation while an edit is saving.
- Checkpoint-based user edits can be silently dropped if replacement history loading takes longer than the fixed continuation delay.
- Approving an unrelated command can mark an older denied file edit as approved in the UI and file summary. This does not execute the denied write.

## Other known unresolved preview findings

- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Project memory remains opt-in. Cordis runtime preview remains off by default. New labels use English. The Mac grey-panel incident remains unverified.

## Install and rollback

Install **roo-cline-4.2.26.vsix**, verify its SHA-256 checksum, then run **Developer: Reload Window** when ready to interrupt the extension session. Install separately on each extension host.

The previous 4.2.25 prerelease remains available. Do not open unfinished recovery branches in older versions, which do not enforce their preparation marker. Resolve interrupted assistant edits before downgrading below 4.2.22. Rollback does not undo stored history edits, remove truncation tags, restore files, erase memories, or stop detached processes.
