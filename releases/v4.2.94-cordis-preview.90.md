# Roo Code 4.2.94 - Cordis preview 90

Extension version: **4.2.94**. Git tag: **v4.2.94-cordis-preview.90**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release fixes the GitHub release updater on remote extension hosts (SSH, WSL, dev containers).

## Problem

On an SSH remote window, the Roo update panel said "Remote extension host (ssh-remote) · Running 4.2.55" and "Version X was installed. Reload the window to activate it." Reloading did not help: the remote host stayed on 4.2.55, and the updater refused to check again ("already staged. Reload before another update").

## Cause

After a successful install, the updater saves an install receipt (`githubReleaseUpdater.installedVersion`) in VS Code `globalState`. That storage is shared by the local and the remote extension hosts of the same window. The receipt written when the local (Mac) host installed an update was read by the remote host. The remote host then reported an install that never happened on the remote machine, and blocked its own update.

The remote machine's extension folder (`~/.vscode-server/extensions`) contained only 4.2.55, which confirms that no install ran there.

## Fix

- The install receipt is now scoped to the extension host: `githubReleaseUpdater.installedVersion:<remote name or "local">:<host name>`. Each host only sees its own receipt.
- The old unscoped receipt is ignored, and a successful install removes it, so older builds on other hosts stop reading it.

## Hosts still on 4.2.55 need one manual install

A remote host that runs an old build still uses the old updater, so it cannot move past the shared receipt by itself. Install once by hand, in a terminal of the remote window:

```
curl -fL -o /tmp/roo.vsix https://github.com/ec-jt/Roo-Code/releases/download/v4.2.94-cordis-preview.90/roo-cline-4.2.94.vsix
code --install-extension /tmp/roo.vsix --force
```

Then reload the window. From 4.2.94 on, the remote host updates itself through the update panel.

## Changes

- `src/services/updates/ReleaseUpdater.ts`: `installedReceiptKey()` scopes the receipt; the legacy key is ignored and cleared after an install.
- `src/services/updates/__tests__/ReleaseUpdater.spec.ts`: 2 new tests (receipt scoping; a legacy receipt from another host does not block an update).

## Validation

- `cd src && npx vitest run services/updates`: 118 passed.
- `tsc --noEmit` in `src` passed. `eslint` on the changed files found no problems.

Not verified yet: a live update on an SSH remote host after the manual install of 4.2.94.

## Storage and rollback

The receipt key changes. After a rollback, an older build reads only the legacy key, which 4.2.94 clears; the older build then shows no stale "installed" state. No settings change.
