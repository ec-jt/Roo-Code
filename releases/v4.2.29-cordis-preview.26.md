# Roo Code 4.2.29 - Cordis preview 26

Extension version: **4.2.29**. Git tag: **v4.2.29-cordis-preview.26**. Experimental GitHub prerelease, not a stable or marketplace release.

## Independent context-recovery controls

- Retain **Compact on context overflow** and add a separate saved **Allow truncation fallback** setting in Context Management.
- Show the selected policy: manual-only, compaction-only, or compaction with eligible truncation fallback. Save settings to apply changes; saving does not resume a stopped task.
- Preserve existing automatic-compaction preferences. The new fallback control defaults to enabled for compatibility but has no effect when automatic compaction is off.
- Distinguish a context-limit failure caused by disabled automatic recovery from one that persists after recovery and its single retry.
- Keep the overflow-only policy: no percentage-based trigger, no truncation for unrelated failures, and no additional retry allowance. Fallback is eligible only if overflow compaction also exceeds the context limit or returns an empty summary.

See [context policy](../docs/context-budget.md).

## Condensed summary previews

- Show **Context summary** with bounded summary text instead of an empty history preview. Large structured summaries no longer lose all their preview content.
- Make **Open full message** read the stored summary, subject to the existing 8 MiB native-editor limit.
- Keep ordinary recovery-event identities and original stored history intact. This display fix requires no new compaction or migration of existing summaries.

## Linux browsers and Remote SSH

- Add installed Google Chrome discovery on Linux using standard vendor/system paths. Preserve the sandbox, isolated session profiles, and no-download/no-fallback behavior.
- Add Browser settings instructions for using a browser on the Linux extension host or a dedicated Mac Chrome profile through a private SSH reverse tunnel, including forwarding server-hosted development sites.
- Include the extension-host location and browser executable in local launch failures. A server AppArmor or namespace restriction still requires appropriate host configuration; Roo does not weaken the sandbox or change security policy.
- Validate a bounded Chrome debugging discovery response instead of treating any HTTP success as a browser connection. HTTP discovery does not prove WebSocket access or external sandbox configuration.

See [Remote SSH setup](../docs/browser-remote-ssh.md). Mac Chrome and SSH tunnels must be started manually. Use only trusted hosts/accounts, keep debugging listeners private, and verify loopback bindings. Other users on a shared server may reach a loopback listener. The independent web-to-Markdown fetcher still uses managed Chromium on the extension host.

## Validation and limits

229 distinct focused tests passed across browser launch/discovery/settings (77), summary previews/history (31), and recovery/settings controls (121). Backend and frontend type checks passed for the combined working tree. No live-provider, real Mac-to-server tunnel, affected-server sandbox, interactive VS Code, or real-filesystem crash-injection verification was performed.

Compaction input must still fit the selected model. Recovery branches still require exact pre-event snapshots; older events without snapshots remain unsupported. Task-only checkpoint restore remains an in-place conversation rewind, not a file rollback.

## Known unresolved findings

- **Closing a task blocked by an interrupted assistant-edit marker can overwrite its UI history with an empty snapshot.** Preserve the task directory before attempting recovery.
- **Closing or switching during an assistant edit can leave the task stuck after a safe rollback.** Avoid navigation while an edit is saving.
- Checkpoint-based user edits can be dropped if replacement history loading exceeds the fixed continuation delay. This is separate from the checkpoint-menu restore operation.
- Approving an unrelated command can mark an older denied file edit as approved in the UI and file summary. This does not execute the denied write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Project memory remains opt-in. Cordis runtime preview remains off by default. New settings/help text uses English. The Mac grey-panel incident remains unverified.

## Install and rollback

Install **roo-cline-4.2.29.vsix**, verify its SHA-256 checksum, then run **Developer: Reload Window** when ready to interrupt the extension session. Install separately on each extension host.

The previous 4.2.28 prerelease remains available. It does not honor the separate truncation-fallback setting; disable automatic compaction before downgrading if automatic truncation must remain off. Do not open unfinished recovery branches in versions below 4.2.26, which do not enforce their preparation marker. Resolve interrupted assistant edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo history edits, remove truncation tags, restore files, erase memories, or stop external Chrome/SSH sessions or detached processes.
