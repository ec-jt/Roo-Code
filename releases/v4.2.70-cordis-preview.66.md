# Roo Code 4.2.70 - Cordis preview 66

Extension version: **4.2.70**. Git tag: **v4.2.70-cordis-preview.66**. Experimental GitHub prerelease, not a stable or marketplace release.

## Image offload during overflow recovery (all tasks)

When the provider rejects a request for exceeding its context limit, Roo now reduces older images before it summarizes:

1. Large older tool results are shortened (since 4.2.62).
2. **New:** older images (screenshots, pasted images, and images inside tool results) are saved to the task folder as `images/<sha256>.<ext>` and replaced in the conversation by a short reference with the file path.
3. If that alone fits the request, Roo retries without a summary. Otherwise it summarizes the reduced history as before.

- The latest input and its tool exchange always keep their images.
- Identical images are saved once.
- If an image cannot be saved, it stays in the conversation.
- Models without image support are not affected; their images are already dropped in the summary request.
- The recovery row shows how many images were saved. **Recover in new branch** restores the exact earlier history, images included.
- Reading an offloaded image again with `read_file` needs approval to read outside the workspace.

Setting: **Settings > Context management > Offload older images first** (`offloadImagesOnOverflow`, default on). It is available when **Compact on context overflow** is on.

Offload, like pruning, changes older messages and so breaks prompt-cache reuse from that point. It runs only during overflow recovery, where a summary would do the same.

## Validation

Focused tests pass: the image-offload spec (only older images, recent kept, dedupe by hash, save failure keeps the image, media-type extensions), context-management specs including offload after pruning, prune-or-offload-only result, non-image models untouched and the setting off, and the context-management settings spec (default on, toggle, disabled in manual-only mode). TypeScript checks for types, extension and webview pass. Release gates cover lint, packaging, VSIX ZIP integrity, manifest version, both worker bundles and asset digests.

Pre-existing failures, identical on 4.2.67 or earlier: `TruncationFallback.spec.tsx` (missing context provider in the test), the chat view queued-message test, 4 presenter policy-boundary tests, 25 tests in `src/core/task/__tests__`, and the others listed in 4.2.68.

Image offload was not exercised with a live model or a real context-limit rejection.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Builds before 4.2.62 show prune-only recovery rows as unknown messages; builds before 4.2.70 ignore the offloaded-image count in those rows. Builds before 4.2.68 show a plan review as an unknown message. This release does not migrate or rewrite stored tasks, and no existing task data was read during the release operation.
