# Roo Code 4.2.32 - Cordis preview 29

Extension version: **4.2.32**. Git tag: **v4.2.32-cordis-preview.29**. Experimental GitHub prerelease, not a stable or marketplace release.

## Change models without restarting a response

- Keep the model-profile selector usable during a task and offer **Use for next request** alongside the existing stop/restart action.
- Queue the saved profile on the current task instance. Leave the active response and tool execution unchanged, do not start a request or create a branch, and do not change the global profile.
- Apply the profile at the next request boundary, including automatic continuation after tools. Display **(next request)** while pending. Pending choices are discarded if the task closes before application.
- Preserve strict restart/task-graph restrictions, organization policy, pinned replay profiles, and mediated-runtime provider restrictions. Overlapping profile loads are rejected rather than applied out of order.
- Send correlated rejection results for busy, background, historical, and failed model operations. Show an unknown-outcome warning after 60 seconds without a terminal acknowledgement; never automatically replay the operation.

## Protect user-message edits

- Route short and preview messages through one editor with mandatory task, instance, message, revision, and operation identity.
- Require a settled resume prompt. Stop and reopen the task without resuming before editing. Refuse edits during active requests, tools, approvals, terminals, queued work, and unsettled delegation.
- Lock dispatch while saving both histories. Attempt rollback on failure and block further dispatch in that task instance.
- Keep drafts through confirmation, cancellation, failure, and timeout. Ignore duplicate retrieval responses. Close only after the matching success result.
- Prevent the confirmation dialog from sending Cancel after Confirm.

User edits discard later messages and can send a new request. They do not restore files. Checkpoint-based editing is now explicitly unavailable rather than using the unreliable delayed continuation. Use separate checkpoint controls when needed. Drafts are not durable across navigation or webview reloads. Assistant-response edits still preserve later history and never run automatically.

## Known unresolved findings

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- Long command-output previews can freeze on the beginning instead of following the tail.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. The Mac grey-panel incident remains unverified.

## Install and rollback

From 4.2.30 or later, use **Settings > About > GitHub release updates** after closing the loaded task. Alternatively install the attached VSIX and verify its SHA-256 checksum. Run **Developer: Reload Window** when ready to activate it. Install separately on each extension host. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.31 prerelease remains available. Disable automatic GitHub updates before a deliberate rollback. Versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
