# Roo Code 4.2.11 - Cordis preview 9

Extension version: **4.2.11**. Git tag: **v4.2.11-cordis-preview.9**. This is a GitHub prerelease, not a stable or marketplace release.

## Brave tool availability

Brave web and local search are no longer exposed to the model when the required API key is unset, empty, or whitespace-only. This applies to ordinary registration and the restricted all-tools mode. Previously an unset value was mistaken for a tool with no credential requirement.

Both execution handlers trim configured keys and reject blank keys before approval or network use, protecting calls from stale tool lists. The settings UI applies the same blank-key check. Explicit disable settings, mode restrictions, and tool approvals remain unchanged. Context7 still works without a key, and saved credentials are not deleted.

## Focused workspace validation rules

This repository's rules now prioritize implementation and scoped checks rather than unconditional test coverage and ambiguous "all tests pass" requirements. Valid results can be reused. Rerunning failed checks or checks affected by a correction remains required when needed. Mandatory CI and commit hooks are not bypassed, and package scripts are unchanged.

These are repository workspace instructions, not global settings installed into other projects by this VSIX. Other workspaces may still contain their own unconditional validation rules.

## Validation and limits

26 focused backend tests and nine UI tests passed. Coverage includes missing/empty/whitespace keys, both registration modes, trimmed-key execution, approval denial, explicit disabling, and unchanged Context7 keyless use. One new test initially assumed an allowed-name list existed in ordinary registration mode; after correcting that test-only assumption, the affected suite passed. Targeted lint passed. No live Brave requests were made, so the presence check does not establish that a configured key is valid with Brave.

The separately reported global GitHub-token propagation and provider-only model-cache identity issues are not fixed by this release. Cordis runtime preview remains off by default.

## Install and rollback

Install **roo-cline-4.2.11.vsix**, verify the accompanying SHA-256 checksum, and run **Developer: Reload Window**. Start a new task if an older conversation retains a previous tool list. The extension ID is unchanged.

The previous 4.2.10 prerelease remains available for rollback, but retains the Brave credential-gating defect. Rollback does not undo completed task actions.
