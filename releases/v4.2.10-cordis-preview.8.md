# Roo Code 4.2.10 - Cordis preview 8

Extension version: **4.2.10**. Git tag: **v4.2.10-cordis-preview.8**. This is a GitHub prerelease, not a stable or marketplace release.

## Checkpoint exclusions for environments and caches

Checkpoints now exclude these disposable directories at the workspace root and inside nested projects, even without workspace ignore rules:

- Python: `.venv` (including uv's default project environment), `.virtualenv`, `.tox`, `.nox`, and `__pypackages__`.
- Python tooling: `.mypy_cache`, `.ruff_cache`, `.hypothesis`, `.pytype`, and `.ipynb_checkpoints`.
- Workspace-local caches: `.cache` (including uv and Hugging Face subdirectories) and `.uv-cache`.
- JavaScript tooling: `.npm`, `.pnpm-store`, `.yarn/cache`, `.yarn/unplugged`, `.turbo`, `.svelte-kit`, and `.angular/cache`.

uv's default user cache is normally outside the workspace and therefore outside its checkpoint worktree. Custom environment/cache paths with other names still need workspace Git ignore rules. Roo does not inspect or modify uv configuration or the user cache.

NumPy arrays, pickle/joblib data, TFRecord datasets, and TensorBoard event files are also excluded. Existing model-weight exclusions and the 10 MiB per-file limit remain.

## Preserve dependency definitions

Recognized dependency lockfiles, including `uv.lock`, `poetry.lock`, `pdm.lock`, `Pipfile.lock`, `yarn.lock`, `Cargo.lock`, `composer.lock`, `Gemfile.lock`, and `bun.lock`, are no longer omitted solely by the generic lock-file rule. Workspace Git ignore rules, LFS exclusions, and the size limit still apply. Manifest/configuration files remain eligible.

Generic `models` and `artifacts` directories are not blanket-excluded, since they can hold source and configuration. Exclude additional generated directories in workspace Git ignore rules as needed. Files within excluded environments/caches are not re-included by dependency lockfile exceptions.

## Existing disk usage and restore safety

The exclusions apply to initial and later staging, including existing checkpoint repositories. Previously indexed excluded files are untracked without deleting workspace copies. Restoring old snapshots that contain newly protected files is blocked to avoid overwriting those files.

**This update does not delete, prune, or shrink existing checkpoint history.** Separate repositories per task remain, and there is no aggregate history quota. It does not relocate model directories or compare duplicate models. Existing disk pressure needs a separate, explicitly approved cleanup/migration plan.

## Validation

All 62 checkpoint tests passed across three suites, including real temporary Git repositories. Coverage includes nested directory exclusions, uv definitions, initial/later staging without Git ignore rules, legacy untracking, restore preservation, and workspace-ignore/LFS precedence. An initial run of the older suite failed on a root-owned temporary fixture directory; rerunning that suite with a fresh user-owned temporary root passed. Targeted lint passed. No user checkpoint history or model data was touched.

## Install and rollback

Install **roo-cline-4.2.10.vsix**, verify the accompanying SHA-256 checksum, and run **Developer: Reload Window** on the affected extension host. Installing in code-server does not update a separate Remote SSH VS Code Server automatically.

The previous 4.2.9 prerelease remains available, but rollback removes these new exclusions. It cannot undo completed actions or reclaim existing history. Cordis runtime preview remains off by default.
