# Roo Code 4.2.59 - Cordis preview 55

Extension version: **4.2.59**. Git tag: **v4.2.59-cordis-preview.55**. Experimental GitHub prerelease, not a stable or marketplace release.

## Viewing a parent no longer breaks the child's return

Opening a parent task for inspection cleared its `awaitingChildId` before the user answered the resume prompt. The child's return was then rejected because the parent no longer looked like a pending delegation.

The return path now accepts two persisted states: the ordinary pending-return state, and a parent that was opened for inspection without being resumed.

- Recovery runs only when it is provable. Both saved histories must still end at the exact unanswered delegation to this child: the parent is active with no `awaitingChildId`, the last child link and the delegated target both equal the child, the child is not already marked completed by that child, the child is active with no `awaitingChildId`, the child creation message carries the matching subtask ID and is answered, its prompt equals the child task, and the last API message is a single `new_task` tool call with the same message.
- If any condition fails, the return is refused with a clear message that names the missing or changed link. No history is rewritten.
- When recovery succeeds, the parent is restored to status `delegated` with `awaitingChildId` set before either history is written. An interrupted delivery can therefore retry through the ordinary pending-return path.

## Regression coverage

A new unit spec covers the recovery guard, and the existing delegation close/reopen and history resume specs cover both accepted states and the refusal path. The 65 focused tests across these three specs pass on this source commit, and backend TypeScript checking passes. Those results were produced during the fix work and were not re-run for this release.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads. An editor that still reports an older version after a successful install has not reloaded.

## Validation and limits

Release gates cover packaging, VSIX ZIP CRC, manifest identity and version, both worker bundles, retained feature markers, absence of unfinished provider-connection markers, the presence of the recovery guard and its refusal message in the built bundle, source-to-commit hashes, asset SHA-256, GitHub server digest and size, and installed-file byte identity. These gates are not a full test suite.

A live return after viewing and resuming a parent was not exercised here. Extension activation, live browser behavior, macOS install and end-to-end user workflows remain unverified.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Rolling back does not convert snapshots. Preserve task storage before downgrading, and disable automatic updates before a deliberate rollback.

Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery. Avoid navigation while saving history edits.

This change adds a read-only verification step and can restore only the parent's delegation fields. Existing stored tasks are not migrated or rewritten by the release, and no task data was read during the release operation. Unfinished provider-connection checks and unrelated local editor, UI, Tetris, archive and research changes are excluded.

## Installation

Verify the attached VSIX against its SHA-256 file. Install separately on each extension host. This release operation installs only on the current Linux code-server host, without reloading the editor or activating the new extension. It does not install on a Mac. The companion ZIP is optional, unchanged since 4.2.51, and requires separate manual Chrome installation.
