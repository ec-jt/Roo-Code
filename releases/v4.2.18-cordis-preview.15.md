# Roo Code 4.2.18 - Cordis preview 15

Extension version: **4.2.18**. Git tag: **v4.2.18-cordis-preview.15**. Experimental GitHub prerelease, not a stable or marketplace release.

## Project memory MVP

- Add **Settings > Memory**, with project memory disabled until explicit opt-in. Changes in this panel apply immediately, separately from the general Settings Save button.
- Project memory is local to the extension host and shared across linked worktrees of the same local repository. Independent clones remain separate. No automatic sync or Claude-memory import occurs.
- Store bounded Markdown topic files and a derived index outside workspace checkpoints. Support user, feedback, project, and reference topics, with revision checks, atomic writes, unsafe-file rejection, and best-effort secret detection.
- Add a memory browser with scope selection, search, create/edit, open Markdown, forget-topic, and forget-all controls. Personal mutations require explicit confirmation of the proposed content and cross-project scope.
- After project opt-in, the memory tool can maintain project notes without enabling general all-actions approval. Mandatory tool approvals, mode restrictions, workspace trust, and storage access checks remain applicable.
- Recall a bounded metadata index at task boundaries and read topic bodies on demand. Prepared model-operation replay retains its original context rather than loading fresh memory.
- Disabling stops fresh automatic recall and model writes but keeps files. Forgetting does not erase old conversations, snapshots, backups, or provider-held inputs. Start a new task for a clean context.

Recalled memories are sent to the selected model provider. Memory is fallible context, never permission for commands or other actions. Import, advanced tidy tools, semantic retrieval, and automatic personal-memory learning remain deferred. New UI strings use English fallback.

## Validation and limits

Focused implementation checks passed: 74 tool/approval/recall tests, 69 storage/controller/task tests, and two memory-browser component tests. The 21 storage tests included in those runs also passed after final validation cleanup. Backend and webview type checks and scoped lint passed during implementation.

No live-editor visual test or real-model multi-session smoke test was performed. Source provenance records task IDs, not full source-file lineage. Recall scans within bounded limits rather than using a persistent retrieval cache. Existing transcripts can retain previously recalled text after disablement or forgetting.

## Known issues carried forward

The four findings documented in preview 14 are **not fixed**:

- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.** This is separate from the new memory feature.
- Manual shell execution in a Roo-owned terminal can be misattributed to a pending Roo command. Avoid mixing manual work into Roo terminals when using Stop command.
- A named-pipe managed-environment manifest can block preparation or checkpoint compatibility inspection.
- A future interpreter path supplied to pip can prevent recognition of compatible musllinux wheels.

Cordis runtime preview remains off by default. Installing this package does not opt any project into memory or change existing approval settings.

## Install and rollback

Install **roo-cline-4.2.18.vsix**, verify its SHA-256 checksum, then run **Developer: Reload Window** when ready to interrupt the current extension session. Open **Settings > Memory** to opt in.

The previous 4.2.17 prerelease remains available for rollback. Rolling back does not delete externally stored memories or experimental environments and cannot undo completed actions. Version 4.2.15 predates the background-activity and managed-environment features.
