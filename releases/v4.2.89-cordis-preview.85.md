# Roo Code 4.2.89 - Cordis preview 85

Extension version: **4.2.89**. Git tag: **v4.2.89-cordis-preview.85**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release fixes a defect found in the 4.2.86, 4.2.87 and 4.2.88 live checks. An automatic context summary could leave the context larger than before. The next request was then sent over the context window.

## Context stays within the window after a summary

In the 4.2.88 live check, a task on a profile with a 64,000-token context window override condensed three times. The third condense row showed **75,923 → 128,376 tokens**. The next request used 139,088 input tokens. The same pattern appeared in 4.2.86 (76,418 → 128,440) and 4.2.87 (76,751 → 76,874).

**Cause.** Overflow recovery summarizes the older history. It keeps the newest tool call and its result verbatim after the summary, so no tool result loses its call. Pruning of large tool results ran only on the history before that kept tail. In the live task, the kept tail held a continuation read of `Task.ts` (lines 2001 to 6837, about 220,000 characters). The summary replaced only a small part of the context. The huge newest result stayed whole, and recovery had no check after the summary. The request was sent anyway. It succeeded only because the real model window is 1M.

The "before" value on the row was also misleading. It is the last request's token usage, which does not include the tool result added since that request. So the row showed growth that had happened before the condense.

**Fix.** After a summary, if the estimated prompt is still over the budget for the effective window (including a context window override):

1. The tool results in the kept tail are shortened like older results. The head and tail are kept, and the full text is saved in the task folder (`read_command_output`). The tool call and result pair stays intact.
2. Images in the kept tail are offloaded to files, when offload is on.
3. If the prompt is still over the input limit, recovery stops with an error. History is not changed, and no request is sent.

Each step runs at most once. There is no loop, and recovery still runs at most once per request.

**Reporting.** The condense row now shows:

- **before:** the measured pre-recovery prompt (system prompt, effective history and tools), when that is larger than the last request's usage;
- **after:** the estimate after the kept tail was reduced;
- **pruned count:** includes the shortened tail results.

**Unchanged.**

- Nothing changes when no overflow occurs.
- When the summary already fits, the kept tail is not changed, so prompt-cache behaviour is the same as 4.2.88.
- Prune-only recovery (`context_pruned` rows) and the truncation fallback for a failed summary are unchanged.

## Changes

- `src/core/context-management/index.ts`: `manageContext` reduces the kept tail after a summary when the estimate is over budget, refuses a result over the input limit, and reports the measured pre-recovery size.
- `src/core/context-management/__tests__/context-management.spec.ts`:
    - new tests for the r88 shape (one huge newest tool result after a summary on a 64k window);
    - a summary that does not shrink the context and cannot be reduced further;
    - an unchanged kept tail when the summary fits;
    - two existing tests now use a window large enough for their summary.

## Validation

Not verified yet: a live task on a 64k override profile that reads a large file just before a condense.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until you reload the window.

## Storage and rollback

This release adds no settings and no storage formats. A shortened tail result is saved as a task artifact in the same way as other pruned results.

If you roll back to 4.2.88, a summary can again leave a huge newest tool result in the context and send a request over the window.
