# Roo Code 4.2.90 - Cordis preview 86

Extension version: **4.2.90**. Git tag: **v4.2.90-cordis-preview.86**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

> **Correction:** the 4.2.90 commit message says "for all models". Only profiles with a context window override changed. Models without an override still recover only after a provider rejection (C-6).

This release fixes defect D1 from the 4.2.89 live check. On a profile with a context window override, a request could still be sent over the overridden window. The check before sending used a stale token count.

## The check before sending uses an estimate of the pending request

In the 4.2.89 live check, a task on a profile with a 64,000-token context window override sent two requests above 64k without any recovery first:

- req2: 122,934 input tokens, after two 2,000-line reads.
- req5: 74,042 input tokens, after a 61,536-character read.

Both succeeded only because the real model window is 1M.

**Cause.** For override profiles, Roo checks the size before each request and runs the normal overflow recovery once if the request would not fit. The check used the token usage of the **last** request. That value does not include the tool results added since then. A large read therefore passed the check, and the request was sent over the window.

**Fix.** The check now estimates the request that is about to be sent:

- **Normal case (cheap).** Last request's usage, plus a local token count of only the user messages (tool results) added to the history since that request. The assistant reply is already part of the last usage.
- **Fallback (full count).** When the history changed in a different way since the last request (first request, resume, condense, edit, or a request that recorded no usage), Roo counts the whole prompt locally: system prompt, effective history and tools. This is the same count that overflow recovery uses.
- If counting fails, the last usage is used, as before.

The limit is unchanged: the effective (overridden) context window minus the reserved output tokens. Recovery still runs at most once per request, then the request is sent.

**Unchanged.**

- Models without a context window override still reduce context only after the provider rejects a request for size (constraint C-6). This release does not add proactive recovery for them.
- When automatic context management is off, no proactive recovery runs.
- When the estimate fits, history is not changed, so prompt-cache reuse is the same as 4.2.89.

## Wording

The pruned-results note on context rows said "Shortened N large **older** tool results". Since 4.2.89 the newest result can also be shortened. The note now says "Shortened N large tool results. The full text is saved in the task folder." All 18 locales are updated.

## Changes

- `src/core/task/Task.ts`:
    - new `estimatePendingRequestTokens`, used by the proactive check for override profiles;
    - a history mark is recorded when a request is dispatched, so that the next estimate counts only the new messages.
- `src/core/task/__tests__/task-model-dispatch.spec.ts`: new tests for:
    - the r89 req2 shape (39k usage plus a 2,000-line read on a 64k override);
    - at most one recovery per request;
    - no change under the limit;
    - automatic context management off;
    - no proactive recovery without an override;
    - the history mark.
- `webview-ui/src/i18n/locales/*/chat.json`: `prune.description` and `prune.description_other`.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until you reload the window.

## Storage and rollback

This release adds no settings and no storage formats.

If you roll back to 4.2.89, override profiles can again send a request over the overridden window after a large tool result.
