# Roo Code 4.2.44 - Cordis preview 40

Extension version: **4.2.44**. Git tag: **v4.2.44-cordis-preview.40**. Experimental GitHub prerelease, not a stable or marketplace release.

## Overflow recovery for long tool chains

- When the single summary attempt exceeds the provider context limit or returns an empty summary, the existing **Allow truncation fallback** preference controls whether Roo may exclude unsummarized history. Disabled fallback still leaves history unchanged.
- Prefer complete older exchanges. If none are available, or excluding them still cannot fit, allow exclusion of older completed tool-call/result groups within retained turns. Keep parallel calls and their results together.
- Preserve the root/current summary, retained-turn user input and recognized feedback, interactive tool groups, and the newest complete tool interaction. Preserve non-environment user text and non-text tool results conservatively. Ambiguous or incomplete tool chains are not truncated.
- Tag stored messages rather than deleting them. A disclosure marker tells the model that excluded content was not summarized and is no longer visible. This is lossy fallback, not lossless compaction.
- If protected content still cannot fit, leave history unchanged rather than applying insufficient partial exclusions. Preserve the original compaction error and diagnostics alongside the fallback refusal. Repeating truncation on unchanged history cannot resolve a refusal; use a larger-context model or a new task with a reviewed handoff.

No extra summary attempt or chat retry is added. Automatic recovery still requires an explicit provider context rejection before assistant output starts, and permits at most one chat retry. Manual compaction does not silently truncate.

## Content-free compaction diagnostics

Summary context-limit and empty-summary failures now include stored-prefix, effective-history, and request-message counts; post-conversion text character counts; image/non-text block counts; advertised model context window; available provider-reported input/output usage; HTTP status; and allowlisted error codes. Arbitrary provider strings, response bodies, and conversation content are omitted from these diagnostics. Generic provider-error handling is unchanged.

Character counts are UTF-16 code units, not token counts or wire sizes. Image payload sizes and provider-added overhead are not measured. The advertised window is model metadata, not a confirmed provider limit. Rejected requests often have no usage. No token-counting API request is added for diagnostics. Full history exports can still contain private conversation data and must be reviewed before sharing.

## Validation and limits

The latest focused run passed 36 tests across summary-request and overflow-truncation regressions. An earlier run passed 45 tests across overflow truncation and context management before diagnostics were added. These results are reused rather than represented as a new full-suite run. Release lint, current-code TypeScript checking, packaging, archive integrity, checksums, installed-version checks, and uploaded asset verification are required before publication.

The package is built from an isolated checkout containing only the scoped context-recovery changes and release metadata. Uncommitted provider-connection-check and message-editor work is excluded. No live provider request or exact affected task history was used to validate recovery. This release does not guarantee that provider compaction failures are resolved or that arbitrary protected history can fit a smaller context window.

Previous Windows file-sync, updater, LiteLLM discovery, terminal-output, ripgrep, Settings/MCP, LM Studio, diagnostic-export, and new-task selection changes remain included. The Windows file-sync change is present, but the earlier snapshot-error notification is not a verified fix: dispatch may already be closed when the notification is attempted, so it may never become visible. No Windows host was used. Authenticated LM Studio retains its live-test limitations. Claude and DeepSeek thinking-model switching through LiteLLM remains incomplete and unverified.

## Known unresolved findings

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- The separate bounded large/history command-output preview can still show the beginning instead of following the tail.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Previously reported historical-action and LiteLLM fixture failures and a Bedrock context-window expectation mismatch remain outside this change. This is not a claim that the entire repository test suite passes. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. The Mac grey-panel incident remains unverified.

## Install and rollback

Install the attached VSIX and verify its SHA-256 checksum, or use **Settings > About > GitHub release updates**. If an older updater reports a temporary-directory error, install the VSIX manually once. Install separately on each extension host. Finish or stop work before reloading; installation does not automatically reload the window. This release operation does not reload or activate the installed extension. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.43 prerelease remains available. Disable automatic updates before deliberate rollback. Versions below 4.2.34 do not support the LM Studio token field; versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
