# Roo Code 4.2.48 - Cordis preview 44

Extension version: **4.2.48**. Git tag: **v4.2.48-cordis-preview.44**. Experimental GitHub prerelease, not a stable or marketplace release.

## Same-mode subtask model selection

Same-mode delegation now gives the child a deep copy of the parent's active provider configuration, including its runtime profile ID and unsaved overrides. A workspace provider lock uses the same inheritance path. Explicit initial mode and profile context prevents global UI defaults or a queued next-request profile change from selecting the child's starting configuration.

Different-mode delegation without a workspace lock still selects the saved profile associated with the requested mode. A profile-selection failure is propagated and prevents the child from starting. The parent has already been disposed at that point and must be reopened. Parent history records the parent's actual mode and profile name.

Child startup is deferred until delegation metadata has been saved. Organization allowlist checks still apply to the inherited configuration. Existing approval-revision fences remain in place.

This is not a fix for all model switching. Returning to or rehydrating a parent still loads its saved profile by name; unsaved overrides are not persisted across rehydration. Live extension-host delegation and a complete child-to-parent return were not validated.

The compatible-provider reasoning-stream fix from 4.2.47 is included. Reasoning-only output is still not a final answer, and the cause of the previously reported empty response is not established. No live provider, tunnel, API-key, server, or private-infrastructure checks were performed.

## Validation and limits

The parent task reported 79 passing provider-delegation and delegation-depth tests, four passing sticky-profile race tests, a passing final backend TypeScript check, and a passing scoped diff check. Those results are reused unless a release change affects behavior. Release gates include isolated lint, the release-local formatting and lint hook, packaging, archive integrity, source-to-commit identity, checksums, uploaded-asset verification, and installed-file verification. These are scoped checks, not a full-suite or live-provider pass.

Task-state acceptance checks are **user-attested only**. No executable acceptance test runner was implemented. The earlier claim that such a runner is off by default was misleading; this release does not add one.

The Windows file-sync change from an earlier release is present, but the notification after dispatch is already closed remains unverified and may never appear. No Windows host was used. The Mac grey-panel incident remains unverified. Directory-listing runtime behavior on Windows, macOS, Electron, and remote filesystems remains untested.

## Known unresolved findings carried forward

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- The separate bounded large/history command-output preview can still show the beginning instead of following the tail.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Previously reported historical-action and LiteLLM fixture failures and a Bedrock context-window expectation mismatch remain outside this change. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. Unfinished provider-connection checks and unrelated local UI changes are not included in this release.

## Install and rollback

Install the attached VSIX and verify its SHA-256 checksum, or use **Settings > About > GitHub release updates**. If an older updater reports a temporary-directory error, install the VSIX manually once. Install separately on each extension host. This release operation targets the current Linux code-server host, not a Mac. It does not reload or activate the installed extension. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.47 prerelease remains available. Disable automatic updates before deliberate rollback. Older versions do not provide the task-state workflow; preserve task storage before downgrading. Versions below 4.2.34 do not support the LM Studio token field; versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
