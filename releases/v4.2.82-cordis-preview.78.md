# Roo Code 4.2.82 - Cordis preview 78

Extension version: **4.2.82**. Git tag: **v4.2.82-cordis-preview.78**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

## Fixed: a chat message sent while a task is running could be lost

A message typed while a task was running could disappear with no error. The input box was cleared, but the model never received the text.

The window opened when the last chat row was an auto-approved tool card (for example "Updated the to-do list") and the task then did slow work that added no rows, such as the first checkpoint of an edit.

- The chat view treated the auto-approved tool card as still waiting for approval. It sent the text as a direct reply instead of adding it to the message queue.
- The extension stored the reply although no question was waiting. The next tool approval reset the stored reply, so the text was discarded.

This release fixes both sides:

- **Extension.** The task now records when a question is actually waiting for a reply. A typed message that arrives when nothing is waiting goes into the message queue. The next approval or question delivers it as user feedback, the same path that queued messages already use.
- **Extension.** If a new chat row appeared while attached images were being prepared, a typed message was dropped. It is now queued instead.
- **Chat view.** For tool, command, MCP, browser and computer-use approvals that are already answered (`isAnswered`), the chat view treats the task as busy. Typed text goes to the message queue and appears in the queued-message list.

Button replies (Approve, Reject and similar) and replies to a question that is really waiting are unchanged.

## Changes

- `src/core/task/Task.ts`:
    - `askWithExistingApproval()` now counts complete asks that wait for a reply (`pendingAskCount`, read through `isAskPending`). The previous body moved to `askAndWait()`.
    - `handleWebviewAskResponse()` queues `messageResponse` text and images when no ask is waiting.
    - New `queueUserMessage()` helper.
    - `processQueuedMessages()` leaves the queue in place when no ask is waiting, so queued messages keep their order.
- `src/core/webview/webviewMessageHandler.ts`: the `askResponse` handler queues a `messageResponse` with content when a new row arrived during image resolution, instead of discarding it.
- `webview-ui/src/components/chat/ChatView.tsx`: answered `tool`, `command`, `use_mcp_server`, `browser_action_launch` and `computer_action` asks set `sendingDisabled`, clear `clineAsk` and disable the buttons.
- Tests:
    - `src/core/task/__tests__/task-queue-no-pending-ask.spec.ts` (new, 6 tests): a message with no waiting ask is queued; the next auto-approved or answered tool ask returns it as feedback; a waiting ask still receives the reply directly; button replies and empty text are not queued; partial asks do not count as waiting.
    - `webview-ui/src/components/chat/__tests__/ChatView.spec.tsx`: two new tests (an answered tool ask posts `queueMessage`; an unanswered tool ask still posts `askResponse`).

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until you reload the window.

## Storage and rollback

This release adds no settings and changes no stored data. If you roll back, a message sent in the window described above can be lost again.
