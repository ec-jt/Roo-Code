# Roo Code 4.2.83 - Cordis preview 79

Extension version: **4.2.83**. Git tag: **v4.2.83-cordis-preview.79**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

## Cordis is now on by default for all providers

New tasks now use the Cordis profile on every provider. Before this release, the Cordis profile was opt-in.

- **New tasks only.** A new root task takes the Cordis profile when the setting **Settings > Experimental > Cordis runtime preview** is on. The setting is now on by default. Subtasks inherit the profile of their parent.
- **Existing tasks keep their profile.** A task created as a modes task stays a modes task when you reopen it, and a Cordis task stays a Cordis task. No stored task data changes.
- **If you turned the setting off, it stays off.** A stored "off" value is kept. Only a setting that was never saved now counts as on. See "Who sees the change" below.

The decision and its evidence are in [ADR-2026-11-19-keep-cordis-profile-widen-experiment](../docs/architecture/decisions/accepted/ADR-2026-11-19-keep-cordis-profile-widen-experiment.md).

## What changes for users

In a Cordis task:

- **The mode is locked after the first request.** The task keeps the mode it started in. The `switch_mode` tool is not available, so the model cannot move between Architect, Code and other modes during the task.
- **All tool groups are available in every mode.** Read, edit, browser, command and MCP tools are available without the file restrictions of the mode. For example, Architect mode can edit any file and run commands. The role and instructions of the mode stay the same.
- **`/plan` gives a plan review.** The model writes a plan and calls `exit_plan`. You approve the plan or send it back with Keep planning before any work starts.
- **Drift is raised as an amendment.** When the model finds during the task that the plan conflicts with a constraint or a decision, it proposes a plan amendment as a second plan review, instead of a follow-up question.

### Only on Anthropic

The dispatch runtime (request admission) stays Anthropic-only. On Anthropic, a Cordis task also uses:

- the preview request admission;
- the `cordisTextOnlyTurnPolicy` setting (default `retryThenPause`) for replies without a tool call.

On other providers (for example OpenAI, OpenRouter, Bedrock, Vertex, Gemini), a Cordis task has no dispatch runtime. Requests go out as in a modes task. A reply without a tool call gets the normal "use a tool" reminder, and `cordisTextOnlyTurnPolicy` has no effect.

## How to turn it off

1. Open **Settings > Experimental**.
2. Clear **Cordis runtime preview**.
3. Click **Save**.

New tasks then use the modes profile. Tasks that already exist keep their profile.

## Who sees the change

- If you never saved the Experimental settings, the setting is now on and new tasks use Cordis.
- If your stored settings already contain the setting as off, it stays off. Earlier versions wrote the full set of experiment defaults (with the Cordis preview off) whenever you saved any setting, so a stored "off" does not always mean that you turned it off yourself. To use Cordis in that case, turn the setting on in **Settings > Experimental**.

## Evidence

In evaluation S2 (same feature request, same model, same drift message), the Cordis profile was compared with the modes profile over 4 samples on `claude-opus-5-5`:

- 27% fewer requests (127 vs 173);
- 44% fewer input tokens (12.0M vs 21.2M);
- 35% lower cost ($6.43 vs $9.94).

Cordis was cheaper in every sample, and drift was reported in every run where the drift message arrived. There are no samples on other providers yet. On those providers, the Cordis profile runs without the dispatch runtime, a combination that no live evaluation run has used.

## Changes

- `src/shared/experiments.ts`: the default of `cordisRuntimePreview` is now `true`. New helper `isCordisRuntimePreviewEnabled()` returns the stored value when it is a boolean, else the default.
- `src/core/task/cordis-profile.ts`: `resolveTaskProfile()` uses the effective value. A stored or parent profile still wins.
- `src/api/preview-runtime.ts`: `selectPreviewRuntime()` uses the effective value and still returns a runtime only for `anthropic`.
- `src/core/task/Task.ts`: the live-disable listener uses the effective value.
- `src/core/webview/webviewMessageHandler.ts`: the `/plan` overlay check for new tasks uses the effective value, so `/plan` works when the key is absent.
- `webview-ui/src/components/settings/ExperimentalSettings.tsx`: experiment toggles fall back to the default, so the Cordis toggle shows on when the key is absent.
- `webview-ui/src/i18n/locales/*/settings.json`: new description of the Cordis runtime preview toggle in all 18 locales.
- Tests:
    - `src/api/__tests__/preview-runtime.spec.ts`: absent means on, explicit false means off, no runtime for non-Anthropic providers.
    - `src/core/task/__tests__/cordis-profile.spec.ts`: absent experiments give `cordis`; explicit false gives `modes`; stored and parent profiles still win.
    - `src/core/task/__tests__/task-model-dispatch.spec.ts`: a Cordis task on `openai-native` has no dispatch runtime, gets `exit_plan` and no `switch_mode`, and a reply without a tool call gets the "use a tool" reminder, not `resume_task`. Existing tests now state the default explicitly.
    - `src/core/webview/__tests__/webviewMessageHandler.spec.ts`: `/plan` creates a task with the overlay when the key is absent.
    - `src/shared/__tests__/experiments.spec.ts` and `webview-ui/src/components/settings/__tests__/SettingsView.spec.tsx`: the default is on.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until you reload the window.

## Storage and rollback

This release adds no settings and changes no stored data. It only changes the meaning of a missing `cordisRuntimePreview` key from off to on. If you roll back, a missing key means off again. Tasks created as Cordis tasks keep their stored profile after a rollback.
