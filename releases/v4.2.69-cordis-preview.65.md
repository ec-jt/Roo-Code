# Roo Code 4.2.69 - Cordis preview 65

Extension version: **4.2.69**. Git tag: **v4.2.69-cordis-preview.65**. Experimental GitHub prerelease, not a stable or marketplace release.

## Repeat-call reminder (all tasks)

When the model calls the same tool with identical arguments several times in a row, Roo now adds one line to the tool result at the 3rd, 5th and 8th call:

> Note: this is call 3 of read_file with identical arguments. Check the previous result and change approach, or finish.

- Calls are never blocked; the tool runs as usual.
- Argument order does not matter (keys are compared sorted). MCP tools count per server, tool and arguments.
- `update_todo_list`, `task_state`, `ask_followup_question` and `attempt_completion` neither count nor reset the chain.
- A new message from you resets the count.

The note is part of the newest tool result only, so it does not change earlier messages or the prompt cache.

## Architecture docs and arc42 tooling

- `docs/architecture/` section files start with numbered arc42 headings (`# 2. Architecture constraints`, `# 10. Quality requirements`, `# 11. Risks and technical debt`). Quality goals carry a Q42 tag line (`Quality property: #reliable`), and the index has a section 1.2 quality-goal table. The [arc42-toolkit](https://github.com/MSiccDev/arc42-toolkit) linter now detects the sections and reports no issues.
- Fix: `Paths:` lines in architecture records accept Markdown escapes (`src/\*\*`), which the repository formatter adds on commit. Before this fix, such records did not match by path in **Full** architecture context mode.

## Validation

Focused tests pass: the repeat-call spec (thresholds 3/5/8, key order, reset on a different call, excluded tools transparent, reset on a user message), presenter specs, architecture-docs and architecture-context specs (including the escaped-Paths case). TypeScript checks for types, extension and webview pass. Release gates cover lint, packaging, VSIX ZIP integrity, manifest version, both worker bundles and asset digests.

Pre-existing failures are unchanged from 4.2.68 (4 presenter policy-boundary tests, 25 tests in `src/core/task/__tests__`, and the others listed in 4.2.68).

Whether models change approach after the note was not exercised with a live model.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Builds before 4.2.62 show prune-only recovery rows as unknown messages. Builds before 4.2.68 show a plan review as an unknown message. This release does not migrate or rewrite stored tasks, and no existing task data was read during the release operation.
