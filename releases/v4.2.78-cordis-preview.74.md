# Roo Code 4.2.78 - Cordis preview 74

Extension version: **4.2.78**. Git tag: **v4.2.78-cordis-preview.74**. Experimental GitHub prerelease, not a stable or marketplace release.

## Faster desktop control: batched actions, submit, optional screenshots

Desktop control now needs fewer model turns. In a long task, each `computer_action` call spent about 1.2 s in the tool and about 18 s in the model turn. Saving turns gives the largest gain, so the tool can now do more per call.

- **Batched actions.** A new `actions` parameter takes 1 to 10 steps. Roo checks every step, asks for approval once, runs the steps in order, and returns one screenshot at the end.
- **`submit` on type.** `"submit": true` presses Enter after the text. This replaces a separate `key` call.
- **`screenshot: false`.** A state-changing action or a batch can skip the settle wait and the screenshot. The result is then a short text with no image.
- **Shorter settle wait.** The wait before the screenshot after a state-changing action is now 200 ms. It was 400 ms.

The tool description tells the model to batch predictable steps (for example focus, click, type with submit) and to take a screenshot only when it needs to see the result.

### Batch call shape

```json
{
	"actions": [
		{ "action": "focus_window", "window": "Notes" },
		{ "action": "click", "coordinate": "400,300" },
		{ "action": "type", "text": "Buy milk", "submit": true }
	],
	"screenshot": true
}
```

- Allowed steps: `click`, `double_click`, `right_click`, `move`, `drag`, `type`, `key`, `scroll`, `focus_window`, `wait`, `window_type`, `click_element`.
- Refused as steps: `screenshot`, `list_windows`, `list_elements`, `window_screenshot`.
- `action` and `actions` cannot be given together.
- Every step is checked before approval: required parameters, `submit` rules, the app allowlist (a `focus_window` step changes the active window for later steps), and background mode. The user is never asked to approve an invalid batch.
- The approval lists every step, with the full text of each `type` step.
- Auto-approval is unchanged. A batch uses the `computer_action` ask and still needs the `alwaysAllowComputerUse` opt-in.
- During the run, each step that uses the shared mouse and keyboard still waits until the user pauses. Before each step, Roo checks whether the task was stopped (Stop button or **Stop Desktop Control**) and checks the allowlist again. There is no settle wait between steps, only a fixed 50 ms gap.
- If step k fails, the batch stops. The result names step k, says how many steps finished, lists them, and includes a screenshot when one can be taken.
- The tool result lists the steps that ran, with the screen coordinates that were used.

### Limits

- `submit` is not available for `window_type`. Background typing sets text through Accessibility and cannot press Enter. Roo refuses the call before approval and says to use `click_element` on the send button.
- `screenshot: false` is refused on read-only actions (`screenshot`, `list_windows`, `wait`, `window_screenshot`, `list_elements`).

## Changes

- `packages/types/src/computer-use.ts`: new `batchComputerActions`, `isBatchComputerAction()`, `MAX_COMPUTER_ACTION_STEPS` (10), `ComputerActionToolParams` (`actions`, `screenshot`), and `submit` on `ComputerActionParams`. `ClineSayComputerAction` has optional `action`, and new `steps`, `screenshot`, and `submit` fields.
- `src/services/desktop/DesktopSession.ts`: `DEFAULT_SETTLE_MS` is 200. New `BATCH_STEP_GAP_MS` (50). `execute(params, { screenshot })` can skip the settle wait and the screenshot. New `executeBatch(steps, { screenshot, shouldAbort, beforeStep })`. The input part of each action moved to a private `runStep()` that both paths use. `type` with `submit` presses Enter after the text (also after pasted text). `window_type` with `submit` throws.
- `src/core/tools/ComputerActionTool.ts`: validates single calls and batches before approval. One approval per batch. Passes an abort check and an allowlist recheck to `executeBatch`. Formats batch results and text-only results. `handlePartial` shows the steps of a streamed batch once the array parses.
- `src/core/prompts/tools/native-tools/computer_action.ts`: new `actions`, `submit`, and `screenshot` properties. `action` is no longer required by the schema (the tool checks that exactly one of `action` and `actions` is given). The description has a new "Work fast" section.
- `src/core/assistant-message/NativeToolCallParser.ts`: passes `actions`, `submit`, and `screenshot` into `nativeArgs`, also when `action` is absent.
- `src/core/assistant-message/presentAssistantMessage.ts`: the tool description for a batch says `[computer_action batch]`.
- `src/shared/tools.ts`: new parameter names `actions`, `submit`, `screenshot`. `NativeToolArgs.computer_action` is now `ComputerActionToolParams`.
- `webview-ui/src/components/chat/ComputerActionRow.tsx`: shows a batch as a numbered list of steps, with the full typed text in the approval, "then press Enter" for `submit`, executed coordinates, and a note when no screenshot is taken.
- `webview-ui/src/i18n/locales/*/chat.json` (18 locales): new keys `computerAction.batchSteps`, `computerAction.submit`, `computerAction.noScreenshot`.
- `docs/computer-use.md`: documents batched actions, `submit`, `screenshot: false`, and the 200 ms settle wait.
- Tests: `computerActionTool.spec.ts`, `DesktopSession.spec.ts`, `NativeToolCallParser.computerAction.spec.ts`, `computer-use.spec.ts` (auto-approval), `computerScreenshotHistory.spec.ts`, `ComputerActionRow.spec.tsx`.

`src/core/task/computerScreenshotHistory.ts` is unchanged. It only selects results that contain an image, so text-only results from `screenshot: false` are skipped and do not count toward the 3 kept screenshots. A new test covers this.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback

This release adds no settings and makes no changes to stored tasks. Batch messages in stored conversations use the new `steps` payload. Earlier builds do not show these rows (they show nothing for a payload without `action`), but the tasks still open. Rolling back restores the 400 ms settle wait and removes `actions`, `submit`, and `screenshot` from the tool.
