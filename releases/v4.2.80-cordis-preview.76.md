# Roo Code 4.2.80 - Cordis preview 76

Extension version: **4.2.80**. Git tag: **v4.2.80-cordis-preview.76**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

## Fixed: tool calls after context compaction were rejected

After Roo compacted the context, it retried the request. If the reply had a tool call and no visible text, Roo stopped the task with "The retry after context compaction returned no response. Retry manually." and discarded the tool call.

Most providers send tool calls in pieces (`tool_call_partial` chunks). These include Anthropic, Anthropic on Vertex, Bedrock, OpenRouter, Gemini, LiteLLM and DeepSeek. The check that decides whether the retry produced a response only counted text and complete `tool_call` chunks. So a normal reply, with reasoning and then a tool call, failed this check.

This affected both kinds of recovery:

- recovery after the provider rejects a request as too long;
- the early compaction that 4.2.79 added for profiles with a context window override.

The bug has been in the code since 4.2.23. Release 4.2.79 made it frequent: with a 64k override on a model with a 1M window, Roo compacts much more often. In the evaluation runs S3-none, S3-prune and S3-both, every task stopped at its first compaction.

The check now also counts the first `tool_call_partial` chunk of a tool call (a chunk that has an `id` or a `name`). A retry that returns only reasoning, with no text and no tool call, still raises the error.

## Changes

- `src/core/task/Task.ts`: `attemptApiRequest()` now counts a `tool_call_partial` chunk with an `id` or `name` as a response.
- `src/core/task/__tests__/task-model-dispatch.spec.ts`: three new tests.
    1. A reply with only a tool call, after early compaction, is accepted.
    2. A reply with only a tool call, after a provider-rejected overflow, is accepted.
    3. A reply with only reasoning, after compaction, still raises "returned no response".

## Validation

- `cd src && npx vitest run core/task/__tests__/task-model-dispatch.spec.ts`: 89 passed.
- With the `Task.ts` change removed, the two tool-call tests fail. This confirms that the tests detect the bug.
- `cd src && npx tsc --noEmit -p .`: no errors.

Not verified yet: a live task that compacts and then makes a tool call. The S3 evaluation rerun will test this.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until you reload the window.

## Storage and rollback

This release adds no settings and makes no change to stored data. If you roll back to an earlier build, the bug returns.
