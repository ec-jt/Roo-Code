# Roo Code 4.2.38 - Cordis preview 35

Extension version: **4.2.38**. Git tag: **v4.2.38-cordis-preview.35**. Experimental GitHub prerelease, not a stable or marketplace release.

## Command output capture and visibility

- Recognize shell-integration output-start markers split across stream chunks. Previously, checking each chunk separately could miss the marker and discard subsequent output while the command ran.
- Search accumulated pre-output until the marker arrives, then release that buffer. Bound retained pre-output diagnostics to 64 KiB characters while waiting for the marker.
- Show a small recent-output preview in normal command cards without requiring expansion: up to six lines from the last 2,048 characters. Keep the existing expanded output control.
- Show an explicit no-captured-output message on empty cards and distinguish terminal output from API request statistics.

These changes do not replay commands, alter execution permissions, or reconstruct output already lost. The split-marker defect is covered by synthetic-stream regressions; it has not been confirmed as the cause of the user's particular incident. A silent command or unavailable shell integration can still produce no captured output. The separate large/history preview path remains limited as noted below.

## Validation and limits

73 focused tests passed: 43 terminal/activity tests and 30 command-card tests. Coverage includes every split point in both supported bell-terminated start markers, preserved output, compact recent previews, and empty-output messaging. Release lint, packaging, archive integrity, and checksum checks are required by the release procedure. No user commands were rerun and no live affected-host shell session was used to validate this fix.

Earlier ripgrep, Settings/MCP, LM Studio, diagnostic-export, and new-task model-selection fixes remain included. Ensure manually installed ripgrep is on the extension host's inherited PATH, not only an interactive shell's PATH. Authenticated LM Studio behavior remains mock-tested; legacy SDK operations can outlive the caller timeout. Claude and DeepSeek thinking-model switching through LiteLLM remains incomplete and unverified. Pinned replay and the experimental Anthropic-only mediated runtime retain their restrictions.

## Known unresolved findings

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- The separate bounded large/history command-output preview can still show the beginning instead of following the tail. The new recent preview applies to normal command cards.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

The pre-existing historical-action guard fixture failure remains outside this change. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. The Mac grey-panel incident remains unverified.

## Install and rollback

From 4.2.30 or later, use **Settings > About > GitHub release updates** after closing the loaded task. A stopped or completed task still counts as loaded: return to the empty New Task screen without deleting history. Alternatively install the attached VSIX and verify its SHA-256 checksum. Run **Developer: Reload Window** when ready to activate it. Install separately on each extension host. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.37 prerelease remains available. Disable automatic GitHub updates before a deliberate rollback. Versions below 4.2.34 do not support the LM Studio token field. Versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
