# Roo Code 4.2.77 - Cordis preview 73

Extension version: **4.2.77**. Git tag: **v4.2.77-cordis-preview.73**. Experimental GitHub prerelease, not a stable or marketplace release.

## Queued messages reach the model as user messages

The model now always receives a message you queue while auto-approve is on as a user message. Before this release, Roo attached that message to the next tool approval and put the text inside the tool result as `{"status":"approved","feedback":"..."}`. The model then saw your message mixed into tool output, for example inside a file it had read. It could not tell your instruction apart from file content, so it sometimes treated the instruction as possible prompt injection and ignored it.

This also applies to text you type when you approve or deny a tool.

The tool result now contains only a status line, for example `{"status":"approved","message":"The user approved this operation and sent a message. It follows this tool result."}`. Your text follows as a separate `<user_message>` block in the same user turn, after the tool result, with any attached images.

The regression came from commit `8de9337e6` (2026-01-20). That commit replaced the earlier `<user_message>` wording with bare JSON.

## Changes

- `src/core/prompts/responses.ts`: `toolApprovedWithFeedback()` and `toolDeniedWithFeedback()` return a status line only. New `userMessage()` wraps user text in `<user_message>`.
- `src/core/task/Task.ts`: new `pushUserFeedbackToUserContent(text, images)`. It pushes the user's text and images after the tool result.
- `src/core/assistant-message/presentAssistantMessage.ts`: the native-tool path and the MCP-tool path use the new helper for both approval and denial feedback. Feedback images now come after the tool result, not before it.
- `src/core/tools/ReadFileTool.ts`: the batch path and the single-file path use the new helper. The legacy path showed approval feedback in the chat but never sent it to the model. It now sends it.
- `webview-ui/turbo.json`: the webview build cache now counts `src/package.json` (and the nightly manifest) as an input. Before this change, a version bump could reuse a stale webview bundle, so the panel showed the previous version number.
- `docs/architecture/evaluation-2026-11-18.md`: the build under test is now set to 4.2.76. The workspace commit for the worktrees stays at `9deda9b58`.

## Validation

- Focused tests: 72 passed in 4 files (`readFileTool.spec.ts`, `presentAssistantMessage-images.spec.ts`, `ask-queued-message-drain.spec.ts`, `task-approval-port.spec.ts`).
  - The `readFileTool.spec.ts` mock still used the pre-January wording. It now matches the real output.
  - The approval and denial tests now check that the user's text is not in the tool result and is pushed after it.
  - Two new presenter tests check the order for a tool that is approved with feedback and for one that is denied with feedback.
- 4 tests in `task-approval-port.spec.ts` fail with and without this change. The cause is a missing `checkpointSave` mock in that spec. This release does not fix them.
- `tsc --noEmit` for `src`: no errors.

Not yet verified: a queued message in a live task reaches the model as a user message. Evaluation run S1-off will check this.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback

This release adds no settings and makes no changes to stored tasks. Stored conversations keep the old format. Earlier builds embed feedback in the tool result again.
