# Roo Code 4.2.43 - Cordis preview 39

Extension version: **4.2.43**. Git tag: **v4.2.43-cordis-preview.39**. Experimental GitHub prerelease, not a stable or marketplace release.

## Single-pass compaction

- Omit normal tool definitions from the summary request. Tool calls and results are already converted to text for summarization; sending the tool catalog adds unnecessary context overhead.
- Suppress previous-response chaining for the standalone summary request. Preserve task/mode tracking and the configured response-storage preference.
- Keep one summary attempt. Do not split the conversation into separately summarized sections or summarize intermediate summaries. This avoids introducing an additional lossy summarization pass.
- Report summary overflow with explicit guidance: no summary was applied; try a larger-context model or a lower requested output budget. Partial summaries are not applied after a failed request.
- Propagate available cancellation signals through manual/automatic compaction and check cancellation before dispatch, while receiving chunks, and before returning the result.

The existing automatic recovery policy is unchanged: only an explicit provider context rejection triggers automatic compaction, followed by at most one chat retry. **Allow truncation fallback** remains a separate saved preference. Disable it to prohibit excluding older unsummarized exchanges when automatic compaction fails. Manual compaction does not silently truncate.

Removing unnecessary overhead can help requests near the limit. This release cannot make arbitrarily large history fit into a smaller model window and does not change the provider's output-token limit. Stored original messages remain available, but any summary is inherently lossy.

## Validation and limits

88 focused tests passed across compaction, summary-request regressions, and automatic context-management policy. The extension TypeScript check passed. Coverage includes one-call overflow handling, partial-summary rejection, unchanged input history, metadata isolation, and cancellation. No live provider request was used to reproduce the reported overflow. Cancellation checks do not guarantee immediate interruption of a provider iterator that is already blocked awaiting a chunk.

Release lint, packaging, archive integrity, checksums, installed-version checks, and uploaded asset verification are required before publication. The build uses an isolated checkout so unrelated uncommitted provider-check and message-editor work is not included.

Previous Windows file-sync, updater, LiteLLM discovery, terminal-output, ripgrep, Settings/MCP, LM Studio, diagnostic-export, and new-task selection changes remain included. The earlier snapshot-error notification path has not been independently verified end to end. Authenticated LM Studio and Windows-specific behavior retain their previously documented live-test limitations. Claude and DeepSeek thinking-model switching through LiteLLM remains incomplete and unverified.

## Known unresolved findings

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- The separate bounded large/history command-output preview can still show the beginning instead of following the tail.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Previously reported historical-action and LiteLLM fixture failures and a Bedrock context-window expectation mismatch remain outside this change. This is not a claim that the entire repository test suite passes. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. The Mac grey-panel incident remains unverified.

## Install and rollback

Install the attached VSIX and verify its SHA-256 checksum, or use **Settings > About > GitHub release updates**. If an older updater reports a temporary-directory error, install the VSIX manually once. Install separately on each extension host. Finish or stop work before reloading; installation does not automatically reload the window. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.42 prerelease remains available. Disable automatic updates before deliberate rollback. Versions below 4.2.34 do not support the LM Studio token field; versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
