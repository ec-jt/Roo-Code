# Cordis runtime preview 2

Extension version: **4.2.4**. Git tag: **v4.2.4-cordis-preview.2**. This is a GitHub prerelease, not a marketplace or stable release.

## Subtask completion

Valid delegated subtasks now return their summary and start parent continuation automatically, including when auto-approval is off. The redundant finish-subtask approval is removed. This fixes the shared completion flow, not only Ask-mode subtasks.

Parent-child linkage, current task identity, cancellation, and model-operation fences remain checked. Duplicate returns are guarded. History/delivery failures no longer silently fall through to standalone success. Root completion and completed-child inspection retain their normal behavior.

Persistence still uses separate file writes rather than a cross-file transaction. A failure after closing the child can require manually resuming the parent from history.

## Persistent read-only approval

Eligible pending approvals offer **Always allow read-only actions**. This saves Read permission, enables master auto-approval when safe, and answers only the matching pending request. It does not grant Write or outside-workspace access, and cannot override mandatory model-operation approval.

The Read category now includes native Markdown conversion, web search, documentation retrieval, Git inspection, and filesystem reads. URL/search requests can send data to external services. The new label and description use English fallback for this preview.

Ordinary native tool requests are already covered by **All actions** when the master auto-approval switch is enabled. Mandatory approvals, lifecycle pauses, and separately controlled follow-up questions remain exceptions. The read-only shortcut is hidden if enabling the master would also activate a dormant All actions setting.

## Checkpoint storage protection

- Exclude common model-weight/container formats, including Safetensors, GGUF/GGML, CKPT, PT/PTH, ONNX, and HDF5.
- Enforce a **10 MiB per-file ceiling** before normal checkpoint ingestion, including unknown extensions. Files exactly at the limit remain eligible.
- Retain small model source files, configuration, and shard-index JSON. Do not blanket-exclude model directories.
- Remove protected files from the shadow index without deleting workspace files. Symlinks and unsafe paths are omitted conservatively.
- Reject restores that would touch excluded, oversized, or unsafe files rather than overwriting them.

**Existing checkpoint history is not deleted, pruned, or reduced.** Reclaiming its space is a separate destructive cleanup decision. The limit is per file, not a total history quota. Pause concurrent downloads/training during snapshots and restores: metadata checks cannot be atomic with Git's later reads, and a late-growth race can leave an unreferenced object even though the checkpoint is rejected.

## Writing defaults

STE-inspired user-facing prose is now the default: lead with results, use clear steps and consistent terms, distinguish facts from assumptions, and avoid repetitive progress narration. Requested depth and language preferences remain supported. Code, commands, logs, schemas, and tool arguments are not rewritten to satisfy prose rules. This is not a claim of ASD-STE100 compliance or deterministic model output.

## Install and disable

Download **roo-cline-4.2.4.vsix**, use **Install from VSIX**, then run **Developer: Reload Window**. The extension ID is unchanged.

**Settings > Experimental > Cordis runtime preview** remains **off by default**. To disable it, uncheck the setting and **Save**. This stops further preview dispatch and cancels active preview model requests; it cannot undo completed actions. Re-enabling does not automatically resume stopped tasks. Start or reopen a task explicitly.

The subtask-return fix, checkpoint protections, read-only approval shortcut, and writing defaults do not require enabling Cordis. Graph execution and strict financial budget enforcement remain unavailable.

## Validation and rollback

Targeted backend, UI, and type-contract tests cover summary delivery/resumption, stale approvals, permission persistence, model-operation fences, and checkpoint storage/restore behavior. Checkpoint integration tests use temporary Git repositories, not user checkpoints.

The previous 4.2.3 prerelease remains available for extension rollback. Rolling back the extension does not remove checkpoint protection needs: the older build lacks the new size guard. Do not use an older restore implementation on valuable model files without backups. The original local stable checkpoint remains **a9206b5fd**.
