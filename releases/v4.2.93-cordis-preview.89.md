# Roo Code 4.2.93 - Cordis preview 89

Extension version: **4.2.93**. Git tag: **v4.2.93-cordis-preview.89**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release fixes two observations from the 4.2.92 live check (N1 and N2). Both are about profile changes while a **finished** task is open. With this release, a finished task keeps the provider profile it ran with. Deleting or choosing a profile then changes only the global (current) profile.

## What "finished" means

A task is finished when its last message is a complete "Task Completed" (`completion_result`) ask, ignoring the "resume" prompts that are added when a task is reopened from history. This is the same signal that already decides whether a reopened task shows "Resume completed task".

A task that waits on any other question (a follow-up question, a tool or command approval, a failed request, or the resume prompt of an unfinished task) is not finished. Those tasks keep the 4.2.92 behaviour.

The rule is in one place: `src/shared/taskFinished.ts` (`isTaskFinished`). The extension and the chat view both use it.

## N1: deleting a profile no longer rewrites a finished task's profile

In the 4.2.92 live check, a finished task ran on profile `opus-reject`. Deleting `opus-reject` in Settings switched the UI to `deepseek`, and the finished task's history now said `deepseek`.

**Cause.** After a delete, Settings always activated the first remaining profile, even when the deleted profile was not the current one. That activation also saved the new profile name into the open task.

**Fix.**

- When the deleted profile is not the current global profile, the current profile stays. No other profile is activated.
- When the deleted profile is the current one, the first remaining profile becomes current, as before.
- When the open task is finished, its saved profile and its API handler do not change in either case.
- When the open task is not finished, it follows the activated profile, as before.

## N2: no "Change model" dialog for a finished task

In the 4.2.92 live check, choosing a profile in the chat profile picker while a finished task was open showed the "Change model" dialog ("Stop and restart with this model" or "Use for next request").

**Fix.** When the open task is finished, choosing a profile in the picker changes only the global profile. No dialog opens, and the task's saved profile does not change. The picker shows the global profile.

While a response is streaming, or when the task is not finished, the picker works as before: it opens the dialog, and a profile change applies to the task.

## Continuing a finished task

When you continue a finished task (for example, you send a new message after "Task Completed"), it keeps the profile it ran with. To continue it with a different profile, use the "Change model" dialog after you continue, or start a new task.

Reopening a task from history still restores its saved profile, as before.

## Changes

- `src/shared/taskFinished.ts` (new): `isTaskFinished`, the single rule.
- `src/core/webview/ClineProvider.ts`:
    - `activateProviderProfile` has a new option, `keepFinishedTaskProfile`. With this option, a finished task keeps its saved profile and its API handler.
    - `upsertProviderProfile` does not move a finished task to a different profile.
    - The webview state has a new field, `currentTaskFinished`.
- `src/core/webview/webviewMessageHandler.ts`:
    - `deleteApiConfiguration` keeps the current global profile unless it was deleted.
    - `deleteApiConfiguration`, `loadApiConfiguration` and `loadApiConfigurationById` use `keepFinishedTaskProfile`.
- `src/core/task/Task.ts`: the provider-profile change listener does not rebuild a finished task's API handler.
- `packages/types/src/vscode-extension-host.ts`: `ExtensionState.currentTaskFinished`.
- `webview-ui/src/components/chat/ChatTextArea.tsx`: for a finished task that is not streaming, the picker changes the global profile directly.
- `webview-ui/src/context/ExtensionStateContext.tsx`: a stale state update cannot reset `currentTaskFinished`.
- Tests:
    - `src/shared/__tests__/taskFinished.spec.ts` (new);
    - `src/core/webview/__tests__/webviewMessageHandler.profileFinishedTask.spec.ts` (new);
    - `src/core/webview/__tests__/ClineProvider.sticky-profile.spec.ts` (4 new tests);
    - `webview-ui/src/components/chat/__tests__/ModelOperation.spec.tsx` (3 new tests).

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until you reload the window.

## Storage and rollback

This release adds no settings and no saved data. The new state field `currentTaskFinished` exists only in memory. Rolling back to 4.2.92 restores the earlier behaviour.
