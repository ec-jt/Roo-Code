# Roo Code 4.2.91 - Cordis preview 87

Extension version: **4.2.91**. Git tag: **v4.2.91-cordis-preview.87**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release fixes defect D1 from the 4.2.90 live check. When the first large tool batch of a task overflowed the context window, automatic recovery could not run, so the task stopped.

## Recovery when the first tool batch overflows

In the 4.2.90 live check, two tasks overflowed on their first tool batch. In both, the model read about 2,000 lines of two large files in parallel (tool results of about 98,000 characters each):

- **R1, profile with a 64k context window override.** The check before sending detected the overflow correctly. Recovery then stopped with "Not enough earlier history to compact. Use manual context management." No request was sent.
- **R2, no override.** The provider rejected the request with 400 "prompt is too long". Recovery ran once and stopped with the same error. No retry was sent.

**Cause.** Recovery summarizes the earlier history and keeps the latest input (the newest tool calls and their results) unchanged. With the history `[task prompt, assistant tool calls, user tool results]`, there is no earlier history to summarize. Recovery returned the error before it tried anything else. Pruning of large tool results only applied to messages before the latest input, so the oversized results could not be reduced.

**Fix.** When there is too little earlier history to summarize, recovery now shortens the latest input instead:

1. Large tool results in the whole history, including the latest input, are shortened. The head and tail are kept, and the full text is saved in the task folder (readable with `read_command_output`). Only the result text changes, so every tool call keeps its matching result.
2. Images are offloaded to files in the same scope (when that setting is on and the model supports images).
3. Roo counts the reduced prompt locally. If it fits the input limit (the context window minus the reserved output tokens), the history is updated, a "context pruned" row is shown, and the request is sent once.
4. If it still does not fit, or nothing could be shortened, recovery stops with "Context is still too large after automatic recovery (about N tokens; the limit is L for a W-token window). History was not changed. ..." The misleading "Not enough earlier history" error is gone.

This path compares the estimate with the input limit, not with the 90% budget used before a summary. No summary can follow, so a stricter margin would only refuse requests that fit. The provider stays the final judge, and a second rejection stops the request after the single retry.

**Both paths use the fix.**

- **Profiles with a context window override:** the check before sending runs this recovery once, then sends the pruned request.
- **Models without an override:** recovery still runs only after the provider rejects a request for size (constraint C-6). After the rejection, recovery shortens the results and retries once. A second rejection stops the request.

**Settings.**

- "Prune tool results on overflow" off: nothing is shortened, and recovery stops with the "still too large" error.
- "Offload images on overflow": applies as before.
- "Compact on context overflow" off: recovery does not run at all, as before.

**Unchanged.** With enough earlier history, recovery works as in 4.2.89 and 4.2.90 (prune older results, offload older images, summarize, then shorten the kept tail if needed). When there is no overflow, history is not changed.

## Correction to the 4.2.90 notes

The 4.2.90 commit message said "recover proactively for all models". Only profiles with a context window override changed in 4.2.90. Models without an override still reduce context only after a provider rejection (C-6). The 4.2.90 release notes already described this correctly.

## Changes

- `src/core/context-management/index.ts`:
    - new `reduceWithoutSummary`, used when there is too little earlier history to summarize;
    - new `stillTooLargeError`, shared with the post-summary check from 4.2.89.
- `src/core/context-management/__tests__/context-management.spec.ts`: new tests for the first-batch shape on a 64k window (prune result under the limit, pairs kept, full text saved; pruning off; still too large after pruning).
- `src/core/task/__tests__/task-model-dispatch.spec.ts`: new tests for the override pre-send path, the rejection path without an override, at most one retry, and pruning off.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until you reload the window.

## Storage and rollback

This release adds no settings and no storage formats.

If you roll back to 4.2.90, a task whose first tool batch overflows the context window stops again with "Not enough earlier history to compact."
