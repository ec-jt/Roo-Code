# Roo Code 4.2.100 - Cordis preview 96

Extension version: **4.2.100**. Git tag: **v4.2.100-cordis-preview.96**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release adds parallel subtasks, as decided in ADR-2026-11-22-parallel-subtasks (steps B1 to B4). The feature is behind the new experiment `parallelSubtasks`, which is off by default. With the experiment off, no tool schema contains `new_tasks`, and behaviour is unchanged.

## New: parallel subtasks (`new_tasks`)

The new tool `new_tasks` starts 2 to 4 independent subtasks at the same time. Each subtask has a mode and a message.

- **Isolation.** Each subtask works in its own git worktree, on its own branch `roo/subtask/<taskId>`. The parent's working tree is not changed. If the workspace is not a git repository, no subtask starts and the model receives a tool error.
- **One approval.** The user approves the whole batch once. The approval row lists every subtask (mode and the first line of its message), the number of parallel requests and the token budget.
- **No asking.** Subtasks cannot ask the user. A tool that the existing auto-approval settings would approve runs. Any other tool, follow-up question or mode switch is refused with a tool result, and the subtask lists what needs approval in its result. Subtasks cannot call `new_task`, `new_tasks` or `switch_mode`.
- **Shared limits.** All subtasks of a batch share one runtime, on every provider. It allows at most N model requests at the same time (default 2, setting 1 to 4) and one token budget for input plus output tokens (default 2,000,000). When the budget is used up, the remaining subtasks stop with `budget-denied`.
- **One result.** When every subtask has stopped, the parent receives one tool result. For each subtask it gives the stop reason, the summary, the branch, `git diff --stat`, the uncommitted files and the refused approvals. Nothing is merged automatically. The parent or the user reviews and merges the branches.
- **Stopping.** Stopping the parent stops all its subtasks. Each subtask records its own stop reason (`completed`, `user-stopped`, `budget-denied`, `mistake-limit` or `error`).

## When `new_tasks` is offered

All of these must hold:

1. the `parallelSubtasks` experiment is on;
2. the task is not a parallel subtask;
3. the mode is `orchestrator`, or the task profile is `cordis` or `hybrid`.

Otherwise the tool is absent from the schema, and a call is refused by the same validation that filters the schema. Model-operation branches never get the tool.

## Approval

Auto-approval of a batch uses exactly the rule of `new_task`: it is approved without a prompt only when auto-approval is on and "Subtasks" (`alwaysAllowSubtasks`) or "All actions" is on. In addition, a batch can only start from the current root task (depth 0), never from a model-operation branch or a closed task. A child task cannot use `new_tasks` to bypass the nested-delegation approval of `new_task`.

## New: Background activity section

Background activity shows a **Parallel subtasks** section for the current task's batch. It lists each subtask with its mode, status (running, completed, stopped, budget used up, failed), request count, cost and branch, plus the tokens used against the budget.

- **Stop** stops one subtask. The others keep running.
- **Stop all** stops the batch.
- **Open** shows the subtask's messages read-only in an editor document. The text is a plain transcript (no images or reasoning). It does not go through the webview and is not written to disk. Large transcripts (over 8 MiB) are refused with a message.

The extension sends `parallelBatchUpdated` when a subtask changes state, at most about once per second. The last finished batch of the task stays visible after it ends.

## New: settings

Settings > Experimental has a **Parallel subtasks** toggle. When it is on, two more controls are shown:

- **Parallel requests per batch:** a slider from 1 to 4 (`parallelSubtasksConcurrency`, default 2).
- **Token budget per batch:** a number input (`parallelSubtasksTokenBudget`, default 2,000,000, minimum 100,000).

The approval row shows the values that the batch runs with.

- `packages/types`: experiment `parallelSubtasks`; tool name `new_tasks`; `ClineSayTool` `newTasks` with `tasks`, `concurrency` and `tokenBudget`; `ParallelBatchInfo` and `ParallelChildInfo`; message `parallelBatchUpdated`; webview message `parallelBatchControl`; settings `parallelSubtasksConcurrency` and `parallelSubtasksTokenBudget` in the extension state.
- `src/core/task/parallel/`: `ParallelTaskPool` (batches, isolated worktrees, `stopBatch`, `stopChild`, status snapshots and change events), `BatchAdmissionRuntime` (concurrency and token budget on every provider), the headless provider view, the non-interactive ask policy and capability policy, and the read-only transcript for Open.

## Storage and rollback

New data: the experiment key `parallelSubtasks`, the global settings `parallelSubtasksConcurrency` and `parallelSubtasksTokenBudget`, ordinary history items for subtasks (with `parentTaskId`), git branches `roo/subtask/<taskId>` with their worktrees, and `newTasks` rows in the parent's messages. No existing key is rewritten (C-5).

In 4.2.99 the new keys are ignored. Subtask history items open as ordinary child tasks. A `newTasks` row in a parent's history shows as an unknown tool row. The branches and worktrees stay in the repository until they are merged or removed with `git worktree remove` and `git branch -D`.
