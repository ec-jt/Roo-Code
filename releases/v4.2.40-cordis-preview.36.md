# Roo Code 4.2.40 - Cordis preview 36

Extension version: **4.2.40**. Git tag: **v4.2.40-cordis-preview.36**. Experimental GitHub prerelease, not a stable or marketplace release. Includes the changes tested locally in unpublished version 4.2.39.

## LiteLLM provider setup

- Remove the built-in Sonnet model selection. New LiteLLM configurations show the selection placeholder until a model is chosen. Preserve explicitly saved aliases, including Sonnet if actually configured.
- Discover models using the current form URL and API key rather than saved profile credentials. Use a dedicated LiteLLM request instead of refreshing every router.
- Correlate each reply with its request. Ignore stale replies after credential changes, provider switches, replacement requests, or timeout.
- Keep only the current form's discovery result. Bypass LiteLLM memory/disk catalog caches and shared in-flight discovery requests. Clear displayed results on refresh, configuration changes, and failure.
- Use the same current catalog for the picker, validation, and selected-model metadata. Preserve a configured proxy alias when metadata is unavailable instead of substituting an unrelated model.
- Report sanitized HTTP failures, timeouts, and successful empty catalogs. Normalize root and terminal /v1 URLs, preserve proxy path prefixes, bound discovery requests, and reject redirects without exposing credentials or response bodies.
- Accept discovery metadata when private proxy routing details are redacted. Keep only the selected model's metadata in the inference handler.

The local 4.2.39 refresh fix was confirmed working by the user. The original HTTP 400 was not reproduced in the earlier read-only discovery checks, which returned both configured aliases. No inference or server configuration changes were performed for this work. This release does not change LiteLLM thinking-mode or cross-provider history behavior.

## Validation and limits

Focused discovery, cache bypass, alias-preservation, request-routing, and webview tests cover the refresh fix. Additional tests cover empty initial selections, preservation of explicit Sonnet aliases, and the selection placeholder without automatic initialization. Existing passing checks are reused where code is unchanged. Release lint, packaging, archive integrity, checksum, and installed-version verification are required before publication.

Broader earlier test attempts exposed an unrelated Bedrock context-window expectation mismatch and older LiteLLM handler fixtures without the required VS Code configuration mock. These remain unchanged; this is not a claim that the complete repository test suite passes.

Earlier terminal-output, ripgrep, Settings/MCP, LM Studio, diagnostic-export, and new-task model-selection fixes remain included. Authenticated LM Studio behavior remains mock-tested. Claude and DeepSeek thinking-model switching through LiteLLM remains incomplete and unverified. Pinned replay and the experimental Anthropic-only mediated runtime retain their restrictions.

## Known unresolved findings

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- The separate bounded large/history command-output preview can still show the beginning instead of following the tail. Recent-output previews apply to normal command cards.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

The pre-existing historical-action guard fixture failure remains outside this change. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. The Mac grey-panel incident remains unverified.

## Install and rollback

From 4.2.30 or later, use **Settings > About > GitHub release updates** after closing the loaded task. A stopped or completed task still counts as loaded: return to the empty New Task screen without deleting history. Alternatively install the attached VSIX and verify its SHA-256 checksum. Run **Developer: Reload Window** when ready to activate it. Install separately on each extension host. End-to-end in-app Remote SSH installation remains unverified.

The previous published 4.2.38 prerelease remains available. Disable automatic GitHub updates before a deliberate rollback. Versions below 4.2.34 do not support the LM Studio token field. Versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
