# Roo Code 4.2.63 - Cordis preview 59

Extension version: **4.2.63**. Git tag: **v4.2.63-cordis-preview.59**. Experimental GitHub prerelease, not a stable or marketplace release.

## Summaries keep failed approaches, architecture IDs and blockers

The default context-compaction prompt has three new sections before the next step:

- **9. Failed and Rejected Approaches:** what was tried and abandoned, with the reason, so it is not retried.
- **10. Architecture IDs in Use:** `Q-`, `C-`, `R-` and `ADR-` IDs cited or affected in the task, and proposed records.
- **11. Open Blockers:** unresolved blockers, including recorded architecture drift.

**Optional Next Step** is now section 12. A custom condensing prompt (Settings > Prompts > Context condensing) is still used as written. Roo appends one line to it: "Also preserve failed or rejected approaches, cited architecture IDs, and open blockers." The task-state ledger is still appended as data when the task has one.

The summary request can also carry an architecture context block. No caller supplies one yet; the architecture context provider follows in a later release.

## Read-only modes can read saved output

`read_command_output` moved from the command tool group to the read group. Architect, Ask and custom modes with the read group can now read saved command output and the tool-result artifacts that overflow recovery creates (4.2.62). The tool was already treated as read-only for auto-approval, so approval behavior is unchanged. Modes without the command group still cannot run commands.

## Validation and limits

Focused tests pass: condense and context-management specs (221 tests), including new cases for the template sections, the preserve line with a custom prompt, and the architecture block present and absent; and the tool-filter spec for `read_command_output` in Architect, Ask and Code. Extension TypeScript checking and lint pass. Release gates cover lint, packaging, VSIX ZIP integrity, manifest version, both worker bundles and asset digests. They are not a full test suite.

One test in `src/shared/__tests__/modes.spec.ts` fails: it expects Debug mode without the browser group. The Debug mode definition and the test file are both unchanged since 4.2.62, so this release does not cause it. It is not fixed here.

A live compaction with a real model was not exercised, so summary quality with the new sections is unverified.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Builds before 4.2.62 show prune-only recovery rows as unknown messages. This release does not migrate or rewrite stored tasks, and no existing task data was read during the release operation.

## Installation

Verify the attached VSIX against its SHA-256 file. Install separately on each extension host. The companion ZIP is optional, unchanged since 4.2.51, and requires separate manual Chrome installation.
