# Roo Code 4.2.101 - Cordis preview 97

Extension version: **4.2.101**. Git tag: **v4.2.101-cordis-preview.97**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release closes a known gap of 4.2.100 (ADR-2026-11-22-parallel-subtasks, "Implementation notes (4.2.100)"). Before this release, the rule "`new_tasks` must be the last tool call in its turn" was only in the tool description. Now the runtime enforces it, with the same mechanism as `new_task`.

## Changed: `new_tasks` is isolated in its turn

When an assistant turn contains `new_tasks` and other tool calls, the runtime handles it exactly as it handles `new_task`:

- Tool calls before `new_tasks` run as usual.
- Tool calls after `new_tasks` are removed from the saved assistant message and are not executed.
- Each removed tool call receives an error tool result: "This tool was not executed because new_tasks was called in the same message turn. The new_tasks tool must be the last tool in a message."
- Only the first delegation tool of a turn is kept. If a turn contains `new_task` and `new_tasks`, the first one runs and the later one receives the error result, which names the tool that came first.

The behaviour of `new_task` is unchanged, including the text of its error result.

## Changes

- `src/core/task/delegation-tools.ts` (new): `DELEGATION_TOOL_NAMES`, `isDelegationTool(name)`, `findDelegationToolIndex(blocks)` and `delegationTruncationMessage(toolName)`. One place defines which tools delegate.
- `src/core/task/Task.ts` (R-1, small): the existing `new_task` truncation now uses `findDelegationToolIndex` and `delegationTruncationMessage`, so it also covers `new_tasks`. No other change.
- `src/core/task/__tests__/delegation-tools.spec.ts` (new): the `new_task` isolation cases, run for both `new_task` and `new_tasks`, plus a mixed turn and the unchanged `new_task` message.
- `src/package.json`: version 4.2.101.
