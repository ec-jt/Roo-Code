# Roo Code 4.2.73 - Cordis preview 69

Extension version: **4.2.73**. Git tag: **v4.2.73-cordis-preview.69**. Experimental GitHub prerelease, not a stable or marketplace release.

## Computer use: share the computer with the user

Roo and the user share one mouse pointer and one keyboard focus. Before this release, Roo's clicks and typing could land in whatever the user was working on.

### Take turns (all platforms)

- Before an action that uses the mouse or keyboard (click, move, drag, scroll, type, key, focus window), Roo checks whether the user is active. If the user moved the pointer since Roo's last action, or (on macOS) pressed a key or moved the mouse in the last 1.5 seconds, Roo waits until the user pauses for 1.5 seconds.
- If the user keeps working for 20 seconds, the action does not run. The model is told that the user is busy and what to do instead.
- After a click, drag, or scroll, Roo puts the user's pointer back where it was. A `move` action leaves the pointer at the new position, because that is its purpose.
- Screenshots, window listing and wait never wait for the user.
- On macOS the keyboard check reads the system idle time (`ioreg`, no extra permission). Roo's own input is ignored.

### Background fallback (macOS)

Two new actions work without the shared pointer or keyboard focus, so Roo can keep going while the user works:

- `window_screenshot`: captures one window by id or title, even when other windows cover it. The pointer and the front app do not change.
- `window_type`: inserts text at a window's text cursor through Accessibility, without bringing the window to the front. It works in native apps such as TextEdit, Notes and Mail. Browsers and Electron apps may ignore it, and Roo then reports the failure.

Background clicking is not supported. To click, Roo waits for its turn. Pixels in a window screenshot are not screen coordinates, and the model is told not to click with them.

The app allowlist applies to `window_type` by the target window's title. `window_screenshot` is read-only, like `screenshot`.

## Computer use: scroll distance

Scroll steps are now converted to the unit each system expects. Before this fix, one step on macOS scrolled one pixel and one step on Windows scrolled 1/120 of a notch, so scrolling barely moved. One step is now about one mouse wheel notch:

| Platform | Native units per step     |
| -------- | ------------------------- |
| macOS    | 40 pixels                 |
| Windows  | 120 (one `WHEEL_DELTA`)   |
| Linux    | 1 wheel click (unchanged) |

## Validation

- Live on macOS with the real native module: scroll down and up moved the text by the expected amount (verified before the user started using the computer during the test). `window_screenshot` of a TextEdit window took about 230 ms and `window_type` about 400 ms. Neither changed the front app or moved the pointer. `ioreg` idle time reads correctly, and injected input does not reset it.
- Focused tests pass: desktop services and the tool spec (147 tests, including new user-activity and turn-taking tests), the webview chat row spec (6 tests). TypeScript checks for types, extension and webview pass. Translations are complete for 17 locales.

Not yet verified live: turn-taking inside the editor, the 20-second refusal path, Windows and Linux.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads.

## Storage and rollback warnings carried forward

Builds before 4.2.73 show the new window actions with their raw action name. The warnings from 4.2.72 still apply. This release does not migrate or rewrite stored tasks.
