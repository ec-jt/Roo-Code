# Roo Code 4.2.58 - Cordis preview 54

Extension version: **4.2.58**. Git tag: **v4.2.58-cordis-preview.54**. Experimental GitHub prerelease, not a stable or marketplace release.

## Large task histories prepare faster

Local preparation of long task histories no longer writes snapshot blocks one at a time.

- Message blocks are processed in bounded batches of eight instead of a serial loop.
- Shared snapshot directories are flushed once per batch, children before parents, after all block writes and before the manifest is published. Previously every block write re-synced the whole directory chain.
- A failed batch drains its in-flight writes before the error is rethrown, so no block write outlives a failed save.

Durability and ordering are preserved: per-file sync, checksum validation, immutable publication, no-overwrite semantics and history ordering are unchanged. The fix reduces repeated filesystem sync work, not the guarantees.

The commit records a synthetic measurement of 1,000 reused history rows improving from 39.7s to 3.9s on the author's machine. That figure was not re-measured during this release operation.

## Regression coverage

New tests cover directory flush ordering, retry of a failed flush, and cleanup of in-flight writes when a batch fails. The real-filesystem growth test now allows more time on APFS.

## Features retained from 4.2.51 to 4.2.57

Durable per-message subtask IDs with legacy recovery and the Go to subtask button, browser controls with auto-approval for every rich command, native PDF reading, mode/model preservation, the DeepSeek strict tool-schema fix, the single read-only browser approval, subtask links from an explicit `new_task`-to-child map, and the clear failure for closed or detached browser pages are unchanged. See the [4.2.57 release notes](v4.2.57-cordis-preview.53.md), [4.2.56 release notes](v4.2.56-cordis-preview.52.md), [4.2.55 release notes](v4.2.55-cordis-preview.51.md), [4.2.54 release notes](v4.2.54-cordis-preview.50.md), [4.2.53 release notes](v4.2.53-cordis-preview.49.md), [4.2.52 release notes](v4.2.52-cordis-preview.48.md) and [4.2.51 release notes](v4.2.51-cordis-preview.47.md).

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads. An editor that still reports an older version after a successful install has not reloaded.

## Validation and limits

Focused evidence produced in this release worktree: 129 storage tests pass, including the new flush-ordering, retry and in-flight-cleanup cases; isolated lint passes for all 10 tasks; backend TypeScript checking passes. Release gates cover packaging, ZIP CRC and manifest identity, both worker bundles, feature markers, absence of unfinished provider-connection markers, source-to-commit hashes, asset SHA-256, GitHub server digest and size, and installed-file byte identity. These gates are not a full test suite.

The 39.7s to 3.9s improvement comes from the commit author's machine and was not reproduced here. Extension activation, live browser behavior, macOS behavior and end-to-end user workflows remain unverified.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Rolling back does not convert snapshots. Preserve task storage before downgrading, and disable automatic updates before a deliberate rollback.

Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery. Avoid navigation while saving history edits.

This change alters how snapshot blocks are written. Existing stored tasks are read with the same validation and are not rewritten or migrated by the release. Unfinished provider-connection checks and unrelated local editor, UI, Tetris, archive and research changes are excluded.

## Installation

Verify the attached VSIX against its SHA-256 file. Install separately on each extension host. This release operation installs only on the current Linux code-server host, without reloading the editor or activating the new extension. It does not install on a Mac. The companion ZIP is optional, unchanged since 4.2.51, and requires separate manual Chrome installation.
