# Roo Code 4.2.27 - Cordis preview 24

Extension version: **4.2.27**. Git tag: **v4.2.27-cordis-preview.24**. Experimental GitHub prerelease, not a stable or marketplace release.

## Compaction respects truncated context

- Use the same effective history for compaction as for normal model requests. Previously, compaction selected all messages after the last summary, including exchanges that truncation had excluded. This could produce an unexpectedly oversized compaction request even when the working context was smaller.
- Keep excluded messages stored for recovery. Do not delete source history or undo earlier truncation when generating a summary.
- Include restored exchanges again when their truncation marker has been removed.

The context meter reflects recent request usage or a context-management estimate, not an exact token count of the next compaction payload. Compaction still requires its active input to fit the selected model. This release does not add chunked summarization or guarantee that genuinely oversized input will fit. The reported 2,417,991-token request was not reproduced against a live provider.

## Validation

39 focused tests passed across compaction, nested summaries, and overflow truncation. Regression coverage checks excluded exchanges with and without earlier summaries, unchanged source history, and restored exchanges. No live-provider or interactive VS Code test was performed for this fix.

## Existing recovery limits

Context recovery branches from 4.2.26 remain available. Exact snapshots exist only for newly recorded events; older events without snapshots cannot be recovered by guessing their boundaries. Branches do not restore files or copy command-output artifacts. See [context recovery](../docs/context-recovery.md).

## Known unresolved findings

- **Closing a task blocked by an interrupted assistant-edit marker can overwrite its UI history with an empty snapshot.** Preserve the task directory before attempting recovery.
- **Closing or switching during an assistant edit can leave the task stuck after a safe rollback.** Avoid navigation while an edit is saving.
- Checkpoint-based user edits can be dropped if replacement history loading exceeds the fixed continuation delay.
- Approving an unrelated command can mark an older denied file edit as approved in the UI and file summary. This does not execute the denied write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Project memory remains opt-in. Cordis runtime preview remains off by default. The Mac grey-panel incident remains unverified.

## Install and rollback

Install **roo-cline-4.2.27.vsix**, verify its SHA-256 checksum, then run **Developer: Reload Window** when ready to interrupt the extension session. Install separately on each extension host.

The previous 4.2.26 prerelease remains available but retains the compaction-input bug fixed here. Do not open unfinished recovery branches in versions below 4.2.26, which do not enforce their preparation marker. Resolve interrupted assistant edits before downgrading below 4.2.22. Rollback does not undo history edits, remove truncation tags, restore files, erase memories, or stop detached processes.
