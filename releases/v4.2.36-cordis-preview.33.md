# Roo Code 4.2.36 - Cordis preview 33

Extension version: **4.2.36**. Git tag: **v4.2.36-cordis-preview.33**. Experimental GitHub prerelease, not a stable or marketplace release.

## Ripgrep discovery and workspace preparation

- Expand ripgrep lookup beyond the editor application root to code-server installation layouts and absolute extension-host PATH entries. Prefer bundled binaries, require a regular executable file, and never resolve through a shell or relative workspace PATH entries.
- Return actionable errors when no executable is available. This does not download or install ripgrep.
- If ripgrep is missing during optional workspace-file context collection, continue preparation with an explicit omission notice. Explicit file-list/search tools still report the missing dependency instead of pretending to succeed.

The same lookup serves workspace context and explicit file tools. Home-directory listing is skipped, while ordinary subdirectories are scanned, so a missing dependency can appear specific to subdirectory workspaces. The exact affected-host layout and every possible Preparing delay remain unverified. Other preparation failures are not silently suppressed.

After installing ripgrep manually, ensure its directory is in the environment of the code-server service or container, not only an interactive terminal. Restart that host when safe so it inherits the updated PATH. Older Roo releases do not use this PATH fallback. A working shell command alone does not prove the extension host can find the same executable.

## Settings and MCP controls

- Explain that MCP master/server controls save immediately and do not require the Settings header Save button. MCP configuration-file edits must be saved in the editor.
- Separate provider-draft change tracking from unrelated settings. Provider validation errors no longer block saving unrelated changes.
- Submit provider configuration only when it was changed and is valid. Preserve invalid drafts and unsaved-change protection; show an explicit notice rather than silently discarding them.
- Remove the cached MCP-enabled value from the general settings payload so a later save cannot undo an immediately saved master toggle.

The disabled Save button alone does not prove an MCP persistence failure. Live MCP configuration and tool-approval policy were not changed by this investigation.

Release lint, packaging, archive integrity, and checksum checks are required by the release procedure. No interactive affected-host reproduction or live MCP persistence test was performed.

## Known unresolved findings

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- Long command-output previews can freeze on the beginning instead of following the tail.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

The pre-existing historical-action guard fixture failure remains outside this change. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. The Mac grey-panel incident remains unverified.

## Install and rollback

From 4.2.30 or later, use **Settings > About > GitHub release updates** after closing the loaded task. A stopped or completed task still counts as loaded: return to the empty New Task screen without deleting history. Alternatively install the attached VSIX and verify its SHA-256 checksum. Run **Developer: Reload Window** when ready to activate it. Install separately on each extension host. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.35 prerelease remains available. Disable automatic GitHub updates before a deliberate rollback. Versions below 4.2.34 do not support the LM Studio token field. Versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
