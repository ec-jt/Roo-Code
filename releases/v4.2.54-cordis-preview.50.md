# Roo Code 4.2.54 - Cordis preview 50

Extension version: **4.2.54**. Git tag: **v4.2.54-cordis-preview.50**. Experimental GitHub prerelease, not a stable or marketplace release.

## Browser tool auto-approval now covers every rich command

When auto-approval is enabled and the browser tool is set to always allow, all rich browser commands run without a native modal. This now includes mutations and tab selection: `navigate`, `click_ref`, `fill_ref`, `select_ref` and `select_tab`, as well as the read-only commands.

Without that setting, behavior is unchanged from 4.2.53. Read-only commands need one native approval per task and browser session, and mutations plus `select_tab` need approval for each call.

Warning: auto-approved mutations can submit forms, change account state, or perform other irreversible actions in the target page. Enable the browser always-allow toggle only for trusted sites and tasks.

## Fences, capability checks and transcripts unchanged

Capability checks, session and tab validation, stale-reference rejection, task identity and revision checks, transcript persistence, and the no-automatic-retry rule for uncertain mutations still run for every command, including auto-approved ones. Approval semantics outside the browser auto-approval branch are unchanged. Approvals remain in memory only, not persisted. Tool prompt text and browser control documentation are updated.

## Features retained from 4.2.51 to 4.2.53

Browser controls, native PDF reading, mode/model preservation, the DeepSeek strict tool-schema fix and the single read-only browser approval are unchanged. See the [4.2.53 release notes](v4.2.53-cordis-preview.49.md), [4.2.52 release notes](v4.2.52-cordis-preview.48.md) and [4.2.51 release notes](v4.2.51-cordis-preview.47.md).

## Validation and limits

Focused implementation evidence: 43 tests pass across the browser control tool and browser control message handler specs; the backend TypeScript check passes. Release gates cover isolated lint, packaging, isolated backend TypeScript checking, ZIP CRC and manifest identity, both worker bundles, feature markers, excluded-provider markers, presence of the auto-approval marker in the built bundle, absence of `format: "uri"` in the browser schema, source-to-commit hashes, asset SHA-256, GitHub server digest and size, and installed-file byte identity. These gates are not a full test suite, and installation does not imply activation.

Live CDP behavior, auto-approved mutation execution against a real site, certificate sessions, Chrome companion attachment, macOS behavior and end-to-end user workflows remain unverified.

## Storage and rollback warnings carried forward

Versions 4.2.48 and earlier cannot replay version-2 request snapshots. Rolling back does not convert snapshots. This release does not inventory, read, migrate, rewrite, prune or delete existing task storage. Preserve task storage before downgrading, and disable automatic updates before a deliberate rollback.

Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery. Avoid navigation while saving history edits.

Unfinished provider-connection checks and unrelated local editor, UI, Tetris, archive and research changes are excluded.

## Installation

Verify the attached VSIX against its SHA-256 file. Install separately on each extension host. This release operation installs only on the current Linux code-server host, without reloading the editor or activating the new extension. It does not install on a Mac. The companion ZIP is optional, unchanged from 4.2.53, and requires separate manual Chrome installation.
