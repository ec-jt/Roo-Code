# Roo Code 4.2.25 - Cordis preview 22

Extension version: **4.2.25**. Git tag: **v4.2.25-cordis-preview.22**. Experimental GitHub prerelease, not a stable or marketplace release.

## Overflow-only truncation fallback

- After an explicit provider context-limit rejection, try compaction first. If compaction also exceeds the provider context limit or returns an empty summary, allow a non-destructive truncation fallback before the same single request retry.
- Exclude only complete older exchanges. Retain the root/current-summary exchange and newest user turn with its tool-call/result chain. Refuse ambiguous or unpaired tool history and oversized protected input.
- Keep excluded messages stored, tagged as outside the effective model context. Do not resurrect history already hidden by a summary.
- Show the fallback reason and excluded-message count in the chat before retrying. Account for any failed-summary cost and the reduced context estimate.
- Use token estimates only to choose a post-overflow recovery cut, not to trigger proactive compaction. Manual-only mode remains available.
- Do not truncate after cancellation, stale identity, permission/admission denial, storage errors, authentication failures, rate limits, or transport/server failures. A failed repaired request stops rather than restarting recovery.

See [context policy](../docs/context-budget.md). Truncation omits unsummarized information from model context and can change subsequent behavior. Export important history first.

## Validation and limits

Focused compaction, fallback, request-retry, history-accounting, shared-metric, and UI checks passed. Backend and webview type checks passed. Coverage includes multi-tool chains, earlier summaries, oversized protected input, noneligible errors, mediated admission, and the shared one-retry limit. No live-provider or real-filesystem crash-injection test was performed. Token estimates cannot guarantee that the provider accepts the repaired request.

## Known unresolved lifecycle findings

The latest review identified four issues that this policy change does not fix:

- **Closing a task blocked by an interrupted assistant-edit marker can overwrite its UI history with an empty snapshot.** Preserve the task directory before attempting recovery.
- **Closing or switching during an assistant edit can leave the task stuck even after a safe rollback.** Avoid task navigation while an edit is saving.
- Checkpoint-based user edits can be silently dropped if replacement history loading takes longer than the fixed continuation delay.
- Approving an unrelated command can mark an older denied file edit as approved in the UI and file summary. This does not execute the denied write.

## Other known unresolved preview findings

- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

Project memory remains opt-in. Cordis runtime preview remains off by default. Tool approval and storage settings are unchanged. New explanatory text uses English. The Mac grey-panel incident remains unverified.

## Install and rollback

Install **roo-cline-4.2.25.vsix**, verify its SHA-256 checksum, then run **Developer: Reload Window** when ready to interrupt the extension session. Install separately on each extension host.

The previous 4.2.24 prerelease remains available and stops rather than truncating after compaction failure. Resolve interrupted assistant edits before downgrading below 4.2.22. Rollback does not undo stored history edits or truncation tags, erase memories, stop detached processes, or undo completed actions.
