# Roo Code 4.2.84 - Cordis preview 80

Extension version: **4.2.84**. Git tag: **v4.2.84-cordis-preview.80**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

## Cordis dispatch errors keep their cause and retry before the stream starts

This release fixes two problems in Anthropic tasks that run under the Cordis dispatch runtime.

### 1. The real error is shown

Before this release, every provider failure became a bare `Model dispatch stopped: dispatch-failed`. The HTTP status and the provider message were lost.

Now the error keeps the original cause. The text shown to you, and the recorded dispatch outcome, include the HTTP status, the provider error type and the provider message when they are available. For example:

```
Model dispatch stopped: dispatch-failed (529 overloaded_error: Overloaded)
```

- The text never contains credentials, request headers or request bodies. Anthropic API keys in a message are redacted, and the detail is limited to 300 characters.
- One debug line (`[ANTHROPIC][dispatch] dispatch-error`) records the code, the status and the original message.

### 2. Failures before the first chunk retry automatically

Before this release, a Cordis request that failed before any stream data arrived (for example an overload or a network error) stopped the turn at once and asked you to resume.

Now such a failure uses the same automatic retry as a modes task:

- **Same settings and backoff.** With auto-approval on, the retry waits with the same exponential backoff (`requestDelaySeconds`) and shows the same "retrying" row (`api_req_retry_delayed`). With auto-approval off, you get the same "API request failed" question with a Retry button.
- **Admission again.** Each retry asks the dispatch runtime for a new admission. If the runtime denies the retry (for example a budget limit), the turn stops with that outcome. The failed dispatch is settled as `unresolved`, as before.
- **No retry for:** `cancelled`, `stale`, `policy-denied`, `budget-wait`, `budget-denied`, `lease-expired`, `unsupported-provider`; a confirmed `context-limit` (the existing context recovery handles it); any failure after output started; and a task that is aborted, abandoned or closed.

Tasks with the modes profile do not change.

## Changes

- `src/api/dispatch-admission.ts`: `ModelDispatchControl` takes an optional `{ cause, status }`. It stores `status`, passes `cause` to `Error`, and adds the cause detail to the message. New helper `describeDispatchCause()`. New `toJSON()` that returns only `name`, `code`, `status` and `message`, so serializers never see the raw cause. Admission failures that are not controls keep their cause.
- `src/api/providers/anthropic.ts`: `dispatchError()` is exported, passes the original error as the cause and writes one debug line. `summarizeAnthropicError()` logs only the safe fields of a control.
- `src/core/task/Task.ts`:
    - `attemptApiRequestPinned()`: a pre-stream `dispatch-failed` under the Cordis runtime takes the ordinary first-chunk retry path. Other control codes still throw at once. Before each retry the code checks for abort, abandon, close or a cancelled signal, and then throws `cancelled`.
    - `attemptApiRequest()`: a non-control error in the Cordis path keeps its cause.
- Tests:
    - `src/core/task/__tests__/task-model-dispatch.spec.ts`: new tests for retry then success with two admissions, a denied retry admission, the ask path with auto-approval off, the kept cause in the user-visible error after output started (no retry), and no retry for `cancelled` and `context-limit`. Two existing tests now expect the retry. The interactive "429 stop" case was removed because a pre-stream 429 now retries by design.
    - `src/api/providers/__tests__/anthropic-admission.spec.ts`: new tests for `dispatchError` (cause, status, message, no secrets, context-limit, pass-through) and for a mediated stream that fails before the first chunk.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until you reload the window.

## Storage and rollback

This release adds no settings and changes no stored data. If you roll back, Cordis pre-stream failures stop without a retry again and the error text loses its cause.
