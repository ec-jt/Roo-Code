# Roo Code 4.2.35 - Cordis preview 32

Extension version: **4.2.35**. Git tag: **v4.2.35-cordis-preview.32**. Experimental GitHub prerelease, not a stable or marketplace release.

## Fix model selection after New Task

- Clear stale task identity and model-operation state when an authoritative empty-task snapshot arrives, including when undefined properties disappear during serialization. Preserve active-task state on unrelated partial updates and reject older snapshots.
- Refresh task identity and model-operation state at the backend's final send boundary, alongside the bounded message snapshot. A task closed during asynchronous state assembly must not leave old model controls attached to the empty start screen.
- Use **Change model** as the switch-dialog title. When no request snapshot exists, show next-request selection without the irrelevant restart warning, workspace checkbox, or disabled restart button.
- Keep direct profile selection on the empty New Task screen. For a loaded task, **Use for next request** remains separate from restarting and does not itself send a request. Existing replay, approval, and task-graph safety restrictions remain intact.

## Known unresolved findings

- Subtask links can select the wrong child after earlier delegation messages leave the bounded page, or when historical results use the latest completed-child ID.
- Long command-output previews can freeze on the beginning instead of following the tail.
- Image-only historical/preview messages can appear empty.
- Historical truncation events can hide structured count, reason, and token metrics.
- Same-millisecond timestamps can share expansion state or confuse timestamp-based lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery.**
- **Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing that write.
- Global pip configuration can redirect managed-environment installation outside its approved destination. **Keep managed environments and their auto-approval disabled pending a fix.**
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- Named-pipe managed-environment manifests can block preparation or checkpoint compatibility inspection.
- Future interpreter paths supplied to pip can prevent recognition of compatible musllinux wheels.

The pre-existing historical-action guard fixture failure remains outside this change. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual. The Mac grey-panel incident remains unverified.

## Install and rollback

From 4.2.30 or later, use **Settings > About > GitHub release updates** after closing the loaded task. A stopped or completed task still counts as loaded: return to the empty New Task screen without deleting history. Alternatively install the attached VSIX and verify its SHA-256 checksum. Run **Developer: Reload Window** when ready to activate it. Install separately on each extension host. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.34 prerelease remains available. Disable automatic GitHub updates before a deliberate rollback. Versions below 4.2.34 do not support the LM Studio token field. Versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
