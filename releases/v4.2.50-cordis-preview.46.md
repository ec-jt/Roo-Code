# Roo Code 4.2.50 - Cordis preview 46

Extension version: **4.2.50**. Git tag: **v4.2.50-cordis-preview.46**. Experimental GitHub prerelease, not a stable or marketplace release.

## Rollback warning

**Versions 4.2.48 and earlier cannot replay new version-2 request snapshots.** Rolling back does not convert snapshots. Main chat history files are unchanged, but replay of requests recorded in the new format requires the new reader. Disable automatic updates before deliberate rollback. There is no automatic downgrade or migration.

## Inherited profile guard

Delegated tasks retain their inherited API configuration when unrelated global profile-change events or provider updates arrive. The guard remains active after the first request. Stale asynchronous profile listeners check the current task and selection epoch before applying a profile. Provider activation captures its target task before awaiting profile loading and does not update or notify a different task that became current meanwhile.

Explicit task profile selection releases the guard. This includes a queued next-request profile, a submitted message profile, provider-profile selection, activating an upserted profile, and the webview rename, load-by-name, load-by-ID, and delete-profile routes. An actual mode change releases the inherited guard when API configuration is not locked. Global settings can still change for the UI without changing the guarded task.

This is a scoped inherited-configuration guard, not a global ordering redesign or a fix for every host/model swap. **The chat header still uses the global model and can misrepresent a delegated task's effective model.** Returning to or rehydrating a parent still loads its saved profile by name; unsaved overrides are lost. A different-mode profile-selection failure can leave the parent disposed and require reopening it. No live user request or complete live child-to-parent return was captured to validate this release.

## Validation and limits

The parent task reported **58 passing tests across six focused files**, one passing selected actual-request runtime test with 57 skipped tests, and a passing final backend TypeScript check after the guard follow-up changes. These results are reused unless relevant source changes require another focused check. The earlier 135-test result predates those changes and is not claimed for this release.

Release gates include isolated lint, the release-local formatting and lint hook, isolated backend TypeScript integration checking, packaging, archive CRC and identity checks, source-to-commit hashes, asset checksums, uploaded-asset verification, and installed-file verification. These are scoped checks, not a full-suite or live-provider pass. The broad model-operation suite was not rerun; its previously known unrelated preview failure remains outside this change.

## Storage and unresolved limits carried forward

The [4.2.49 release notes](v4.2.49-cordis-preview.45.md) and [4.2.48 release notes](v4.2.48-cordis-preview.44.md) remain applicable. Version-2 snapshot storage is unchanged. Legacy version-1 records remain readable within the documented bounds without automatic migration. Snapshot deduplication does not bound total storage; there is no retention quota or garbage collector. Saving still scans the supplied history and replay still materializes a full snapshot. Hard-link support is required; Windows directory-fsync power-loss guarantees remain unverified.

**Existing task storage is not inventoried, read, migrated, rewritten, pruned, or deleted by this release operation.** The previously reported 87 GB was not measured or reclaimed.

- Task-state acceptance is user-attested only. There is no executable acceptance runner.
- Subtask links can select the wrong child after older delegation messages leave the bounded page. Historical results can use the latest completed-child ID.
- The separate bounded large/history command-output preview can show the beginning rather than follow the tail.
- Image-only historical/preview messages can appear empty. Historical truncation can hide structured metrics. Same-millisecond timestamps can share expansion state or confuse lookups.
- **Closing a task blocked by an interrupted edit marker can overwrite UI history with an empty snapshot. Preserve the task directory before recovery. Closing or switching during a history edit can leave a task stuck after rollback. Avoid navigation while saving.**
- An unrelated approval can mark an older denied file edit as approved in the UI without executing the write.
- **Keep managed environments and their auto-approval disabled pending fixes.** Global pip configuration can redirect installation outside its approved destination. Named-pipe manifests can block preparation or checkpoint checks. Future interpreter paths can prevent recognition of compatible musllinux wheels.
- Manual commands in Roo-owned terminals can be attributed to pending Roo commands. Avoid mixing manual work into these terminals when using Stop command.
- The Windows file-sync notification after dispatch is closed remains unverified and may never appear. The Mac grey-panel incident remains unverified. Directory-listing runtime behavior on Windows, macOS, Electron, and remote filesystems remains untested.
- Previously reported historical-action and LiteLLM fixture failures and a Bedrock context-window expectation mismatch remain outside this change. Reasoning-only output is not a final answer; the earlier empty-response cause remains unestablished.

Unfinished provider-connection checks and unrelated local UI changes are excluded. No live-provider, tunnel, API-key, server, private-infrastructure, macOS, Windows, network-filesystem, real power-loss, or packaged-runtime snapshot checks were performed. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default. Browser security and SSH setup remain manual.

## Installation

Install the attached VSIX and verify its SHA-256 checksum, or use **Settings > About > GitHub release updates**. If an older updater reports a temporary-directory error, install the VSIX manually once. Install separately on each extension host.

This release operation installs on the current **Linux code-server host, not a Mac**. Installation does not reload or activate the extension. End-to-end in-app Remote SSH installation remains unverified.

The previous 4.2.49 prerelease remains available. Disable automatic updates before deliberate rollback. Older versions do not provide the task-state workflow; preserve task storage before downgrading. Versions below 4.2.34 do not support the LM Studio token field; versions below 4.2.29 do not honor the separate truncation-fallback preference. Do not open unfinished recovery branches in versions below 4.2.26. Resolve interrupted history edits before downgrading below 4.2.22. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes.
