# Roo Code 4.2.49 - Cordis preview 45

Extension version: **4.2.49**. Git tag: **v4.2.49-cordis-preview.45**. Experimental GitHub prerelease, not a stable or marketplace release.

## Rollback warning

**Versions 4.2.48 and earlier cannot replay new version-2 request snapshots.** Rolling back does not convert snapshots. Main chat history files are unchanged, but replay of requests recorded in the new format requires the new reader. Disable automatic updates before deliberate rollback. There is no automatic downgrade or migration.

## Deduplicated request snapshot storage

New snapshots use version-2 envelopes with task-local content-addressed message and prompt blocks and a canonical 32-way prefix tree. Small manifests contain two root/count pairs and a prompt reference instead of repeated full histories. Blocks become durable before the manifest is published. The public snapshot API still accepts and returns a complete version-1 snapshot object.

Legacy version-1 envelopes remain readable without automatic migration. Identical retries preserve legacy bytes and inodes without creating blocks. Branches own independent blocks; legacy branch provenance retains its source lookup. See [snapshot storage](../docs/snapshot-storage.md) for the format, publication protocol, and limits.

**Existing task storage is not inventoried, migrated, rewritten, pruned, or deleted by this release operation.** The previously reported 87 GB was not measured or reclaimed. This change eliminates repeated full-payload append growth; it does not bound total storage. There is no retention quota or garbage collector. Unique content, request metadata, and orphan blocks from failed writes can continue growing.

Saving still scans the supplied history for canonicalization, reads, and synchronization. CPU work and filesystem work are not incremental. Replay still materializes the full snapshot.

Per-operation guards allow 64 MiB per block, 512 MiB of referenced bytes per save or read, 1,000,000 messages per sequence, and 64 KiB per version-2 manifest. A new 512 MiB preallocation guard applies to legacy envelopes: larger old records remain untouched but cannot be replayed. The shared reader permits the legacy bound before identifying the format, then applies the smaller version-2 limit.

## Validation and limits

The parent task reported **196 passing storage and coordinator tests** and a passing backend TypeScript check for the current behavior. Those results are reused; subsequent changes were documentation and unused-import removal only. Release gates include isolated lint, the release-local formatting and lint hook, packaging, archive CRC and identity checks, source-to-commit hashes, asset checksums, uploaded-asset verification, and installed-file verification. These are scoped checks, not a full-suite pass.

The growth regression uses 96 temporary snapshots. It checks logical bytes below one eighth of full copies and allocated bytes below one half. This is a fixture result, not a measurement of the reported 87 GB or installed tasks. No installed task storage was accessed for validation.

No macOS, Windows, network-filesystem, real power-loss, or packaged-runtime snapshot validation was performed. Hard-link support is required. Windows directory-fsync power-loss guarantees are not established.

## Known limits carried forward

The [4.2.48 release notes](v4.2.48-cordis-preview.44.md) remain applicable and are not rewritten by this release. In particular:

- Returning to or rehydrating a parent loads its saved profile by name; unsaved overrides are lost. A different-mode profile-selection failure leaves the parent disposed and requires reopening it. Not all host/model switching is fixed.
- Task-state acceptance is user-attested only. There is no executable acceptance runner.
- The Windows file-sync notification after dispatch is closed remains unverified and may never appear. The Mac grey-panel incident remains unverified.
- Interrupted history edits and closing or switching tasks during an edit retain the recovery risks documented in 4.2.48. Avoid navigation while saving.
- Managed environments and their auto-approval should remain disabled pending the previously documented fixes.

Unfinished provider-connection checks and unrelated local UI changes are excluded. No live-provider or private-infrastructure checks were performed. Project memory remains opt-in. Cordis runtime preview and automatic GitHub updates remain off by default.

## Installation

Install the attached VSIX and verify its SHA-256 checksum, or use **Settings > About > GitHub release updates**. If an older updater reports a temporary-directory error, install the VSIX manually once. Install separately on each extension host.

This release operation installs on the current **Linux code-server host, not a Mac**. Installation does not reload or activate the extension. End-to-end in-app Remote SSH installation remains unverified. Rollback does not recover rewound messages, undo edits, restore files, erase memories, or stop detached processes. Earlier rollback restrictions in the 4.2.48 notes still apply.
