# Roo Code 4.2.102 - Cordis preview 98

Extension version: **4.2.102**. Git tag: **v4.2.102-cordis-preview.98**. This is an experimental GitHub prerelease. It is not a stable release or a marketplace release.

This release fixes two defects found in the live check of 4.2.101 (parallel subtasks, ADR-2026-11-22-parallel-subtasks).

## Fixed: a parallel child could write into the parent's working tree (D-1, high)

In 4.2.101 a parallel child wrote `../<repo>/src/x.txt`. The file landed in the parent's checkout, the tool row showed `isOutsideWorkspace: false`, and the combined result reported no changes. The cause: for file tools, the editor folders (which include the parent's checkout) counted as inside the workspace, and the child's brief named the parent's absolute path.

Now:

- **Write confinement.** A parallel child may only change files inside its own git worktree. The check runs in the child's capability policy, before validation and before any approval, so auto-approval cannot override it. It covers `write_to_file`, `apply_diff`, `edit`, `search_and_replace`, `search_replace`, `edit_file`, `apply_patch` (every added, deleted and updated file, and every `*** Move to:` destination), and the output path of `generate_image` and `generate_video`. A refused call receives the tool result "Parallel subtasks may only change files inside their worktree <worktree>. <path> is outside it." Nothing is written.
- **Paths are resolved before the check.** `..` and `.` are normalised. The nearest existing ancestor is resolved with `realpath`, so a symbolic link inside the worktree that points outside it is refused. A dangling link is followed to its target.
- **Commands.** A parallel child's `execute_command` with a `cwd` outside the worktree is refused in the same way. A missing `cwd` still runs in the worktree.
- **Workspace boundary.** For a parallel child, only its worktree is inside the workspace. Reads elsewhere, including the parent's checkout, are "outside workspace" and follow the outside-workspace auto-approval setting. If it is off, the read is refused, because a child cannot ask.
- **Child brief.** Each child's first message now starts with: "Your workspace is the git worktree <worktree> on branch <branch>. Resolve every relative path against it. Do not read or write files in other checkouts of this repository. Ignore any absolute path to another checkout given below; use the matching path inside your worktree instead."
- **Combined result.** Refused changes are listed for each child under "Refused changes outside the child's worktree (not applied)". The pool also compares `git status --porcelain` of the parent repository at batch start and at batch end. If they differ, the result contains a warning and the changed lines.

Shared tasks and sequential isolated subtasks (`new_task` with `workspace: isolated`) behave as before.

## Fixed: Settings > Auto-Approve "All Actions" was not saved (D-2, medium)

Turning "All Actions" off and pressing Save did not store the change. Save now sends `alwaysAllowAll` with the other auto-approval settings.

## Changes

- `src/utils/containedPath.ts` (new): `resolveRealPath(path)` and `isPathInsideRealRoot(path, root)`.
- `src/core/task/parallel/non-interactive.ts`: `checkParallelChildConfinement`, `outsideWorktreeMessage`, `OUTSIDE_WORKTREE_REFUSAL`, `PARALLEL_CHILD_CONFINED_TOOLS`. `parallelChildToolPolicy` takes an optional confinement.
- `src/core/tool-execution/invocation-policy.ts`: `ToolInvocation` has an optional read-only `args`.
- `src/core/task/Task.ts` (R-1, one line): `checkToolInvocation` passes the call's parsed arguments to the policy.

- `src/core/task/parallel/ParallelTaskPool.ts`: the child brief (`parallelChildBrief`), the confinement for each child, the parent-tree check (`parentTreeChanges`) and the new sections of the combined result.
- `webview-ui/src/components/settings/SettingsView.tsx`: `handleSubmit` sends `alwaysAllowAll`.
- Tests: `src/core/task/parallel/__tests__/confinement.spec.ts` (new), 7 new cases in `ParallelTaskPool.spec.ts`, 1 new case in `SettingsView.spec.tsx`.
- `src/package.json`: version 4.2.102.
