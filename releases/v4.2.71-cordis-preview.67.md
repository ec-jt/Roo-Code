# Roo Code 4.2.71 - Cordis preview 67

Extension version: **4.2.71**. Git tag: **v4.2.71-cordis-preview.67**. Experimental GitHub prerelease, not a stable or marketplace release.

## Desktop control: `computer_action` (opt-in, off by default)

Roo can now see and control other desktop applications through a new native tool, `computer_action`. It takes screenshots and sends mouse and keyboard input through the libnut native layer. One universal VSIX includes the binaries for macOS (x64 and arm64), Windows x64 and Linux x64 (X11).

Actions: `screenshot`, `click`, `double_click`, `right_click`, `move`, `drag`, `type`, `key`, `scroll`, `list_windows`, `focus_window`, `wait`.

- Turn it on in **Settings > Computer use** (`computerUseEnabled`, default off). The tool is offered to the model only when the setting is on and the model supports images.
- Every action needs approval unless **Auto-approve > Computer use** (`alwaysAllowComputerUse`) is on. **Always allow all** does not turn it on.
- **Allowed applications** (`computerUseAllowedApps`) limits which windows input actions and `focus_window` can target. Read-only actions (`screenshot`, `list_windows`, `wait`) are always allowed.
- A status bar item shows when Roo is controlling the desktop. **Roo: Stop computer use** (`Cmd/Ctrl+Alt+Shift+X`) cancels every task that has a desktop session.
- Screenshots are reduced to at most 1280x800. Coordinates from the model are mapped back to screen points, including on Retina displays.
- The new `computer` tool group is part of Code mode. Custom modes must add `computer` to their groups to use the tool.

Platform requirements:

- **macOS:** grant Accessibility and Screen Recording to the editor app, then quit and reopen the editor. The settings page has a **Check permissions** button that requests missing permissions. Administrator rights are not needed.
- **Windows:** no extra permissions. The editor should not run elevated.
- **Linux:** X11 only. Wayland-only sessions and sessions without a display are refused with an explanation.
- Remote sessions (SSH, containers, WSL) are refused, because the tool would control the remote host.
- linux-arm64 and win32-arm64 have no prebuilt binaries and are refused.

See `docs/computer-use.md` for the user guide.

## Validation

Focused tests pass: the desktop service specs (loader, platform check, PNG encoding, key parsing, session coordinate mapping, window allowlist, session registry, activity indicator), the tool spec, the parser, build-tools, mode-filter and auto-approval specs for `computer_action`, the stop command spec, the permission-check message handler spec, and the webview settings and chat row specs. Translations cover all 17 locales. TypeScript checks for types, extension and webview pass. A macOS load test confirmed the native module loads and captures the screen from Node.

Pre-existing failures, identical on 4.2.70: `TruncationFallback.spec.tsx`, the chat view queued-message test, 4 presenter policy-boundary tests and the `native-read-tools` Markdownify test.

Not yet verified: live use inside the editor (Electron load, clicks on Retina, scroll direction, approvals, allowlist, stop key, screenshot speed), Windows, Linux X11, and a native-speaker review of the translations.

## Installed version requires a reload

Installing a VSIX does not activate it. A running editor keeps its current extension version until the extension host reloads. On macOS, new privacy permissions take effect only after a full quit and reopen.

## Storage and rollback warnings carried forward

Builds before 4.2.71 show computer-use rows as unknown messages. The warnings from 4.2.70 still apply. This release does not migrate or rewrite stored tasks.
